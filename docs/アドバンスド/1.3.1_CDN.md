## 1. ウェブコンテンツ配信の安定化（CDNの基礎）

### CDN（Content Delivery Network）とは
- コンテンツを **高速、かつ高い信頼性** で配信する仕組み。

| | 経路 | 影響 |
|---|------|------|
| **CDNなし** | WebサイトへのアクセスはWebサーバに**直接到達** | アクセス増加でWebサーバの負荷が高まり、コンテンツ配信に悪影響の可能性 |
| **CDNあり** | Webコンテンツの配信は**CDNから**行われる | Webサーバの負荷が軽減。CDNは一般的に規模の大きなサーバ群で構成され、多くのアクセス処理に適する |

### オリジンサーバとキャッシュサーバ
- **オリジンサーバ**: 実際のコンテンツが格納されているサーバ。
- **キャッシュサーバ**: コンテンツをキャッシュし、配信を肩代わりするサーバ。

### キャッシュの動作（配信フロー）
1. **初回アクセス**: ユーザがWebコンテンツへアクセスすると、ユーザはCDN（キャッシュサーバ）にリクエストする。
2. キャッシュサーバはオリジンサーバからコンテンツを取得し、ユーザに返す。このとき取得したコンテンツを**キャッシュとして保持**する。
3. **2回目以降のアクセス**: キャッシュサーバが保持済みのコンテンツを返す（オリジンへ取りに行かない）。

### キャッシュ制御の仕組み（Cache-Control）
- **Cache-Control ヘッダ**に値を設定し、CDNにキャッシュ動作を指示する。
- 一般的には Expires ヘッダなどもキャッシュ制御に使われるが、**さくらのウェブアクセラレータでは `Cache-Control` ヘッダを使う**。
- 事前準備として、Webサーバの設定でHTTPレスポンスヘッダの `Cache-Control` に特定の値をセットする。
  - 例: `Cache-Control: s-maxage=86400` → キャッシュを保持する最大1日間（86400秒）。

### 導入検討時の考慮（用途）
- **国内向け**にウェブコンテンツを提供する場合、さくらのウェブアクセラレータでキャッシュ配信し、アクセス急増時でも負荷を分散して表示を安定化させることを検討する。
- トラフィック変動に柔軟対応し、将来的なコンテンツ拡張にも迅速適応できる**拡張性の高い構成**がとれる。
- 主な用途:
  - アクセス集中時の表示速度低下やサーバダウンを回避する。
  - 負荷を分散してウェブサイトの表示を安定化する。
- 仕組みを理解し適切な設定を行う。**ドメイン種別とオリジン種別**を選択し、導入時のURL変更やDNS切替の手間とリスクを考慮して決定する。

## 2. さくらのウェブアクセラレータ（概要）

- さくらインターネットが提供する**CDNサービス**。
- **高速で安価な国内向け**ウェブコンテンツ配信サービス。
- ウェブサイト等の**表示を安定化**する。

### 料金・提供プラン（重要）
- さくらのウェブアクセラレータに**プランは存在しない**。
- **月間の転送量に対する従量課金**。
- 課金対象 = **キャッシュサーバからインターネットへの送信トラフィック（アウトバウンドトラフィック）**。
- 【Tips】**プロジェクトごとに一定の無償利用枠**が用意されている。無償利用枠は**一度のみ適用**され、**有効期限はない**。
- 【Tips】サービス利用規約には**クラウドサービス約款が適用**される。

### オリジンへの通信
- キャッシュサーバ → オリジンサーバへの通信は **HTTP（80）または HTTPS（443）** を使用。
- 接続元ネットワークはクラウドマニュアルに記載。
- オリジンサーバへの接続時に**特定のリクエストヘッダが付与**される（接続元IPアドレスなどを含む）。例:
  - `X-Real-IP: 1.1.1.1`
  - `X-Forwarded-Proto: https`
  - `X-Forwarded-Host: www.example.jp`

### コンテンツ配信の基本仕様（重要表）

| 項目 | 仕様 |
|------|------|
| 対応プロトコル | HTTP、HTTPS（**HTTP/2対応**） |
| HTTPS接続時の暗号化プロトコル | **TLS 1.2, TLS 1.3** |
| 設置拠点 | 国内IDC（**東京と大阪の2拠点**）。閲覧者のアクセスは自動的に割り振られる。**アクセス先の拠点を指定することはできない** |
| 配信ファイル | **制限なし** |
| サイト数制限 | **20サイト** |
| サイト利用 | さくらインターネットのサービス**以外**で稼働するサイトも指定可能 |

## 3. キャッシュ制御の方法と仕様

### キャッシュ制御の2つの方法（優先順位に注意）
| 方法 | 制御手段 |
|------|----------|
| a. オリジンサーバで設定 | オリジンサーバの **Cache-Control ヘッダ**（`s-maxage=*****`）で制御 |
| b. コントロールパネルで設定 | **キャッシュ期間の設定**で制御 |

- ⚠️ **両方で設定されている場合は、オリジンサーバの設定が優先される。**
- 【Tips】オリジンサーバでのCache-Control設定例（Apache / Nginx 向け）はクラウドマニュアルに記載。

### キャッシュ仕様（最重要表）

| 項目 | 仕様 |
|------|------|
| キャッシュ対象 | **GETリクエストのみ** |
| キャッシュ保持期間 | **最大7日間** |
| キャッシュファイルサイズ | **最大2GiB-1** |
| キャッシュ単位 | **URL単位（?クエリストリング込み）** ※Varyサポート機能が無効の場合 |
| キャッシュ削除単位 | **全件削除** / **URL単位（?クエリストリング込み）** |
| キャッシュ制御ヘッダ（キャッシュ期間設定） | `Cache-Control: s-maxage` |
| キャッシュ制御ヘッダ（キャッシュ無効設定） | `Cache-Control: no-store` または `Cache-Control: private` もしくは `Pragma: no-cache` |

> ⚠️ 試験頻出: キャッシュ対象は**GETのみ**、保持期間は**最大7日**、ファイルサイズは**最大2GiB-1（約2GB）**。キャッシュ単位/削除単位は**URL単位（クエリストリング込み）**。

## 4. ドメイン種別とオリジン種別

### 設定の全体像
- さくらのウェブアクセラレータを利用するには**サイトを作成**する必要がある。
- 1つのWebサイトに対して**1つのサイト**を作成する（サイト＝管理対象）。
- 1つのサイトに対して**ドメイン種別を1つ**、**オリジン種別を1つ**指定する。

| 設定 | 選択肢 |
|------|--------|
| ドメイン種別 | **独自ドメイン** / **サブドメイン** のいずれか |
| オリジン種別 | **ウェブサーバ** / **オブジェクトストレージ** のいずれか |

### ドメイン種別（独自ドメイン vs サブドメイン）

| 項目 | 独自ドメイン | サブドメイン |
|------|--------------|--------------|
| アクセス形式 | 利用者が管理するFQDN（例: `https://www.example.jp`） | ウェブアクセラレータが生成するFQDN `http(s)://ランダム文字列.user.webaccel.jp/` |
| 経由範囲 | **すべてのサイトアクセス**がウェブアクセラレータを経由 | **サイトアクセスの一部のみ**が経由 |
| DNS | 名前解決を設定するDNSが必要（`www → xxxxx.user.webaccel.jp` に関連付け） | 一部のコンテンツ（画像ファイル等）のみウェブアクセラレータ経由になるようサイト内で指定 |
| 表示ドメイン | サイト内に表示されるコンテンツも同じ（利用者の）ドメイン | キャッシュ対象は `xxxxx.user.webaccel.jp` の外部ドメインで配信 |

- 独自ドメイン: 生成されるFQDNは利用者所有ドメインのFQDNに関連付けされるため、**すべてのアクセスが経由**する。
- サブドメイン: 利用者ドメインでアクセスしつつ、**一部コンテンツのみ**生成FQDN経由でアクセスする。

### SSL証明書（独自ドメイン）（重要 Tips）
- **独自ドメインの場合、ウェブアクセラレータにSSL証明書を登録できる。**
  - 利用者所有の証明書だけでなく、**Let's Encrypt 証明書の登録が可能**で**自動更新も設定できる**。
- **生成FQDN（`*.user.webaccel.jp`）については、さくらインターネットが管理する証明書を使用**するため、**利用者で証明書を登録することはできない**。

### オリジン種別（ウェブサーバ vs オブジェクトストレージ）
オリジンへアクセスするために必要な情報を指定する。

| オリジン種別 | 指定する情報 |
|--------------|--------------|
| **ウェブサーバ** | オリジンプロトコル（http または https）、オリジンサーバ（IPアドレスまたはFQDN） |
| **オブジェクトストレージ** | エンドポイント、リージョン、バケット、アクセスキー |

- 【Tips】オリジンにオブジェクトストレージを選択する場合は**コントロールパネルでキャッシュ制御する**。サイト作成時に**「デフォルトのキャッシュ期間」を有効にしてキャッシュ期間を設定する必要がある**。
- ⚠️ ドメイン種別・オリジン種別は重要設定のため、**サイト作成前にどの方式を選択するか検討**する必要がある。

## 5. さくらのウェブアクセラレータの利用（コントロールパネル操作）

### 操作環境
- **専用のコントロールパネル**で操作する（サーバやディスクを操作する画面とは**異なる**）。
- **APIでの操作**も可能。

### サイト追加の流れ
1. さくらのクラウドホーム画面から「さくらのウェブアクセラレータ」をクリック。
2. **ドメイン種別、サイト名、リクエストプロトコル**を設定。
3. **オリジン種別**を選択（ウェブサーバ選択時はオリジンプロトコル・オリジンサーバも設定）→「保存」。
4. サイト作成後、**有効化が必要**。対象サイトで「設定」→ **サイトのステータスを有効に**する。

### サイト追加時に必要な設定（オリジン種別ごとの整理）

| ドメイン種別 \ オリジン種別 | 共通 | ウェブサーバ | オブジェクトストレージ |
|------------------------------|------|--------------|------------------------|
| **独自ドメイン** | リクエストプロトコル / サイト名 / **公開ドメイン名** | + オリジンプロトコル / オリジンサーバ | + エンドポイント / リージョン / バケット名 / アクセスキー / **キャッシュ期間** |
| **サブドメイン** | リクエストプロトコル / サイト名 | + オリジンプロトコル / オリジンサーバ | + エンドポイント / リージョン / バケット名 / アクセスキー / **キャッシュ期間** |

- **リクエストプロトコルとサイト名は、オリジン種別に関わらず設定**する。
- **公開ドメイン名は独自ドメインを選択する場合に設定が必要。**

### 公開ドメイン名
- ウェブアクセラレータにアクセスする際のFQDN。
- 独自ドメイン方式: サイト作成時に**利用者が指定**する。
- サブドメイン方式: **自動的に生成**される（`https://xxxxx.user.webaccel.jp`）。

### リクエストプロトコル
- ウェブアクセラレータにアクセスする際に使用するプロトコル。
- **`http/https` / `httpsのみ` / `httpsにリダイレクト`** の中から選択。

### サイトの有効化（重要）
- サイト作成後に**手動で有効化**する必要がある。**作成直後はキャッシュが無効化されている。**
- **独自ドメインの場合**、有効化する前に公開ドメイン名に対する**ドメイン認証が必要**。
  - 利用者が管理するDNSで、公開ドメイン名への **CNAMEレコード** を設定するか、もしくは **TXTレコード** を設定し、ドメインの所有権を保有しているか確認する。
- 【Tips】所有権確認のため適切なDNSレコード設定が必要で、未設定時はコントロールパネル上に警告メッセージが表示される。

## 6. 利用の検討（方式選択・チューニング）

### ドメイン種別の選択ケース
- **独自ドメイン**: 利用者が管理するドメインを使ってキャッシュ配信する場合。
- **サブドメイン**: 画像など一部のファイルをキャッシュしたい場合で、**配信ドメインが外部ドメインになることを許容できる場合**。

### 事前確認事項（方式 × オリジン種別）

| | ウェブサーバ | オブジェクトストレージ |
|---|--------------|------------------------|
| **独自ドメイン** | 利用者管理ネームサーバで CNAME / A / TXT レコードを編集できる。オリジンサーバでHTTPレスポンスヘッダを追加できる | 利用者管理ネームサーバで CNAME / A / TXT レコードを編集できる |
| **サブドメイン** | オリジンサーバでバーチャルホスト設定が可能で、`******.user.webaccel.jp` へのアクセスをコンテンツ格納ディレクトリ閲覧に設定できる。オリジンサーバでHTTPレスポンスヘッダを追加できる | 特になし |

### メリット・デメリット（ウェブサーバオリジンの場合）

| 方式 | メリット | デメリット |
|------|----------|------------|
| **独自ドメイン（ウェブサーバ）** | 利用中ドメインでキャッシュ配信可能 / サイトURLの変更なしにほとんどのファイルをキャッシュ配信可能 / SSL証明書登録で独自ドメインでもSSL化可能、自由度が比較的高い、サイトファイルの**全キャッシュも可能** | 運用中ドメインへCNAME設定を行うため**ダウンタイム発生の可能性** / Zone ApexにCNAMEを設定できない一部ネームサーバ運用中は**この方式を利用できない** / DNS設定が必要でネガティブキャッシュ発生リスクも多少存在 / キャッシュされないトラフィックでもウェブアクセラレータから配信したトラフィックは**課金対象** |
| **サブドメイン（ウェブサーバ）** | DNS設定不要で**瞬時に**配信切替可能 / **ダウンタイムなし**でキャッシュ配信を利用可能 / 事前確認も可能で切替リスクを低く抑えられる | 配信が `******.user.webaccel.jp` ドメインになり**利用者ドメインを利用できない** / サイト全てをキャッシュ配信しようとするとサイトURLがサブドメインになり**現実的でない** / キャッシュ対象ファイルのURLが利用者のサイトドメインと異なる |

- 【Tips】クラウドマニュアルでは、**独自ドメインを選択し、利用者で新規にサブドメインを用意して利用する方式**が紹介されている。これにより、キャッシュ配信に利用者のドメインを使え、かつ**ダウンタイムなしで切り替え**られる。

### ファイルサイズ・キャッシュ対象の注意
- キャッシュ可能な**1ファイルあたりの最大ファイルサイズ = 2GB（2GiB-1）**。これを超えなければ画像だけでなく**動画もキャッシュ可能**。

### キャッシュ配信状況の確認（x-cache ヘッダ）

| `x-cache` の値 | 意味 |
|----------------|------|
| **HIT** | ファイルがキャッシュされている |
| **MISS** | ファイルがキャッシュされていない |
| （ヘッダ自体が無い） | そのドメインがウェブアクセラレータ経由で配信されていない可能性 |

- HTTPレスポンスヘッダは**ブラウザの開発者ツール**で確認できる。

### オリジンアクセスと安全性
- **東京リージョンと大阪リージョンのそれぞれから**、キャッシュ取得のためにオリジンへのアクセスが発生する。
- **不適切なコンテンツをキャッシュしないよう注意**。機密情報・法的に問題のあるコンテンツはキャッシュしない（意図せず配信してしまう可能性がある）。

### キャッシュヒット率のチューニング（重要）
- 運用では**キャッシュヒット率を可能な限り100%に近づける**ようチューニングする。
- ヒット率上昇 → オリジンサーバの負荷低減 → 大量アクセス時の安定運用に効果。
- 適切な**キャッシュ期間（s-maxage）**を模索する。コンテンツの更新頻度に合わせて調整。
- キャッシュ期間の長期化とコンテンツの素早いアップデートは**トレードオフ**。
  - **まずは10分程度の短い設定で運用**し、コンテンツ更新で支障が生じない範囲で**できる限り長く**しながら設定値を模索することが推奨。
- **アクセスログ**を活用しユーザのアクセス傾向を分析してヒット率向上を図る（分析例はクラウドマニュアルに記載）。
- 【Tips】**キャッシュ削除API**とコンテンツ更新を連動させると、キャッシュ期間の長期化と素早いアップデートを両立できる。CMSのファイル更新と連動しAPI経由でキャッシュ削除をリクエストすれば、古いキャッシュを自動クリアできる。大規模システムでの利用検討時に有効。

### キャッシュヒット率の算出と確認
- キャッシュヒット率は、**キャッシュ期間（s-maxage）あたりに発生するリクエスト数**に対する、**オリジンに到達するキャッシュ取得回数**をもとに計算できる。
- 計算例: `s-maxage=600` で600秒間に1000万リクエストの場合、期間内に**東京・大阪リージョンからそれぞれ1回ずつ**（計2回）のキャッシュ取得が発生すると仮定して:
  - `(1 − 2 / 1000万) × 100 = 99.99998%`
- キャッシュヒット率は**コントロールパネルで確認できる**。
  - サイト情報で**リクエスト数・転送量・キャッシュヒット率の時間推移がグラフ表示**される。**月別使用量の実績値**も確認可能。

## 7. 試験対策・要点チェック

- [ ] CDNはオリジン負荷を**キャッシュサーバ**が肩代わりして軽減。初回はオリジン取得、2回目以降はキャッシュ配信。
- [ ] さくらのウェブアクセラレータは**Cache-Controlヘッダ**でキャッシュ制御（Expiresは使わない）。`s-maxage=86400` で最大1日。
- [ ] 料金: **プランなし / 月間転送量の従量課金 / 課金対象はアウトバウンド（送信）トラフィック**。
- [ ] **プロジェクトごとに無償利用枠**（一度のみ・有効期限なし）。利用規約は**クラウドサービス約款**。
- [ ] 仕様: 対応プロトコル**HTTP/HTTPS（HTTP/2）**、暗号化**TLS 1.2/1.3**、拠点**東京・大阪の2拠点（指定不可）**、配信ファイル**制限なし**、**サイト数20**。
- [ ] キャッシュ: 対象**GETのみ** / 保持**最大7日** / サイズ**最大2GiB-1** / 単位**URL単位（クエリ込み）** / 削除**全件 or URL単位**。
- [ ] キャッシュ無効化ヘッダ: **no-store / private / Pragma: no-cache**。
- [ ] オリジンとコントロールパネル両方で設定時は**オリジン設定が優先**。
- [ ] ドメイン種別 = **独自ドメイン（全アクセス経由）/ サブドメイン（一部のみ経由・外部ドメイン配信）**。
- [ ] オリジン種別 = **ウェブサーバ / オブジェクトストレージ**。オブジェクトストレージはCPでキャッシュ制御し**デフォルトキャッシュ期間が必須**。
- [ ] SSL証明書は**独自ドメインのみ登録可能**（**Let's Encrypt自動更新**対応）。生成FQDN `*.user.webaccel.jp` はさくら管理証明書で**利用者登録不可**。
- [ ] 公開ドメイン名: 独自ドメイン=利用者指定 / サブドメイン=自動生成。
- [ ] リクエストプロトコル = **http/https / httpsのみ / httpsにリダイレクト**。
- [ ] サイトは作成後**手動で有効化**（作成直後はキャッシュ無効）。独自ドメインは有効化前に**CNAMEまたはTXTでドメイン認証**が必要。
- [ ] **x-cache** ヘッダ: HIT=キャッシュ有 / MISS=キャッシュ無 / ヘッダ無=経由していない可能性。
- [ ] チューニングは**まず10分程度**から開始し、支障ない範囲で長くする。**キャッシュ削除API**でアップデートと長期キャッシュを両立。
- [ ] ヒット率はコントロールパネルでグラフ確認。東京・大阪から**各1回ずつ**オリジン取得が発生する前提で算出。
