## 1. モニタリングスイートとは

- **多様な環境のシステムを監視するためのプラットフォーム**。
- さくらのクラウドに限らず、**その他のクラウドサービスやオンプレミス等の多様な環境を、一元管理**できる。

### 主な機能（4つ）

| 機能 | 内容 |
|------|------|
| **ストレージ** | サービスの**メトリクス・ログ・トレース**を保存し、Web UIで表示 |
| **ルーティング** | 各サービスからストレージへの**データ転送設定** |
| **ダッシュボード（専用Web UI）** | ダッシュボード（**Perses**）管理、データ可視化 |
| **アラート機能** | **メトリクス状態に基づく通知** |

### 構成イメージ（フロー）

```
[対応サービス]                    [モニタリングスイート]
 NFSアプライアンス  ─┐                ┌─ ログストレージ      ─┐
 AppRun            ─┤  ルーティング   ├─ メトリクスストレージ ─┤
 シンプル監視       ─┼───────────────▶├─ トレースストレージ   ─┼─▶ ダッシュボードプロジェクト
 エンハンスド        │                └──────────────────────┘    （Perses で可視化）
   ロードバランサ    │                                          └─▶ アラートプロジェクト
 オンプレミス       ─┤                                              （メトリクス状態で通知）
 他社クラウド       ─┘
```

- 対応サービス例: NFSアプライアンス、AppRun、シンプル監視、エンハンスドロードバランサ 等々（さくらのクラウドの対応サービス）。
- データはルーティングを経由して各ストレージ（ログ／メトリクス／トレース）に蓄積され、**ダッシュボードプロジェクト**と**アラートプロジェクト**で活用する。

> 【TIPS】**Perses** はオープンソースのダッシュボードツールで、**Prometheus** などから取得したデータを可視化できる。

## 2. シンプル監視との違い（重要比較表）

- **シンプル監視とモニタリングスイートは併用が可能**。
- 例: シンプル監視の監視ログを、モニタリングスイートに連携する。

| 項目 | シンプル監視 | モニタリングスイート |
|------|--------------|----------------------|
| 監視方式 | **サービス監視** | **内部データの収集・蓄積** |
| 対象 | URL、ポート、SSL証明書 | ログ、メトリクス、トレース |
| 主な用途 | **状態の確認** | **何が起きているかを詳しく知る** |
| ログ保存 | あり（ログ表示と結果の通知） | あり（**検索に対応**） |
| メトリクス保存 | **なし** | **あり（可視化に対応）** |

> ⚠️ 試験頻出: シンプル監視はメトリクス保存**なし**、モニタリングスイートはメトリクス保存**あり（可視化対応）**。ログ保存はモニタリングスイートが**検索対応**。

## 3. モニタリングスイートが扱う3種類のデータ

| データ種別 | 内容 | 例 |
|------------|------|-----|
| **ログ** | 何が起きたかの**イベントを記録** | エラーメッセージ、アクセス履歴、操作記録 |
| **メトリクス** | **数値の時系列データ**を記録（**PromQL** 形式でクエリ可能） | CPU使用率、メモリ消費量、リクエスト数 |
| **トレース** | 1つのリクエストがどのように流れたか、**処理の経路を可視化** | リクエストが経由したサービス、各処理にかかる時間 |

> 【TIPS】**PromQL** は Prometheus に保存された時系列データをリアルタイムに集計できるクエリ言語。

---

## 4. モニタリングスイートのストレージ

- **ストレージ＝データを蓄積するための場所**。
- データの種類ごとに **3つのストレージ種別** がある。

| ストレージ種別 | 保存するデータ |
|----------------|----------------|
| **ログストレージ** | ログの保存 |
| **メトリクスストレージ** | メトリクス等の指標を保存 |
| **トレースストレージ** | トレースデータの保存 |

### システム領域とユーザ領域（重要）

| 領域 | 保存対象 | 削除・保存期間変更 | 課金 | トレース対応 |
|------|----------|--------------------|------|--------------|
| **システム領域** | さくらのクラウドが提供する機能のログとメトリクス | **できない** | **課金対象外** | － |
| **ユーザ領域** | 利用者が設定したログとメトリクス | 可（設定可能） | **課金対象**（**書き込みリクエスト量と保存期間**に基づき課金） | **対応** |

> ⚠️ 試験頻出: システム領域は**削除・保存期間変更不可・課金対象外**。ユーザ領域は**課金対象（書き込みリクエスト量＋保存期間で課金）**で**トレースにも対応**。

## 5. データ収集の方法とアクセスキー

- データを収集するには、まず各機能に対応した**ストレージ（リソース）を作成**する。
- ストレージごとに**保存期間**や**アクセスキー**を持つ。
  - **アクセスキー**＝各データの保存に必要な**認証情報**。
- 「アクセスキー」タブから「追加」ボタンでアクセスキーを追加。
- 追加後、メトリクス・ログ・トレースの各データに対応する **ID・シークレット・エンドポイント**（さくらのクラウド側への送信先）が表示される。
- データに応じた**連携ソフトの情報は設定例に例示**される。

### 機能ごとの連携ソフト（重要表）

| 機能 | 連携ソフト |
|------|-----------|
| **メトリクス** | **Prometheus** / **opentelemetry-collector** |
| **ログ** | **fluentbit** / **opentelemetry-collector** |
| **トレース** | **opentelemetry-collector** |

---

## 6. モニタリングスイートのルーティング

- **ルーティング**＝対象のサービスからストレージへデータを転送するための設定。
  - **ログルーティング**: ログを**ログストレージ**に送る。
  - **メトリクスルーティング**: メトリクスを**メトリクスストレージ**に送る。
- **対応サービス**: データベースアプライアンス、VPNルータ、エンハンスドロードバランサ、NFSアプライアンス、AppRun、シンプル監視 など。

---

## 7. ストレージデータの閲覧

- ストレージに蓄積されたデータは、モニタリングスイートの**専用Web UI 上で表示**。
- **ダッシュボード機能から Perses UI**（オープンソースのダッシュボード）を表示。
- **ストレージごとに詳細の確認やエクスポートに対応**。
- 閲覧種別: ログ閲覧 / メトリクス閲覧 / トレース閲覧。
- サインインは「**Sign in with Sakura Cloud**」をクリック。

---

## 8. アラート機能

- **アラートプロジェクト**は、アラートに関する設定をまとめて管理する。

| 設定項目 | 内容 |
|----------|------|
| **アラートルール設定** | 対象の**メトリクスストレージ**や、**閾値**を設定 |
| **ログ計測ルール設定** | **ログの件数をカウントしてメトリクス化** |
| **通知先設定** | **シンプル通知** または **EventBus** を指定 |
| **通知ルーティング設定** | どのアラートをどの通知先に送るかの指定 |

> ⚠️ 試験頻出: 通知先は**シンプル通知 または EventBus**。ログ計測ルールは**ログ件数をカウントしてメトリクス化**する。

---

## 9. まとめ

- モニタリングスイートは**多様な環境のシステム監視を行うためのプラットフォーム**。
- **ログ・メトリクス・トレース**のデータを蓄積し、可視化できる。
- 複数サービスのログを一カ所に集約し、**内部で何が起きているか、なぜ起きたのか**を分析できる。
- アラートのルール条件に応じ、**メトリクスの状態に基づいて通知**できる。

---

## 10. 試験対策・要点チェック

- [ ] モニタリングスイート＝**多様な環境（他社クラウド・オンプレミス含む）を一元管理**する監視プラットフォーム。
- [ ] 主な機能は **ストレージ / ルーティング / ダッシュボード（Perses） / アラート** の4つ。
- [ ] 扱うデータは **ログ・メトリクス・トレース** の3種類。メトリクスは **PromQL** でクエリ可能。
- [ ] **ダッシュボードは Perses**（オープンソース、Prometheus 等のデータを可視化）。
- [ ] シンプル監視＝**サービス監視（URL・ポート・SSL証明書）**、モニタリングスイート＝**内部データの収集・蓄積**。両者は**併用可能**。
- [ ] シンプル監視は**メトリクス保存なし**、モニタリングスイートは**メトリクス保存あり（可視化対応）・ログ検索対応**。
- [ ] ストレージ種別は **ログ / メトリクス / トレース** の3つ。
- [ ] **システム領域**＝さくらのクラウド提供機能のログ・メトリクス、**削除/保存期間変更不可・課金対象外**。
- [ ] **ユーザ領域**＝利用者設定のログ・メトリクス（**トレースも対応**）、**課金対象（書き込みリクエスト量＋保存期間）**。
- [ ] **アクセスキー**＝データ保存に必要な認証情報。追加後に **ID・シークレット・エンドポイント** が表示。
- [ ] 連携ソフト: メトリクス＝**Prometheus / opentelemetry-collector**、ログ＝**fluentbit / opentelemetry-collector**、トレース＝**opentelemetry-collector**。
- [ ] ルーティング対応サービス: **DBアプライアンス・VPNルータ・エンハンスドロードバランサ・NFSアプライアンス・AppRun・シンプル監視** など。
- [ ] 閲覧は専用Web UI（Perses）、**ストレージごとに詳細確認・エクスポート対応**。
- [ ] アラート設定4種: **アラートルール / ログ計測ルール / 通知先 / 通知ルーティング**。
- [ ] アラート通知先は **シンプル通知 または EventBus**。ログ計測ルールは**ログ件数をメトリクス化**。
