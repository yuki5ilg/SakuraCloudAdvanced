## 1. NoSQL の基礎

### NoSQL とは（用語定義・重要）
- **"NoSQL"** とは、**RDBMS（MySQLやPostgreSQL）と異なるデータベースの概念**。
- **パフォーマンス、信頼性、俊敏性に重点**を置き、データを迅速かつ効率的に処理する一連の概念。
- いくつかのパターンがある: **KVS（キーバリューストア）／グラフデータベース／カラム型データベース** など。
- 一般的に、NoSQLは**スケーラビリティ**を備える。
- **NoSQLはRDBMSを置き換えるものではなく、ユースケースの違い**（使い分け）。
- NoSQLは、**大量のログやイベント等のデータ格納**でパフォーマンスを発揮する。

### RDBMS と NoSQL の対比（登場背景）

| | RDBMS | NoSQL |
|------|-------|-------|
| 特徴 | 伝統的に使い勝手が良いが、**スケールに課題** | **パフォーマンスに優れ、スケーラビリティを備えている** |
| 代表例 | MySQL、PostgreSQL | （KVS、グラフDB、カラム型DB など） |

### NoSQL の想定利用シーン
- **高負荷・高可用性が求められるサービス用途**
  - SNS、動画配信、オンラインゲームなど、アクセスが集中するWebサービス
  - **水平スケールアウト**を前提とした大規模サービス基盤
- **継続的なデータ蓄積が前提となる用途**
  - IoT、センサーデータの時系列蓄積
  - リアルタイム解析基盤
- **耐障害性が求められる業務システム基盤**

## 2. Apache Cassandra（重要）

- Cassandraは、**分散型・高可用性のNoSQL**。
- **スケーラビリティ**を備え、**高可用性・耐障害性・一貫性**を備える。
- **分散設計は Amazon Dynamo、データモデルは Google の Bigtable を基盤**。
- **SQL に類似したクエリ言語（CQL）**を持つ。
- **Facebook が 2007年に開発**。多くの業界で大規模アプリケーションを支える。
- **オープンソース**として公開され、自由に利用できる。
- **マスタ（マスター）が存在しない構成**なのでノード障害に強い。
  - RDBMSのようなマスターが存在しないため、ノード障害にも耐えうる構成。
- **スケールアウト前提**の構成なので、クラウドのスケーラビリティと相性が良い。
- 主な利用シーン: **大量のデータ保存や分析**。

> ⚠️ 試験頻出: **分散設計＝Amazon Dynamo / データモデル＝Google Bigtable**。**Facebookが2007年に開発**。**マスタレス構成**でノード障害に強い。

### まとめ（教材内）
> NoSQLとは、パフォーマンス・信頼性・俊敏性に重点を置き、データセットを迅速かつ効率に処理できるようにする一連の概念。Apache Cassandra は、クラウドの特性を活かせるスケーラビリティを備えている。

## 3. さくらのクラウドNoSQL（概要）

- さくらのクラウドが提供する、**Apache Cassandra のマネージドNoSQLサービス**。
- **Cassandra ノードをコントロールパネルから作成・管理・削除可能**。
- ノード管理は **GUI** のほか、**API や CLI（cqlsh）** で操作可能。
- 初期設定の **bootstrap** や、障害発生時の **repair（リペア）** などの対応を簡略化。
- データベースの**作成・起動・停止・削除**など一連のライフサイクル管理に対応。
- さくらのクラウドの**マップ機能とも統合**。
- **安全に利用できる**
  - 接続元ネットワーク範囲の限定や、ユーザによるアクセス制御に対応。
  - **プライベートネットワーク内で安全に運用可能**。
- **運用面の機能充実**
  - **NFSアプライアンスに自動バックアップ可能**。
  - **モニタリングスイートとの連携**も可能。

### 提供プラン（最重要表）
**40GB / 100GB / 250GB の3構成**を提供。ストレージはいずれも **SSD**。

| プラン名 | スペック | ディスクサイズ | ストレージ | ノード数 | ノード追加上限数 |
|----------|----------|---------------|-----------|:---:|------|
| 40GBプラン | 2コア4GBメモリ | 40 GB | SSD | 1 | **追加不可** |
| 100GBプラン | 3コア8GBメモリ | 100 GB | SSD | 3 | **2台 × 3回** |
| 250GBプラン | 6コア16GBメモリ | 250 GB | SSD | 3 | **2台 × 3回** |

- **40GB**: 1ノード構成、**ノード追加不可**。
- **100GB**: 3ノード構成、**2ノード単位で追加可能（最大9ノード）**。
- **250GB**: 3ノード構成、同上で追加可能（最大9ノード）。

> ⚠️ 試験頻出: ノード追加は **2台ずつ × 最大3回 = 最大9ノード構成**（100GB/250GBのみ）。40GBは1ノードで追加不可。

## 4. NoSQL の使い方

### 基本操作の流れ
1. **事前設計**
2. **データベースを作成**
3. **接続情報を設定**（ネットワーク、認証）
4. アプリケーションから **Cassandra と同様にアクセス**
5. **バックアップを設定**
6. **定期リペアをスケジュール化**
7. 必要に応じて**ノードを追加**（100GB/250GB）
8. 不要になったデータベースを削除

### NoSQL 事前設計（重要）
さくらのクラウドNoSQLの利用には**ある程度の事前設計が必要**。

- **ネットワークの考慮（必須）**
  - NoSQLは **L2スイッチを経由して接続**するため、**東京第2ゾーンに事前にスイッチを準備**。
  - NoSQL作成前に **NoSQLのIPアドレスを決定**しておくとスムーズ（クライアントの接続先）。
- **バックアップの考慮**
  - NoSQLデータのバックアップには **NFSアプライアンスが必要**。予め準備すると設定がスムーズ。
- **暗号化**
  - NoSQL暗号化に対応する場合は、事前に **KMSキーを作成**しておく。

### コントロールパネルからのアクセス
- クラウドのホーム画面から操作。**事前の申し込み・申請は不要**、**オンデマンドですぐ利用可能**。
- ホーム画面から「**NoSQL**」を選択。

### NoSQL 管理画面
- Apache Cassandraのデータベース管理・操作をこの画面で行う。
- 契約中の**データベース名、コア、メモリ、ディスク**の情報を確認。
- 詳細情報の表示はデータベース「**名前**」をクリック。
- 「**情報**」画面から、**バックアップ設定の変更、Cassandraパラメータ設定**も可能。

## 5. データベース作成

### 作成前に検討すること（※必須項目に注意）
NoSQL画面で「**DB作成**」をクリックして作成開始。

| 検討項目 | 必須/任意 | 内容 |
|----------|:---:|------|
| アクセス用IPアドレス | **必須** | CassandraにアクセスするためのIPアドレス |
| 接続スイッチ | **必須** | どのスイッチに接続するか事前決定、無ければ新規作成 |
| 契約プラン | **必須** | 40GB / 100GB / 250GB |
| ユーザ名・パスワード | **必須** | Cassandraに接続するユーザ認証情報 |
| アクセス制限 | 任意 | 接続元IPアドレスまたはCIDRを決定 |
| KMS | 任意 | 使う場合は事前作成 |
| バックアップ設定 | 任意 | 行う場合はNFSサーバ作成（**後からでも設定可**） |

### 検討事項：基本項目
- **データベース名、プラン、ユーザ名、パスワード**を指定。

### 検討事項：ネットワーク設定
- データベース作成後、**スイッチに接続する必要あり**。
- 利用ゾーンは **東京第2ゾーン内のスイッチ**を指定。
- **プライベートネットワークでの接続を推奨**。
- Cassandra用の接続ポートをアプリ側で利用可能。

### 検討事項：アクセス制限
- 「**接続元ネットワーク**」＝ **ACL機能（オプション）**。
- 利用する場合はチェックを入れて有効化。
- **複数のIPアドレス、またはCIDRで接続元を制限可能**。

### 検討事項：バックアップ設定（重要表）
バックアップは「**自動**」と「**随時**」の2種類。

| 種類 | 内容 |
|------|------|
| **自動** | 実行間隔: **1–7日**で設定 / 実行時間帯: 任意指定 / 世代数: **1〜8世代** |
| **随時** | 任意のタイミングで手動取得。**古いバックアップの削除は手動** |

- **バックアップ先は NFSアプライアンスを別途用意**する。

### 検討事項：名前
- コントロールパネル上に表示されるデータベース名を入力。
- 最後に「**作成**」ボタンをクリックすると作成開始。

## 6. さくらのクラウドNoSQL の運用

### NoSQL（Cassandra）の管理
- 各種設定状況の確認・変更は管理画面を通して行う。
- NoSQL画面からデータベース名をクリックして各種設定変更が可能。

### Cassandra 詳細パラメータ設定
- 「**パラメータ設定**」をクリックし、対象項目を変更後、「**反映**」ボタンをクリック。

### リペア（重要）
- **リペアとは整合性を維持する機能**。
- 機能を使うには**複数のノードを事前に作成する必要あり**。
- 管理画面からリペア処理が可能。

| リペア種類 | 特徴 | 実行目安 |
|------------|------|----------|
| **増分リペア** | 軽量 | **1〜3日ごと**の実行が目安 |
| **完全リペア** | 全範囲 | 増分リペアとの併用なら**1〜3週間ごと** / 単独なら**7日に1回が最小** |

- ⚠️ **40GBプランではリペアは利用不可**。

### ノード追加（拡張）
- 対象は **100GB / 250GB プラン**。
- **2ノードずつ**、**最大3回追加（＝最大9ノード構成）**。
- 追加後は**自動的にデータ分散される**ため、**アプリ側の変更は不要**。
- **Cassandraにアクセスするエンドポイントは変わらない**。

### Cassandra のバージョン選択について（重要）
- サポート対象は **Cassandra 4系のみ**。
- 新規作成時は標準で**最新バージョン**が適用。
- 作成後は、**過去3世代分のマイナーバージョン**がサポート対象。
- **メジャーバージョンアップ（4→5）は非対応**。

### API / CLI の利用
- データベース作成、起動、停止、削除、バックアップ管理に利用可能。
- **運用自動化・IaCと相性がよい**。管理画面と同等操作をAPIで再現できる。
- クラウドのホーム画面から **APIキーを別途発行**する必要あり。
- **cqlsh クライアント**から、NoSQL（Cassandra）に直接接続可能。

### 監視
- **クラスタ状態、ノード状態、バックアップ状況**などをGUIで確認可能。
- **リペアの進行状況**も把握できる。
- **API でも状態取得が可能**。

## 7. 注意事項（試験頻出）

- **提供ゾーン: 東京第2ゾーンのみ**。
- バックアップには **NFSアプライアンス**を使う。
- **40GBプランはリペア・ノード追加 非対応**。
- **Cassandra のメジャーバージョンアップ不可**。

### まとめ（教材内）
- さくらのクラウドNoSQLは**マネージドデータベースサービス**のため、**運用設計が容易**。
- **高可用性・拡張性・分散性**を備えた堅牢なデータ基盤をクラウドサービスとして利用可能。
- 運用では**バックアップ、リペア、暗号化、ネットワーク要件**が必要。
- 適切な構成で、大規模サービスで安定して機能する。

## 8. 試験対策・要点チェック

- [ ] NoSQL = **RDBMSと異なる概念**。**パフォーマンス・信頼性・俊敏性**に重点。パターンは **KVS / グラフ / カラム型**。
- [ ] NoSQLは**RDBMSを置き換えるものではなく、ユースケースの違い**。大量ログ・イベント格納に強い。
- [ ] Cassandra: 分散設計＝**Amazon Dynamo** / データモデル＝**Google Bigtable**。
- [ ] Cassandraは **Facebookが2007年に開発**、**マスタレス構成**、**CQL（SQL類似）**を持つ。
- [ ] さくらのクラウドNoSQL = **Apache Cassandra のマネージドサービス**。GUI / API / CLI（**cqlsh**）で操作。
- [ ] プラン3種: **40GB（1ノード・追加不可）/ 100GB（3ノード）/ 250GB（3ノード）**、全て**SSD**。
- [ ] スペック: 40GB=**2コア4GB**、100GB=**3コア8GB**、250GB=**6コア16GB**。
