## A. 横断・最重要比較表

### コンテナ3サービス
| | コンテナレジストリ | 高火力DOK | AppRun |
|--|--|--|--|
| 役割 | Dockerイメージ保管 | GPUコンテナ実行 | サーバレスWebアプリ実行 |
| オートスケール | － | なし（タスク単位） | あり |
| API | なし | あり | あり |
| カテゴリ | グローバル | 専用ダッシュボード | 共用型/専有型 |

### AppRun 共用型 vs 専有型 ⚠️最頻出
| | 共用型 | 専有型 |
|--|--|--|
| 実行環境 | 複数利用者で共有 | 専有クラスタ(Kubernetes) |
| **オートスケール基準** | **同時リクエスト数** | **CPU使用率** |
| ゼロスケール | **対応（スケール0）** | － |
| 分離 | － | ワーカノードを仮想サーバレベルで分離 |
| 用途 | 小規模・新規・バックエンドAPI | マイクロサービス・冗長・高セキュリティ(自治体等) |
- バージョンは**最大5世代**保持。**共用型⇔専有型の相互変更は不可**。専有型クラスタ作成には**「作成・削除」IAMポリシーのサービスプリンシパル**が必要。

### 高火力 DOK / VRT / PHY
| | DOK | VRT | PHY |
|--|--|--|--|
| 区分 | マネージドコンテナ | クラウドサーバ | GPUベアメタル |
| 操作単位 | タスク/ノートブック | 仮想サーバ | 物理サーバ |
| GPU | H100/V100 | H100/V100 | **H100/H200/B200** |
| 専有 | 8GPU専有プランあり | － | すべて専有 |
- DOK: 課金は**起動時間のみ・秒単位**。結果は**オブジェクトストレージ**へ。ノートブックの成果物は環境変数 **`$SAKURA_ARTIFACT_DIR`**。

### ロードバランサの選択 ⚠️設計編最頻出
| | LB（アプライアンス） | エンハンスドLB |
|--|--|--|
| レイヤ | **L4(TCP)** | **L7(HTTPS)** |
| 方式 | **DSR型** | プロキシ型 |
| セッション維持 | **不可**（アプリ/外部ストアで） | **可（スティッキー）** |
| グローバル接続 | 共有セグメント直結不可（ルータ＋スイッチ/VPNルータ配下） | グローバル対応・エニーキャスト |
- ⚠️ **DSR**＝実サーバにループバックIF設定＋ARP応答抑制が必要（OS/NW設定変更前提、アプリ非改修）。
- ⚠️ **エンハンスドLBのCPSはHTTPS時にプラン表示の1/10**。
- アプライアンスLBの固定仕様＝**DSR / 最小接続数(Least Connection) / L4**。

### GSLB vs エンハンスドLB（切替）
- **GSLB＝DNSベース（DNSラウンドロビン相当）**。切替反映は**クライアントのDNSキャッシュ(TTL)依存＝即時不可（数分）**。**重み100:0は設定不可**→ソーリーサーバで対応。権威DNSは別途用意し**GSLBのFQDNをCNAME**設定。
- **エンハンスドLB＝切替が速くシンプル・L7高度負荷分散**。

### リージョン/ゾーン 🔢
- リージョンは**東京・石狩**の2地域。ゾーン: 東京/東京第2/石狩/石狩第2/石狩第3 等（プラン・料金・提供状況が多少異なる）。
- ⚠️ **オブジェクトストレージは2025年12月より石狩に加え東京でも利用可能**。
- NoSQL(Cassandra)は**東京第2ゾーンのみ**。

## B. 要素技術 分冊サマリ

### 1.1.1 コンテナ
- Docker発表**2013年**、思想**Build/Ship/Run**。コンテナ＝名前空間分離のLinuxプロセス。
- レジストリ: ホスト名 **`名前.sakuracr.jp`**（一意）、push前に **`docker tag`**、認証情報は **`~/.docker/config.json`**。
- 公開設定: **Pullのみ（認証不要・Push不可）/ 非公開（認証要・Push可）**。権限: All / Push&Pull / Pullのみ。

### 1.1.2 アプリ連携 🔢
- **シンプルMQ**: At-Least-Once（重複あり→冪等設計）、最大**256KB**（バイナリはBase64）、可視性タイムアウトあり、キュー名は作成後変更不可、APIキーは一度のみ表示。
- **シンプル通知**: メール/Webhook。上限**10分1,200件・1日1,500件**（JST3:00リセット）。
- **EventBus**: スケジュール（最短**1分**）＋イベント検知（ソース=モニタリングスイート/イベントログ）、ジョブ=通知/MQ/オートスケール、ベストエフォート。
- **APIゲートウェイ**: 認証4種＝**BASIC/HMAC/JWT/OIDC**。CNAMEは `cname.tk1.apigw.sakura.ne.jp`。オブジェクトストレージ連携は**GET/HEAD/OPTIONSのみ**。
- **Workflows**: YAML Runbook（meta/args/steps）。制限＝**256KB/5000ステップ/並列100/実行1年/履歴90日**。サービスプリンシパルIDは作成後変更不可。

### 1.2.1 分散DB（Cassandra）🔢
- NoSQL＝KVS/グラフ/カラム型。RDBMSの置換ではなくユースケース違い。
- Cassandra: 分散設計=**Amazon Dynamo**/データモデル=**Google Bigtable**、**Facebookが2007年開発**、**マスタレス**、**CQL/cqlsh**。
- プラン: **40GB(1ノード・追加不可)/100GB(3ノード)/250GB(3ノード)**、全SSD。
- ノード追加＝**2台ずつ×最大3回＝最大9ノード**（100/250GBのみ）。
- バックアップ＝**NFSアプライアンス必須**（自動 間隔1–7日/1〜8世代）。リペア（整合性維持）増分1〜3日・完全1〜3週間/単独7日に1回、**40GBは不可**。
- **Cassandra 4系のみ**、メジャーアップ(4→5)不可。**東京第2ゾーンのみ**。

### 1.3.1 CDN（ウェブアクセラレータ）🔢
- 料金: **プランなし・従量課金・アウトバウンドのみ課金**。プロジェクトごとに無償利用枠。
- 仕様: HTTP/2、**TLS1.2/1.3**、**東京・大阪2拠点（指定不可）**、**サイト数20**。
- キャッシュ: **GETのみ / 最大7日 / 最大2GiB-1 / URL単位（クエリ込み）**。制御は **Cache-Control**（`s-maxage`）。無効化＝**no-store/private/Pragma:no-cache**。
- ⚠️ オリジンとCP両方設定時は**オリジン設定が優先**。
- SSL証明書は**独自ドメインのみ登録可（Let's Encrypt自動更新）**。生成FQDN `*.user.webaccel.jp` は利用者登録不可。
- ドメイン: 独自（全経由）/サブドメイン（一部経由）。オリジン: ウェブサーバ/オブジェクトストレージ。
- サイトは作成後**手動で有効化**。独自ドメインは有効化前に**CNAMEまたはTXTでドメイン認証**。**x-cache**＝HIT/MISS。

### 1.4.1 モニタリングスイート
- **他社クラウド・オンプレ含む一元監視**。機能4つ＝**ストレージ/ルーティング/ダッシュボード(Perses)/アラート**。データ3種＝**ログ/メトリクス/トレース**（メトリクスは**PromQL**）。
- ⚠️ **シンプル監視＝サービス監視（URL/ポート/SSL）・メトリクス保存なし**。モニタリングスイート＝内部データ収集・保存。**併用可**。
- ストレージ: **システム領域（削除/期間変更不可・課金対象外）/ ユーザ領域（課金＝書込量＋保存期間・トレース対応）**。
- 認証＝**アクセスキー**（ID/シークレット/エンドポイント）。連携＝Prometheus/fluentbit/opentelemetry-collector。アラート通知先＝**シンプル通知 or EventBus**。

### 1.5.1 データ暗号化（KMS/シークレットマネージャ/HSM）🔢
- **KMS**: **エンベロープ暗号化**（データ暗号キーをKMSキー=マスターキーで暗号化）。生成＝自動（**FIPS 140-2 level3 HSM**）/ **BYOK（256bit＋base64）**。
  - ステータス: 有効(暗号○復号○)/**制限中(暗号×復号○)**/**一時停止中(両方×)**/削除保留中。削除猶予**7〜90日**で復元不可。ローテーション＝最新は暗号化/復号、旧は**復号のみ**。
- **シークレットマネージャ**: **KMSと連携して暗号化**。**KMSキー削除で復元不可（事業者でも不可）**。ローテーション対象＝**DBアプライアンス/エンハンスドDB**、**サービスプリンシパル権限依存・同一ゾーン制約**。
- **クラウドHSM**: **Luna Network HSM 7**、メモリ**640KB**・RSA**100qps**・VIP最大**20個**。ライセンスは**1サーバ/VM毎**。**冗長化・バックアップなし（利用者管理）**。閉域接続（ローカルルータとピアリング）。

### 1.5.2 ガバナンスと統制
- 2本柱: **サービスポリシー（予防的統制）/ セキュリティコントロール（発見的統制・脅威検知）**。
- サービスポリシーは**組織→フォルダ→プロジェクトに継承**。4ルール＝**cloud-restrict-zone / cloud-restrict-service / cloud-restrict-member-authentication / iam-disable-api-key-creation**。
- ⚠️ **サービスポリシーはIAM/IDポリシーより優先**。IAM/ID＝権限付与(ユーザ対象)、サービスポリシー＝操作制御(リソース階層)。
- セキュリティコントロール＝**イベントログの拡張**。自動アクション＝シンプル通知連携/ワークフロー実行。重大度＝**低/中/高・致命的**。結果は「リスクの可能性」を示すのみで**最終判断は利用者**。

## C. 設計編 分冊サマリ

### 2.1.1 デザインパターン（定石）
1. **可用性・拡張性**: アプライアンスLB＋DBアプライアンス。LB配下サーバの拡張は**停止を伴う→負荷分散対象から除外してから**。
2. **コスパ**: CDN（静的=ウェブアクセラレータ/オリジン=オブジェクトストレージ、動的=Webサーバ）。**1サイト1バケット**、キャッシュ長めが効果最大。
3. **DR**: GSLB＋2ゾーン＋**ブリッジ接続**。**ウォームスタンバイ=常時2倍コスト** vs **パイロットライト**（DR側通常停止）。
4. **インターネットVPN**: サイト間VPN＝安価・セキュア、E2E品質は**低い側が上限**、**BGP/動的ルーティング不可**→マーケットプレイスNWサービス。
5. **ハイブリッド**: Web=クラウド/DB=専用サーバPHY、間は**ブリッジ接続**。**PHYはバックアップサービスなし**。帯域 PHY=2〜20Gbps/クラウド=1〜10Gbps。

### 2.2.1 小規模
- 共通: **高可用性/冗長化は必須でない・最小構成**。
- 固定IPがない拠点→**VPNルータ不適切・マーケットプレイスNWサービス**。サイト間VPNは**CIDR重複不可**。
- 共有セグメント＝100Mbps・追加料金不要。ルータ＋スイッチ＝100M〜5Gbps（ゾーンにより最大10Gbps）。追加IPは**運用必要5個を引いた数**（/28=16→11）。
- DBは**非公開**（Web/AP公開・DB非公開）。リモートアクセスVPN（WireGuard可）。

### 2.2.2 中規模（共通: Web/AP 2台・DB 2台で冗長化）
- ケース1: CMS＋セッション維持→**L7(エンハンスドLB)スティッキー**。静的はCDN＋オブジェクトストレージ。⚠️NFSアプライアンスはシングル構成。
- ケース2: ユーザ固有データ・TCP分散→**L4(アプライアンスLB)・DSR**。CDNメリット限定的。
- ケース3: DR＝**GSLB手動切替・待機系停止が最安**。**RPO1日/RTO6時間**。DBゾーン間同期: **冗長化オプションありはマルチゾーン非対応**、マルチゾーン自動同期は**DBアプライアンス(クラスタ)＝3ゾーンマルチマスタ**。**SEG**でオブジェクトストレージへプライベート接続。

### 2.2.3 大規模
- ケースA（基幹・閉域）: **業務NW/中間NW/公開NW(DMZ)の3層分離**。閉域は**ダイレクトアクセス（L3分割要）**。各サーバ**NIC2枚**、VPNルータFW＝**スタンダード(シングル)/プレミアム(冗長)**、ケーブル標準2本。**DR対象外**。
- ケースB（SaaS Web）: Web/AP**ステートレス＋オートスケール(Act/Act)**、認証**JWT**。CDN＋オブジェクトストレージ。DB＝**プライマリ＋リードレプリカのゾーン間冗長**（停止時に別ゾーンがプライマリ化）。負荷分散本命=**エンハンスドLB(エニーキャスト)**、代替=GSLB多段(TTLで即時切替不可)。**マネージドDBキャッシュなし→Redis自前**。**オブジェクトストレージのリージョン間レプリは自動切替されない**。
- ケースC（マルチハイブリッド）: オンプレ＋海外クラウド＋さくらの3者。移行基準＝**トラフィック課金大/マネージド非依存/国内データ志向/新規**。残す基準＝**クラウド固有依存/移行コスト高/廃止予定**。海外クラウドは**アウトバウンド課金・為替・レイテンシ**注意。**サイト間VPNはBGP非対応**。

## D. ひっかけ注意リスト（最終確認）
- AppRunオートスケール: 共用=**同時リクエスト数** / 専有=**CPU使用率**。
- 共用型⇔専有型の変更**不可**。バージョンは**5世代**。
- 高火力 **H200/B200はPHYのみ**。DOK課金は**起動時間のみ**。
- L4=DSR・セッション維持不可 / L7=プロキシ・スティッキー可。エンハンスドLBのCPSは**HTTPSで1/10**。
- NFSアプライアンスは**シングル構成**。VPNルータは**スタンダード=シングル/プレミアム=冗長**。
- 共有セグメントに**アプライアンスLBは直結不可**。
- GSLBは**TTL依存で即時切替不可・重み100:0不可・CNAMEで権威DNS連携**。
- DBアプライアンス**冗長化オプションありはマルチゾーン非対応**／**クラスタ=3ゾーンマルチマスタ**。
- KMS**制限中=復号のみ**／**一時停止中=両方不可**／削除猶予**7〜90日**。BYOK=**256bit+base64**。
- KMSキー削除でシークレット/暗号化データは**復元不可**。
- クラウドHSMは**冗長化・バックアップなし**。
- サービスポリシーは**IAM/IDより優先**、組織階層に**継承**。
- ウェブアクセラレータ: **GETのみ/最大7日/2GiB-1/URL単位**、課金は**アウトバウンドのみ**、証明書は**独自ドメインのみ**。
- オブジェクトストレージは**2025年12月から東京でも提供**。
