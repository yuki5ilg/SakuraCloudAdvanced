## 1. サーバプラン（仮想サーバ）

- さくらインターネットによる **自社構築・自社運用のクラウド基盤** 上の仮想サーバ。「伸縮自在」「高品質低価格」。
- プランは **CPUの仮想コア数 × メモリサイズの組み合わせ** で構成。

### 提供プランのスペック範囲（重要表）

| プラン種別 | 最小スペック | 最大スペック |
|-----------|------------|------------|
| 通常プラン | CPU 1コア / メモリ 1GB | CPU 20コア / メモリ 224GB |
| コア専有プラン | CPU 2コア / メモリ 4GB | CPU 192コア / メモリ 1024GB |

- 仮想コア数に応じて **選択できるメモリサイズには範囲がある**。
  - 例: CPU 1コア → メモリ 1〜5GB / CPU 20コア → メモリ 16〜224GB

### 料金
- プランに応じた **時間額・日額・月額** が設定されている。
- 仮想コア数とメモリサイズが大きいプランほど高価。
- **東京リージョンと石狩リージョンで料金が異なる場合がある**。

## 2. サーバの作成と削除

### 作成のモード（2種類）
| モード | 特徴 |
|--------|------|
| シンプルモード | いくつかのメニュー選択と情報入力で簡単にサーバを作成 |
| 通常モード | 詳細な条件でサーバを作成 |

- サーバ作成時、**OSがインストールされた状態のディスクを同時に作成できる**。
- 設定項目: OSのホスト名、OSの管理ユーザのパスワード、コントロールパネル上に表示されるサーバの名前 など。
- デフォルトでは作成後にサーバが自動起動する。**自動起動させない場合はチェックを外す**。
- **同時に複数台作成可能**。2以上を入力すると `hostname-01`, `hostname-02` … のように名前の後ろに連番が付与される。

### 削除
- 削除には **サーバの停止が必要**。
- サーバに接続されているディスクも同時に削除できる。

## 3. サーバのステータスと電源操作

### ステータス（重要表）

| ステータス | 状態 |
|-----------|------|
| UP（起動） | 電源が投入された状態 |
| DOWN（停止） | 電源が未通電の状態 |
| CLEANING（準備中/起動処理中） | シャットダウン完了後、クラウド基盤上のDBを更新している状態。電源操作不可だが、通常数秒〜数十秒で停止状態に遷移 |

### 電源操作（重要表）

| 電源操作 | 機能 |
|----------|------|
| 起動 | サーバへ電源投入し起動する |
| cloud-init起動 | cloud-init対応アーカイブから作成したディスクを接続したサーバを起動する際、cloud-configで起動後の構成情報を設定できる |
| シャットダウン | 電源ボタン押下をエミュレート。ACPI対応OSならシャットダウン処理が始まり自動的に電源オフになる |
| 強制リブート | リセットボタン押下をエミュレート。状態に関わらずOS動作を中断し起動手順を開始 |
| 強制停止 | サーバの電源がオフになる。操作実行時点で電源断される |

### ホストサーバの変更（重要）
- **シャットダウン→起動 / 強制停止→起動** … サーバが起動するホストサーバは**変更される**。
- **強制リブート / OS上で reboot** … 起動するホストサーバは**変更されない**。

### 強制停止・強制リブートの注意
- 通常のシャットダウン処理が行われず、**ディスク不整合により次回起動時に不具合が出る可能性**。
- 使用するのは、電源操作メニューのシャットダウンを実行しても反応がない場合、またはターミナル内でのシャットダウン・リブート操作に反応がない場合。

### その他
- 複数サーバを選択して **電源の一括操作が可能**。ただし **cloud-init起動は個別選択時のみ**可能。
- ACPI(Advanced Configuration and Power Interface)対応OSはコントロールパネル操作でシャットダウン可能。

## 4. プラン変更・クローン・タグ

### プラン変更
- CPUの仮想コア数とメモリサイズを変更できる。
- **サーバの停止が必要**。
- プランを変更すると **リソースIDも変更される**。
- **プラン変更前のサーバの作成日時は引き継がれない**。
- ※ サーバ停止が必要なその他のケース: NICドライバを異なるタイプに変更 / ディスクを接続 / NICを追加。

### クローン機能
- 既存のサーバを元に新規でサーバを作成する機能。
- **追加したNICや2つ目以降のディスクのコピーは行われない**。

### タグ機能
- サーバやディスクなどのリソースに付与し、種類や役割に応じた分類ができる。
- 一部のタグは付与すると**特殊な機能が使える（特殊タグ）**。

### 特殊タグ（重要表）

| 特殊タグ | 機能 |
|----------|------|
| @keyboard-us | サーバ上のキーボードをUS配列として設定する |
| @group | サーバをグループ化し、起動するホストサーバを分離する |
| @auto-reboot | サーバ停止時に自動起動する。**サーバ内のシャットダウンコマンドによる停止が対象**。コントロールパネルやAPIでの停止操作は自動起動の対象外 |
| @boot-cdrom | 接続された仮想CD-ROMドライブから優先して起動する |
| @boot-network | 仮想NICのPXE boot機能から優先して起動する。@boot-cdromと同時設定すると起動順序が不明確になる場合あり |
| @cpu-topology | CPUのハードウェア情報を変更し、OS側でCPUソケット個数が**1ソケット**と認識されるようにする。Windows Server + MS SQLなどソケット数でライセンス料金が変わる環境で利用 |

- ※ 収容先ホストにメンテ予定が発生すると **`@mainte-YYYYMMDD-*`** タグが自動付与される。

### @group（グループ化）の詳細
- 複数サーバをグループ化し、収容先ホストサーバを分散できる。
- グループは **A, B, C, D の4つ**から選択。
- 異なるグループのタグが付与されたサーバは、起動時にそれぞれ別のホストサーバで起動する（例: @group=Aのサーバ1とBのサーバ2は別ホスト）。
- ※ 起動先ホストはコントロールパネルで「収容ホスト名」と表示（サーバ一覧/詳細の情報タブで確認）。

## 5. NICとスイッチ接続

### サーバのNIC（作成時）
- NICの接続先ネットワークを指定する。
- デフォルトは **「インターネットに接続」**＝無料のグローバルネットワーク「共有セグメント」に接続。
- 共有セグメント接続のNICには **グローバルIPアドレスが自動的に1つ割り当てられる**（さくらのIPアドレスプールの未使用アドレスから。過去割当アドレスが空いていれば優先割当されるが、再割当は保証されない）。

### NICの追加とスイッチ接続（重要）
- サーバ作成後にNICを追加できる。
- **1台のサーバに搭載できるNICは最大10個**。
- 追加したNICを **グローバルネットワークに接続することはできない**。
- 追加したNICは **スイッチに接続する必要がある**（同じゾーンに事前にスイッチを作成。他ゾーンのスイッチには接続不可）。
- 操作はサーバ詳細画面のNICタブ。追加だけでなく削除も可能。**サーバの停止が必要**。
- ※ NICドライバは **VirtIO** と **Intel e1000ドライバエミュレーション** の2種類から選択。**デフォルトはVirtIO**。VirtIOは仮想NICのマルチキュー(CPUコア分散)に対応しネットワーク処理性能の向上が期待できる。

### NICタブで操作できること
- **NICの詳細情報**: リソースID・MACアドレスを確認できる。MACアドレスはNIC作成時にグローバルに一意なアドレスが自動割当され、利用者は割当・変更不可。
- **DNS逆引きレコード設定**: 割り当てIPアドレスに逆引きレコードを設定可能。**1つ目のNICでのみ設定可能**。事前に逆引きするホスト名が正引きレコードとして登録され、その値にサーバのIPアドレスが設定されている必要がある。
- **IPv4アドレス設定**: コントロールパネル表示用のIPv4アドレス（NICリスト・マップ機能で使用）。**2つ目以降のNICで設定可能**。**サーバOSの設定には反映されない**（OS上のIPはOSで設定する）。
- ※ NICタブにはゾーンに応じた「推奨ネームサーバ」が表示される。無料で利用でき、東京と石狩でネームサーバが異なる。

## 6. ディスク・ISOイメージの操作

### ディスクの接続と取り外し
- サーバ詳細画面の「ディスク」タブで操作。
- **1台のサーバには最大3台までディスクを接続できる**。
- **サーバの停止が必要**。

### ISOイメージの挿入と取り出し
- サーバ詳細画面の「ISOイメージ」タブで操作。仮想CDドライブにISOイメージを挿入できる。
- **1台のサーバに挿入できるISOイメージは1つ**。
- パブリックISOイメージのほか、利用者がISOイメージ機能でアップロードしたISOイメージを利用可能。

## 7. 監視・コンソール接続

### シンプル監視とアクティビティ
- 「シンプル監視」タブ: そのサーバについてシンプル監視機能で監視している項目の一覧を確認できる。
- 「アクティビティ」タブ: 以下の時間経過をグラフで確認できる。
  - **CPU時間 / NICのトラフィック / ディスクの転送量**

### コンソール接続
- サーバ詳細画面の「コンソール」タブ。コンソール入出力をコントロールパネルやVNCクライアント経由で操作（仮想ディスプレイ表示・キーボード/マウス入力）。
- 用途: ネットワーク未接続状態のサーバ操作 / GUIでのサーバ操作 / OSのシングルユーザモード / ネットワーク設定を誤り外部から接続できない場合の操作。
- 接続方法: コンソール画面をクリック、または右上「リモートスクリーンに接続」→「HTML5モード」。
- 機能: **NMI(Non-maskable interrupt)送信**（NMI対応OSでメモリダンプ取得時に使用）、文字列のコンソールへの貼り付け、VNC接続用 vncファイルのダウンロード。
- ※ コンソールは日本語配列キーボード前提。JP/JP106以外を設定している場合などは一部キー（アンダースコア等）が入力できない場合がある。

## 8. コア専有プラン

- **ホストサーバのCPUコアを専有利用**するプラン。通常プランはCPUコアを複数サーバで共用するが、コア専有はサーバに専用割り当てし、**安定した動作が期待できる**。
- ホストサーバに搭載されているCPUに応じた **3つのタイプ**がある。

### 提供プラン（重要表）

| タイプ | 最小プラン | 最大プラン | ゾーン |
|--------|-----------|-----------|--------|
| Intel® Xeon® Processor | CPU 2コア / 4GB | CPU 10コア / 96GB | すべてのゾーンで利用可能（ゾーンによる料金差なし） |
| AMD EPYC 7003 Series | CPU 32コア / 120GB | CPU 128コア / 480GB | 石狩第3ゾーンを除くすべてのゾーン（料金差なし） |
| AMD EPYC 9004 Series | CPU 192コア / 1024GB（単一） | 同左 | 東京第2ゾーンおよび石狩第3ゾーン |

### 注意点
- **シンプルモードでは選択できない**。**通常モードで作成**する。
- Intel Xeon と AMD EPYC でホストサーバの仕様が異なり、動作確認済みOSなど一部の仕様に相違がある（詳細はクラウドマニュアル）。

## 9. 高火力VRT(GPU)プラン

- **GPUが搭載されたサーバ**。GPUによる計算能力を必要とする用途向け（CGレンダリング、機械学習、ディープラーニング、高度な科学計算）。
- **2つのプラン**を提供。

### 提供プラン（重要表）

| 項目 | V100プラン | H100プラン |
|------|-----------|-----------|
| アーカイブ | NVIDIA V100 | NVIDIA H100 |
| 搭載GPU | NVIDIA V100 32GB × 1 | NVIDIA H100 SXM 80GB × 1 |
| CPU | 4コア | 24コア |
| メモリ | 56GB | 240GB |
| ゾーン | 石狩第1ゾーンでのみ利用可能 | 石狩第1ゾーンでのみ利用可能 |

### 料金
- **時間額は24時間まで適用される**（※通常プランの時間額は10時間まで）。それ以外は通常プランと同じ料金体系。

### 注意点
- **1つのGPUを専有して利用**できる。
- **シンプルモードでは選択できない**。**通常モードで作成**する。
- **OSにWindows Serverを選択できない**（動作確認済みOSはクラウドマニュアル）。
- **サーバにGPUドライバのインストールが必要**（サーバ作成後に利用者がインストールする）。

## 10. 専有ホストプラン

- **ホストサーバを専有利用**するプラン。通常プランはホストサーバのCPUコアを複数の利用者で共用するが、専有ホストはホストサーバのリソースを独占し、**安定した動作が期待できる**。

### 専有ホストを利用するケース
- **コンプライアンス要件**: 同一ホストで他利用者と共用することが許されない等。
- **ソフトウェアのライセンス要件**: ホストサーバのスペックでライセンスコストが変化するソフトを導入する等。
- **負荷状況に応じたキャパシティプランニング**: CPUのオーバーコミット率を利用者側でコントロールできる。

### 提供プラン（重要表）

| 項目 | 標準専有ホスト | Windows専有ホスト | 専有ストレージ用ホスト |
|------|---------------|-------------------|----------------------|
| 物理コア数 | 20コア | 20コア | 96コア |
| 最大仮想コア数 | 200仮想コア | 200仮想コア | 960仮想コア |
| 物理メモリ容量 | 224GB | 224GB | 1024GB |
| 用途 | Windows以外の仮想サーバを起動 | Windowsの仮想サーバを起動 | 専有ストレージに対応 |
| ゾーン | すべてのゾーンで利用可能 | すべてのゾーンで利用可能 | 東京第2ゾーンでのみ利用可能 |

### 仕組みと制約（重要）
- 専有ホスト上のサーバには、合計で **200個の仮想コア**・合計 **224GBのメモリ** を割り当て可能（標準専有ホストの場合）。
- 同じゾーン内で**停止中のサーバ**から専有ホスト上で起動するサーバを割り当てる。割り当ての追加・解除は**停止中のサーバのみ**可能。
- **物理マシンをそのまま利用するサービスではない**。ベアメタルや専用サーバではなく、**仮想化基盤の一部**として提供。提供範囲は**ホストサーバ部分のみ**（ネットワークやストレージ等は通常プラン同様、別リソース）。
- 専有ホスト上のサーバでは **Nested VM** を利用できる（Hyper-V 仮想サーバ内でHyper-Vを実行可能）。
- 専有ホスト上で起動できるのは**サーバのみ**。アプライアンス(VPNルータ等)は起動不可。
- 解約時は、全サーバの割り当てが解除されている必要がある（ただし**全サーバが停止状態の場合のみ、同時に割り当て解除が行われる**）。
- ※ 特殊タグ **@group は専有ホストで起動するサーバには効力がない**。専有ホストで起動する際は @group タグを外す。

## 11. パブリックアーカイブ

- **各種OSが初期インストールされた状態のアーカイブ**。インストール作業なしにOSがブートする状態のサーバを作成できる。サーバ作成時に**ディスクのソースとして指定**する。

### 料金
- **無料で利用できる**。ただし**有償OSの場合は別途ライセンス料金が発生**する。

### サポート・提供ポリシー
- LinuxやWindows Serverなど様々なOSを提供。利用可能なOSと設定内容（リリースノート）はクラウドマニュアルで公開。
- さくらインターネットによってサポートされるが、**OSやアプライアンスによってサポート範囲が異なる**。
- 提供ポリシーに沿って新OSの公開と古いOSの取り下げが行われる。
- 過去に提供終了した一部のアーカイブは **アーカイブ共有機能**で利用可能（ただし**サポート対象外**）。
- ※ 提供中のアーカイブ/ISOには識別用タグが付与され、API取得時に使用される。

### Windows Server パブリックアーカイブ（重要表）

| アーカイブ | 説明 |
|-----------|------|
| Windows Server Datacenter Edition | 標準のアーカイブ。リモートデスクトップ機能は**管理目的のみ**利用許可 |
| Windows Server for RDS | デスクトップ用途。リモートデスクトップ接続のライセンスが**1つ**組み込まれている |
| Windows Server for MS SQL | SQL Serverがインストール済み。複数エディションを提供 |

- ※ for RDS と for MS SQL では、MS Office利用ライセンス組み込みのアーカイブが別途提供される。
- ※ 必要に応じて別途 RDS SALライセンスを契約できる。
- 提供OSのエディションは **Datacenter Edition**。バージョンはクラウドマニュアル参照。
- 対応するディスクは **最小100GB、最大2TB**。
- ※ アーカイブには ActiveDirectory のユーザ数無制限CALライセンス相当が含まれる。

### Red Hat Enterprise Linux Server パブリックアーカイブ
- **石狩第3ゾーンおよび東京第2ゾーン**で cloud-init対応アーカイブを提供。
- コア専有プラン(Intel Xeon) の **2〜8コア**のプランに対応。

### cloud-init 対応アーカイブ
- 指定した構成情報に従い、**サーバの初回起動時に自動的に初期設定**を行える。
  - OSの基本設定（ホスト名、パスワード、タイムゾーン等）
  - SSH公開鍵の設置、指定パッケージのインストール
  - スクリプトの実行
- cloud-init はクラウド上のサーバ初期化を自動化するツール。さくらのクラウドでは cloud-init を使ってスタートアップスクリプトを実行することもできる。
- cloud-init対応アーカイブは、アーカイブ名の末尾に **「cloudimg」** が付与されている。

## 12. スタートアップスクリプト

- **サーバ起動時に自動的に実行するスクリプト**。ディスクに設定したスクリプトがサーバ起動時に自動実行され、初期設定を自動化する。
- 用途例: 必要なアプリの自動インストール、多数のユーザ登録、OSの全般的な設定の自動化。

### 料金
- **無料で利用できる**。**Linuxのパブリックアーカイブに対して動作保証**がされている。

### クラス（2種類）と実行タイミング（重要）

| クラス | 内容 | 実行タイミング |
|--------|------|---------------|
| SHELL | シェルスクリプト | **サーバ起動時に毎回実行** |
| YAML_CLOUD_CONFIG | YAML形式のスクリプト | **サーバ初回起動時のみ実行** |

- ※ SHELLクラスを初回起動時のみ実行したい場合は、スクリプト内に特殊タグ **@sacloud-once** を付与する。

### 特殊タグ（重要表）

| 特殊タグ | 説明 |
|----------|------|
| @sacloud-once | コメントとして記述すると、起動時に1回のみ実行される |
| @sacloud-desc / @sacloud-desc-begin / @sacloud-desc-end | ディスク作成画面のスタートアップスクリプト選択欄に説明文として表示される文字列を指定 |
| @sacloud-require-archive | サーバ作成画面で指定OS以外のパブリックアーカイブを選択した場合に警告を表示。想定外環境への適用を防止 |
| @sacloud-tag | スタートアップスクリプトのリソースにタグを付与。@require-core / @require-memory-gib を指定すると、指定の仮想コア数・メモリに満たない場合にサーバ作成画面で警告を表示できる |

## 13. システム構成設計の考え方

### サーバプランの検討
- ソフトウェアやアプリのシステム要件に応じて、適切なサーバプランとOSを選択。CPUの仮想コア数とメモリサイズを検討。
- **通常プラン・コア専有・専有ホスト・高火力VRT(GPU)プラン**から選択。
- **機密コンピューティングが必要な場合は機密VMプランを検討**。
- 利用したいスペックのプランが提供されているか事前に確認（仮想コア数ごとに選択可能なメモリ範囲が異なる）。
- レンダリング・機械学習・高度な科学計算などGPU計算能力が必要なら高火力VRT(GPU)プランを検討。

> ※ 機密VMプラン: ソフト実行中のメモリを暗号化し内容を秘匿して処理する技術。さくらのクラウドの機密VMプランは **AMD Secure Encrypted Virtualization (SEV)** を用いる。VM固有の暗号鍵でレジスタ/メモリ領域を暗号化し、当該VM以外からのメモリアクセスをCPU内蔵機能で拒否。ハイパーバイザー侵入や管理者の悪意からVMを保護。金融・医療・公共機関など高セキュリティ業務に適する。安全性検証には**リモートアテステーション**という仕組みが取られる。

### NIC・ネットワークの検討
- NICドライバは特別な要件がない限り **VirtIO** を選択（高パフォーマンス。特にLinuxでVirtIOを選ばないと通信遅延やパケット分割/重複が発生することがある）。
- **複数NICを使ったボンディング構成はとれない**。
- **1つのスイッチまたは共有セグメントに、同じサーバの複数NICを接続することはできない**。

### パブリックアーカイブとOSの選択
- Linuxサーバはパブリックアーカイブ提供OSからの選択を検討。リリースノートを確認し、必要なソフトのインストール・設定変更はサーバ作成後に行う。
- 提供されていないOSは、パブリックISOイメージまたは利用者アップロードのISOイメージでインストールする。
- ※ 機密VMプランでは検証用パブリックアーカイブを利用できる。

#### Windows Server / ライセンス
- 必要なライセンスを確認し適したアーカイブを選択。VDI等デスクトップ用途は **for RDS**（利用人数に応じた RDS SALライセンスも契約）、SQL Serverは **for MS SQL**。
- 基本はさくらインターネット提供のライセンスを使用。持ち込みは提供者に可否を確認。
- Windows Server は **SPLA（Service Provider Licence Agreement）** ライセンスで提供。**さくらのクラウド上で稼働するWindows Server OSのライセンスを利用者が別の環境で使うことはできない**。
  - ※ SPLAはライセンスを第三者（エンドユーザー）が利用可能にする仕組み（通常のボリュームライセンスでは第三者利用は不可）。

#### Oracle Database
- **ライセンスの都合上、さくらのクラウド上でOracle Databaseは使用できない**。**利用者によるライセンス持ち込みも不可**。
- 利用したい場合は **専用サーバPHY、またはハウジングに設置した物理サーバ**上で稼働させ、クラウドとブリッジ接続またはハイブリッド接続で連携する。

#### サポート範囲
- **無料OSのサポート範囲は初回のサーバ起動まで**。OSの設定は利用者の責任範囲。テクニカルサポートが必要なら他社の有償サポートを検討。
- **Windows Server OSのサポートは一般的な情報提供のみが基本**。SPLAでマイクロソフトが提供するのは製品使用権のみで、テクニカルサポートは別途有償。さくらインターネット経由でマイクロソフトのプロフェッショナルサポートも利用可能（手数料が必要・対応に時間・問題解決は保証なし）。

#### ネームサーバ・NTP
- さくらインターネット提供の名前解決用ネームサーバと時刻同期用NTPサーバの利用を検討（どちらも無料）。
- パブリックアーカイブから作成したサーバには、これらを利用する設定が標準で入っている。独自のDNS/NTPを使う場合は設定変更が必要。

## 14. 試験対策・要点チェック

- [ ] 通常プラン: 最小 **CPU1コア/メモリ1GB** 〜 最大 **CPU20コア/メモリ224GB**。プランは **仮想コア数×メモリ** の組み合わせ。
- [ ] コア専有プラン全体: 最小 **2コア/4GB** 〜 最大 **192コア/1024GB**。タイプは **Intel Xeon / AMD EPYC 7003 / AMD EPYC 9004** の3種。
- [ ] 高火力VRT: V100=**32GB×1/4コア/56GB**、H100=**SXM 80GB×1/24コア/240GB**。**石狩第1ゾーンのみ**。**時間額は24時間まで**（通常は10時間）。**Windows Server不可**・**GPUドライバは利用者が導入**。
- [ ] 専有ホスト: 標準/Windows=**20物理コア・200仮想コア・224GB**、専有ストレージ用=**96物理コア・960仮想コア・1024GB（東京第2ゾーンのみ）**。**Nested VM可**、**アプライアンス起動不可**、**@group無効**。
- [ ] NICは **最大10個**。追加NICは**グローバル接続不可・スイッチ接続必須**。NICドライバ既定は **VirtIO**。逆引きは**1つ目のNICのみ**、IPv4表示設定は**2つ目以降**。
- [ ] ディスクは **1サーバ最大3台**、ISOイメージは **1サーバ1つ**。
- [ ] 電源: シャットダウン/強制停止→起動は**ホスト変更あり**、強制リブート/OS reboot は**ホスト変更なし**。CLEANINGは電源操作不可。
- [ ] 特殊タグ: **@cpu-topology=1ソケット化（ライセンス対策）**、**@auto-reboot はサーバ内シャットダウンのみ対象**、**@group=A/B/C/Dでホスト分散**。
- [ ] スタートアップスクリプト: **SHELL=毎回実行 / YAML_CLOUD_CONFIG=初回のみ**。**@sacloud-once で1回のみ**。**無料・Linuxアーカイブで動作保証**。
- [ ] パブリックアーカイブ: **無料（有償OSはライセンス別）**。Windowsは **Datacenter / for RDS / for MS SQL**、ディスク **最小100GB〜最大2TB**、**SPLA提供で他環境での流用不可**。
- [ ] cloud-init対応アーカイブはアーカイブ名末尾が **cloudimg**。RHELのcloud-init対応は**石狩第3・東京第2ゾーン**でコア専有Xeon **2〜8コア**対応。
- [ ] **Oracle Databaseはクラウド上で利用不可（持ち込みも不可）** → 専用サーバPHY/ハウジングで連携。
- [ ] 機密コンピューティングは **機密VMプラン（AMD SEV）**、検証は**リモートアテステーション**。
- [ ] コア専有・高火力VRTは**シンプルモードで選択不可（通常モードで作成）**。
