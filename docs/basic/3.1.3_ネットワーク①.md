## 1. リージョンとゾーン

### 基本概念（重要表）

| 項目 | リージョン | ゾーン |
|------|-----------|--------|
| 定義 | データセンターがある**地理的な単位**。東京や石狩など都市ごとに割り当て | リージョン内にある**ネットワークの管理単位** |
| 位置づけ | ゾーンの地理的位置を把握するための概念 | リソースを配置できる単位。**操作対象はゾーン単位** |
| リソース配置 | **リージョン上にはリソースを配置できない** | リソースを配置できる |
| 構成関係 | リージョン配下に**必ず1つ以上のゾーン**が存在 | 各ゾーンは**物理的に独立**している |

### リージョンとゾーンの違い（詳細比較・重要表）

| 観点 | リージョン | ゾーン |
|------|-----------|--------|
| 拠点の単位 | 国内の地域（拠点の最小単位の上位） | 拠点の最小単位（データセンタ建屋内のフロア） |
| 地理 | 国内の地域 | 同一地域内や隣接する都道府県など |
| データセンター | リージョンごとに異なる | ゾーンごとに異なる場合もあるが同じ場合もある。同じ場合は**建屋やフロアが異なる** |
| 電源設備 | 共用しない | 同一建屋内に他ゾーンがある場合、**建屋の電源設備が単一障害点**となる |
| ネットワーク設備 | 他リージョンと**経路が多重化されたバックボーン回線**を介して接続 | クラウドより上位の**同一論理ネットワーク内**に複数ゾーンを収容 |
| ネットワーク遅延 | 数百km〜数千kmの地理的距離に応じた遅延が発生 | 同一論理ネットワーク内なのでリージョン間に比べ**低遅延** |
| DR観点の分散・冗長 | **有効** | 同一リージョン内の場合は**推奨しない** |

### ゾーン単位／ゾーン跨ぎの操作

- **同一ゾーン内のリソースに対してのみ可能な操作**（一例）:
  - サーバとディスクの接続
  - スイッチの接続
  - アーカイブからディスクの作成
  - 専有ホストでのサーバ起動
  - ISOイメージの接続
  - アーカイブの作成
- **ゾーンを跨いで接続できるリソース・サービス**（一例）:
  - ブリッジ接続
  - ハイブリッド接続
  - ハウジング
- ※上記はいずれも一例。詳細はクラウドマニュアルを参照。

### グローバルリソース

- リージョンやゾーンに**依存しない**機能・リソース。
- コントロールパネル上で**いずれのゾーンを選択しても表示・利用できる**。
- 例: **GSLB / ローカルルータ / エンハンスドロードバランサ / シンプル監視**（一例）。

### Sandboxゾーン

- コントロールパネルやAPIの操作を**テストする環境**。
- サービス用のゾーンとは**独立したゾーン**で、利用中の本番環境に影響を与えない。
- 作成したリソースに**課金が発生しない**。
- **リソース本来の機能は動作しない**（サーバへログインしての利用もできない）。

## 2. バックボーン

- 高い可用性と優れたトラフィック配信能力を持つ、さくらのクラウドのバックボーンネットワーク。
- **対外接続の総計は 1.8Tbps**。
- **各データセンター間は 10Gbps〜100Gbps で接続**。
- 国内の代表的なIX（インターネットエクスチェンジ）や多数の大手ISPと、**東京および大阪**で接続。
- ホストサーバと上流ネットワーク間は十分な通信帯域を備え、**論理速度10Gbps以上の回線**を使用。
- ネットワークが輻輳しないよう、さくらインターネットによって監視され、必要に応じて設備の増強が行われる。
- ネットワークマップ参照先: `https://www.sakura.ad.jp/services/datacenter/networkfacility/backbone_map.html`

## 3. スイッチとルータ＋スイッチ

### スイッチ（仮想ネットワークスイッチ）

- クラウド内部で**プライベートネットワーク**を作成。
- サーバ間を **L2接続** し、サーバ間を**ローカル通信**させる。
- **プランは存在しない**。料金は**時間額・日額・月額**が設定。

### ルータ＋スイッチ（インターネット接続専用の仮想ネットワークスイッチ）

- **グローバルネットワーク用**。ルーティング機能を持ち、広帯域。
- 構成要素: **ルータ**（インターネット回線の帯域・ルーティング機能・追加IPアドレス・オプション設定機能）＋**スイッチ**＋**グローバルIPアドレス**。

### スイッチとルータ＋スイッチの違い（最重要比較表）

| 観点 | スイッチ | ルータ＋スイッチ |
|------|---------|------------------|
| 仕様の違い | プライベートネットワークの**L2接続用** | スイッチに加えて**ルータ機能や複数のIPアドレス**が付属 |
| 役割の違い | LAN内で使用する**L2スイッチ** | インターネット回線とグローバルIPアドレスがバンドルされた**L3スイッチ** |
| 用途の違い | ローカルネットワーク用 | インターネット接続用 |
| オプション設定機能 | 特に設定項目なし | **スタティックルート機能**、割り当てIPアドレスブロックの**DNS逆引き設定**、**IPv6アドレスの割り当て**が可能 |

### ルータ＋スイッチのプラン・料金（重要表・数値正確保持）

| 要素 | 提供プラン | 料金 |
|------|-----------|------|
| ルータ | 帯域幅に応じたプラン。**最小100Mbps、最大10Gbps**（**10Gbpsは東京第2ゾーンのみ選択可能**） | **時間額・月額**（日額の設定なし）。広帯域ほど高価 |
| スイッチ | プラン提供なし | 時間額・日額・月額 |
| 追加IPアドレス | グローバルIPアドレスの**個数を選択**。**最小16個(/28)〜最大256個(/24)** | **月額**（時間額・日額の設定なし）。個数が多いほど高価 |

### サービスエンドポイントゲートウェイ（SEG）

- さくらのクラウドが提供する**マネージドサービスへクラウド内部ネットワーク経由で安全に接続**できる、**スイッチの拡張機能**。
- 接続先例: **オブジェクトストレージ、コンテナレジストリ等**（インターネット経由ではなくクラウド内部ネットワーク経由でアクセス）。
- ⚠️ **tips（重要制約）**:
  - SEGは**スイッチに対してのみ利用可能**で、**ルータ＋スイッチでは利用できない**。
  - 本機能を有効化した**スイッチに直接接続されているサーバのみ**が利用対象。
  - マネージドサービスへの通信は **100Mbps 共有回線（ベストエフォート）** を使用。
  - 利用者側で**独自のファイアウォール設定やルーティング制御は行えない**。

## 4. スイッチとルータ＋スイッチの利用

### 作成

- 作成画面で「ルータ＋スイッチ」を作るかを選択（**スイッチ＝いいえ／ルータ＋スイッチ＝はい**）。「はい」で追加項目（**追加IPアドレスの個数・ルータの帯域幅**）が表示される。
- スイッチ作成時: 設定項目は少ない。ルータ＋スイッチ作成時: **追加IPアドレスで割り当てられたIPアドレスブロック**と**ルータの帯域**が割り当てられる。

### ルータの利用

- インターネット回線は**共有帯域のベストエフォート型**で、**帯域は保証されない**。
- ルータの**プラン(帯域幅)は無停止で変更可能**。プラン変更しても**グローバルIPアドレスは変更されない**。
- **追加IPアドレスが /25 または /24 を利用中の場合は、利用者での変更は不可**。さくらインターネットに問い合わせて変更を依頼する。

### 追加IPアドレス（重要・数値正確保持）

- ⚠️ **tips**: コントロールパネルやAPI操作では **/25 または /24 のプリフィックスは選択できない**。これらを利用するには**さくらインターネットへの申し込み**が必要で、**申し込みは法人の利用者からのみ**受け付け。
- **自由に割り当て可能なIPアドレス数 ＝「追加IPアドレス数 − 5個」**。
  - 内訳: ネットワークアドレス1個、ブロードキャストアドレス1個、クラウド基盤がゲートウェイアドレスとして3個を使用。
- 割り当てられたIPアドレスブロックは**変更できない**。

### スタティックルート機能（ルータ＋スイッチ）

- 新たに割り当てたIPアドレスブロックの**ルーティング先を、ルータ＋スイッチに接続されたサーバ等に設定**できる。
- 図の流れ: ①ルータ＋スイッチ(1.1.1.0/28)上にLinuxルータを構築 → ②スタティックルート追加（ネクストホップに1.1.1.14を設定）→ ③新たに2.2.2.0/28を割り当て → ④通信可能。
- ⚠️ **tips**:
  - 1つのルータ＋スイッチに**20ブロックまで**追加可能。
  - スイッチ／ルータ＋スイッチを削除するには、全リソースの接続解除が必要。加えてスタティックルート利用時はその設定も削除が必要。
  - ルータ＋スイッチを削除すると、作成時に割り当てられた**追加IPアドレスも同時に削除**される。
  - 一度削除されたIPアドレスブロックと**同じブロックを再度割り当てることはできない**。

## 5. パケットフィルタ機能

### 概要

- サーバの**仮想NICに着信、もしくは仮想NICから発信するパケット**を、指定条件でフィルタリングする機能。
- **無料**で利用できる。
- 動作は**ステートレス**。

### フィルタリングの条件（プロトコル別・重要表）

| プロトコル | 指定可能な項目 |
|-----------|----------------|
| TCP | 送信元ネットワーク、送信元ポート、宛先ポート |
| UDP | 送信元ネットワーク、送信元ポート、宛先ポート |
| ICMP | 送信元ネットワーク |
| fragment | 送信元ネットワーク |
| IP | 送信元ネットワーク |

- ルール設定時、**空欄の項目は ANY（全てにマッチ）** として処理される。
- **アクション**は**許可（allow）／拒否（deny）**を指定。

### 設定の流れ

1. パケットフィルタの作成
2. 作成したパケットフィルタへのルール設定（ルールの三本線アイコンをドラッグして上下移動 → 適用順番を変更可能）
3. 設定済みパケットフィルタの**NICへの適用**

### ルールの評価（最重要）

- ルールは**上から順に評価**される。条件にマッチしたパケットには「アクション」で設定した動作が行われる。
- **いずれの条件にもマッチしなかったパケットは「許可」**となり、適用されたサーバのNICに着信する。
- 全てを拒否したい場合は、**「送信元ネットワーク」を空欄・アクション「拒否」のルールをリスト末尾に追加**する。
- ステートレスのため、ルールリスト末尾に全拒否を設定する場合は、**サーバ発の通信の戻りパケットを適切に許可する設定が必要**。
  - 例（インターネット上のWebサーバへアクセス）: 送信元 1.1.1.100:50001 → 宛先 2.2.2.100:80 に対し、戻り（送信元 2.2.2.100:80 → 宛先 1.1.1.100:50001）を許可する。

### ルール設定例（必要ポートのみ開放し、不要ポート宛て着信を全拒否）

| # | 説明 |
|---|------|
| 1 | 全ての送信元からの80番ポート(HTTP)への接続を許可 |
| 2 | SSHは **1.1.1.0/24** のネットワークからのみ接続を許可 |
| 3 | `ntp1.sakura.ad.jp`(**210.188.224.14**)からのレスポンスを許可 |
| 4 | サーバ発通信の戻りパケットを許可（**TCP 32768-61000ポート**） |
| 5 | サーバ発通信の戻りパケットを許可（**UDP 32768-61000ポート**） |
| 6 | 全てのICMPパケットの着信を許可 |
| 7 | 全てのfragmentパケットの着信を許可 |
| 8 | 上記ルールに適合しなかったパケットを全て拒否 |

- ⚠️ **tips**: 新規作成時は**既存フィルタからのコピー**、または**さくらインターネット提供のプリセットからのコピー**で作成できる。プリセット例: SSHのアクセス制限、特定IPアドレスからの接続拒否、不要ポートのフィルタ(Linux)等。

## 6. ローカルルータ

### 概要

- 複数のローカルネットワークを**閉域網で接続**するリソース。
- ローカルルータ同士を **L3で接続**する。**異なる会員IDやプロジェクトのローカルルータを接続できる**。
- クラウドだけでなく、**さくらのVPS、専用サーバPHYのスイッチにも接続できる**。
- **グローバルリソース**（どのゾーンを選択しても操作可能。ただし実際のリソースは単一のリージョンに配置される）。
- **帯域は 1Gbps ベストエフォート**。
- **プランは存在しない**。料金は**時間額・日額・月額**。

### 利用ステップ

1. ローカルルータを作成する
2. スイッチに接続する（接続タイプがスイッチの場合）
3. ピア設定をする（スイッチまたはハイブリッド接続につなぐための接続タイプを選択）

### 作成・接続時のポイント

- **ハイブリッド接続につなぐ場合は会員IDでのログインが必要**。
- 作成すると**リソースIDとシークレットキー**が発行され、これらは**ピア設定の際に使用する情報**。
- スイッチに接続するインターフェースのネットワーク設定で **IPアドレスを3つ設定**する。**仮想IPアドレスがサーバのゲートウェイのIPアドレス**となる。
- 専用サーバPHYやVPSのスイッチと接続する場合は**会員IDでのログインが必要**。

### ピア設定

- 作成したローカルルータと接続先ローカルルータの**両方で、それぞれに対するピア設定を追加**する。
- ピア設定には接続先ローカルルータの**リソースIDとシークレットキー**を設定する。
- ⚠️ **tips（ピア接続）**:
  - ピア接続が正常な場合、ステータスは **「UP」**。各ピア設定に対して有効／無効を指定できる。
  - 片方からピア設定を削除すると、もう片方のステータスは **「DOWN」** になる。削除時は**両方から削除**する。
  - 両方のローカルルータの**ネットワークアドレスおよびネットマスクが一致する場合、ピア設定がエラー**となる。

### その他のtips

- スイッチ接続時にグローバルIPアドレスを設定することも可能。ただし**インターネットへの到達性が自動的に設定されるものではない**。
- さくらのVPSと専用サーバPHY間をローカルルータで接続可能。**クラウドのサーバを使用しない構成でも、ピア設定の作業はクラウドのコントロールパネル上で行う**。

### スタティックルート機能（ローカルルータ）

- 指定したIPアドレスブロックのルーティング先を、**スイッチやハイブリッド接続とつながっているサーバ等**に設定できる。
- 図例: 192.168.0.0/24 のスタティックルートのネクストホップに 192.168.100.0/24 上のLinuxルータ(.100)を設定。

## 7. ロードバランサ

### 概要

- **L4ロードバランサ**。可用性と耐障害性の向上を目的とした**仮想アプライアンス**。
- **スイッチかルータ＋スイッチに接続する必要がある**。

### プラン・料金

- 処理性能に応じた**2種類のプラン**: **標準プラン／ハイスペックプラン**。
- 各プランで**冗長化の有無**を選択: **シングル構成／冗長構成**。
- プランと冗長化の有無に応じた**時間額・日額・月額**が設定。

### 通信フロー（DSR方式）

- ① クライアントはロードバランサで指定された **VIP（仮想IPアドレス）とポート番号**宛てに通信。
- ② ロードバランサは、実サーバとして登録されている**いずれか1台に通信を転送**。
- ③ 実サーバからのレスポンスは**直接クライアントに返る**（**DSR: Direct Server Return 方式**）。

### 基本仕様（最重要表・数値正確保持）

| 項目 | 仕様 |
|------|------|
| 構成 | **DSR方式** |
| 対応プロトコル | **TCPのみ** |
| 冗長化 | **VRRP**を用いた冗長化に対応。**二重化**での冗長 |
| 仮想IPアドレス(VIP)、ポート番号 | **最大20個まで** |
| 設定可能な実サーバ数 | ロードバランサ1台あたり**最大40台** |
| 振り分けアルゴリズム | **least connection** |
| セッション維持 | **セッション維持機能なし** |
| IPv6対応 | **非対応** |

### ヘルスチェック／ソーリーサーバ

- **ヘルスチェック**: 実サーバの状態を定期監視。異常検出された実サーバ（ステータス DOWN）は**新規リクエストの振り分け先から除外**される。
- **ソーリーサーバ**: 実サーバが**全てダウン状態の場合に誘導先**として使われるサーバ。エラーメッセージやHTMLページ表示等で、振り分け先がない場合でもユーザに情報提供できる。

## 8. ロードバランサの利用

### 作成

- 冗長化で「はい」を選択した場合は **IPv4アドレスを2つ**設定する。
- **ゲートウェイアドレスの設定が可能**。

### VIP・ポート番号の設定

- **VIPアドレス**: ロードバランサが受け持つ負荷分散用の仮想IPアドレス。
- **ポート番号**: 仮想IPアドレスで着信を受けるポート番号。
- **チェック間隔**: 実サーバのヘルスチェックを実行する間隔。
- **ソーリーサーバの設定が可能**。VIPとポート番号の組み合わせ**1つに対してソーリーサーバを1つ**指定できる。

### ヘルスチェックの設定（重要表・数値正確保持）

- 監視方法は **http / https / tcp / ping** のいずれかを選択。

| 項目 | 仕様 |
|------|------|
| ヘルスチェックの実行間隔 | **10秒以上**で変更可能（※VIP設定時に指定） |
| ヘルスチェックのタイムアウト | **1-30秒**の範囲で変更可能 |
| 失敗時にリトライするまでの時間間隔 | **5秒** |
| サーバダウン判定のチェックのリトライ回数 | **1-5回**の範囲で変更可能 |

- 設定値: ヘルスチェックに失敗した際、**5秒間隔で指定回数リトライ**し、全て失敗するとダウンとなる。

### 電源操作・ネットワーク・実サーバ

- 電源操作: 停止・再起動などサーバと同様の操作が可能（**cloud-init起動を除く**）。作成後は自動的に起動。**削除する場合は停止が必要**。
- ネットワーク利用:
  - ロードバランサのIPアドレス、VIP、ソーリーサーバのIPアドレスは**すべて同一ネットワークである必要がある**。
  - 作成後に**接続先スイッチの変更・切断、IPアドレス等のネットワーク設定の変更はできない**。
- 実サーバ:
  - 設定した実サーバに対して**有効／無効**を指定可能。無効にした実サーバは振り分け対象にならない。
  - コントロールパネルで実サーバとのコネクション数（**Establish状態のtcpコネクション数**）を確認できる。
  - ⚠️ **tips**: 実サーバが DOWN の時にヘルスチェック設定を変更すると UP に戻らない等、正常動作しない場合がある。この場合は**実サーバの有効/無効を切り替える**ことで改善する。

## 9. GSLB（Global Server Load Balancing）

### 概要

- **DNSベースの広域負荷分散**。可用性と耐障害性の向上が目的。
- **グローバルリソース**。複数のロケーションに跨るバランシング、**DR対策**に有効。
- **プランは存在しない**。料金は**時間額・日額・月額**。

### 基本仕様（重要表・数値正確保持）

| 項目 | 仕様 |
|------|------|
| 負荷分散の動作 | **DNSラウンドロビン相当** |
| 対応ネットワーク層プロトコル | **IPv4、IPv6** |
| 冗長化 | **標準で冗長構成** |
| 設定可能な実サーバ数 | GSLB1台あたり**最大12台** |
| DNS応答時のTTL | **10秒** |

### 利用ステップと生成FQDN

- ステップ: ① GSLBの作成 → ② 実サーバの登録。
- GSLBが生成するFQDN: **`site-XX.gslbXX.sakura.ne.jp`**（XXは任意の文字列）。
- GSLBとは別に利用者で用意するもの: **バランシング対象のFQDN** と **それを名前解決する権威DNS**（※これらが無くてもGSLBの利用自体は可能）。

### 通信フロー（DNSラウンドロビン方式）

1. クライアントが、バランシング対象FQDN（例: www.example.jp）のIPアドレスを権威DNSに問い合わせる → 権威DNSは**GSLBが生成するFQDNを返す**（CNAME）。
2. クライアントがGSLBが生成するFQDNのIPアドレスを問い合わせる → GSLBは**実サーバのIPアドレスを全て返す**。
3. 返ってきた実サーバIPアドレスの中から**1つが選択されてアクセス**される。
- ⚠️ **tips**: 利用者の権威DNSで、GSLBが生成するFQDNを **CNAMEレコード**として設定する。権威DNSは**さくらのクラウドのDNSアプライアンス**で簡単に用意できる。独自ドメインが必要な場合は**ドメイン取得代行サービス**の利用も検討。

## 10. GSLBの利用

### ヘルスチェック（重要表・数値正確保持）

- 監視で異常が検出された実サーバの**IPアドレスは応答されない**（例: 1.1.1.1=UP, 2.2.2.2=DOWN, 3.3.3.3=UP → 応答は 1.1.1.1, 3.3.3.3）。
- 監視方法は **http / https / tcp / ping** のいずれかを選択。

| 項目 | 仕様 |
|------|------|
| ヘルスチェックの実行間隔 | **10-60秒**の範囲で変更可能（※GSLB作成時に指定） |
| ヘルスチェックのタイムアウト | **10-60秒**の範囲で変更可能 |
| サーバダウン判定のチェックのリトライ回数 | **3回** |

- 設定値: ヘルスチェックに失敗した際、**3回連続タイムアウトでダウン判定**となる。
- ⚠️ **tips**: 実サーバが全てDOWNの場合は**全てのIPアドレスが応答**される。ただし**ソーリーサーバが設定されている場合はソーリーサーバのIPアドレスが応答**される。

### 重み付け応答（重要）

- 実サーバのIPアドレスごとに**応答確率を調整**する機能。重み付けを有効にし、実サーバごとに重み値を設定する。
  - 例: 重み値 1:3:6 → 各実サーバのIPアドレスを **1:3:6 の比率**で応答（10%/30%/60%）。**単一レコードの応答**となる。
- ⚠️ **tips**: 重み付け応答は**GSLB作成時にデフォルトで有効**。意図的に無効を選択しない限り、FQDNの問い合わせに対して**実サーバの単一レコードが応答**される。実サーバの重み値にはデフォルトの**1**が設定される。有効・無効による動作の違いを理解しておくこと。

### 実サーバの設定

- 実サーバには**グローバルIPアドレスを設定**する。**FQDNやプライベートIPアドレスは設定できない**。
- **IPv6アドレスを設定できる**。
- 実サーバの**有効／無効**を設定できる。**無効にした実サーバのIPアドレスは応答されない**。

### その他

- GSLBに**電源操作は無く、起動ステータスは存在しない**。有効状態が「利用可能」であれば利用できる。
- **ソーリーサーバの設定が可能**。重み付け応答の設定も可能。
- ⚠️ **tips**: GSLBでは**セッションが維持されない**ため、**同時接続数やセッション数などの上限は制限されていない**。

## 11. 試験対策・要点チェック

### リージョンとゾーン
- [ ] リージョン＝**地理的単位**（リソース配置不可）、ゾーン＝**ネットワーク管理単位**（リソース配置可・操作はゾーン単位）。
- [ ] リージョン配下に**必ず1つ以上のゾーン**、各ゾーンは**物理的に独立**。
- [ ] 同一建屋内に他ゾーンがある場合、**建屋の電源設備が単一障害点**。同一リージョン内のゾーン分散はDR目的では**推奨しない**。
- [ ] **同一ゾーン内のみ**: サーバ-ディスク接続、スイッチ接続、アーカイブからのディスク作成等。**ゾーン跨ぎ可**: ブリッジ接続・ハイブリッド接続。
- [ ] グローバルリソース例 = **GSLB / ローカルルータ / エンハンスドロードバランサ / シンプル監視**。
- [ ] Sandboxゾーンは**課金なし・機能は動作しない**テスト環境。

### バックボーン
- [ ] **対外接続総計 1.8Tbps**、**DC間 10〜100Gbps**、ホスト-上流間は**論理10Gbps以上**。東京・大阪でIX/ISP接続。

### スイッチ／ルータ＋スイッチ
- [ ] スイッチ＝**L2・ローカル・プランなし**、ルータ＋スイッチ＝**L3・インターネット接続・グローバルIPバンドル**。
- [ ] ルータ帯域 **最小100Mbps〜最大10Gbps**（**10Gbpsは東京第2ゾーンのみ**）。料金は**時間額・月額**（日額なし）。
- [ ] 追加IP **最小16個(/28)〜最大256個(/24)**、料金は**月額のみ**。**/25・/24は法人申し込み制**。
- [ ] **使用可能IP数 = 追加IP数 − 5**（NW1・ブロードキャスト1・GW3）。
- [ ] スタティックルートは**1ルータ＋スイッチに20ブロックまで**。削除されたブロックは**再割り当て不可**。
- [ ] **SEGはスイッチ専用**（ルータ＋スイッチ不可）、**直接接続サーバのみ**対象、**100Mbps共有ベストエフォート**。

### パケットフィルタ
- [ ] **無料・ステートレス**、NICの着信/発信に適用。空欄＝**ANY**、アクションは**allow/deny**。
- [ ] ルールは**上から順に評価**。**マッチしなければ「許可」**。全拒否は**送信元空欄・拒否を末尾**に。
- [ ] ステートレスのため**戻りパケット許可が必要**（例: 戻りは TCP/UDP 32768-61000）。

### ローカルルータ
- [ ] **閉域網でL3接続**、**異なる会員ID/プロジェクト間も接続可**、VPS・専用サーバPHYのスイッチにも接続可。
- [ ] **グローバルリソース**、**帯域 1Gbps ベストエフォート**、プランなし。
- [ ] ピア設定は**両方に必要**（リソースID＋シークレットキー）。正常=**UP**、片方削除で他方**DOWN**。**NWアドレス・ネットマスク一致でエラー**。

### ロードバランサ
- [ ] **L4 / DSR方式 / TCPのみ / IPv6非対応 / セッション維持なし / least connection**。
- [ ] **VIP最大20個**、**実サーバ最大40台**、冗長化は**VRRP（二重化）**。
- [ ] ヘルスチェック: 間隔**10秒以上**、タイムアウト**1-30秒**、リトライ**1-5回**、失敗時リトライ間隔**5秒**。監視は http/https/tcp/ping。
- [ ] IP/VIP/ソーリーサーバは**同一ネットワーク**。作成後のNW設定変更不可。削除は要停止。

### GSLB
- [ ] **DNSラウンドロビン相当 / IPv4・IPv6対応 / 標準で冗長 / 実サーバ最大12台 / TTL 10秒**。
- [ ] 生成FQDN = **`site-XX.gslbXX.sakura.ne.jp`**、権威DNSに**CNAME**で設定。
- [ ] ヘルスチェック: 間隔**10-60秒**、タイムアウト**10-60秒**、リトライ**3回**（3回連続タイムアウトでダウン）。
- [ ] **重み付け応答はデフォルト有効**（無効にしないと単一レコード応答、デフォルト重み値1）。
- [ ] 実サーバは**グローバルIP必須**（FQDN・プライベートIP不可、IPv6可）。**電源操作なし・セッション維持なし**。
- [ ] 全DOWN時は**全IP応答**、ソーリーサーバ設定時は**ソーリーサーバIP応答**。
