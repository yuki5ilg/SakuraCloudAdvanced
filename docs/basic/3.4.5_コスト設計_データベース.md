## 1. データベースとコストパフォーマンス（基本の考え方）

### 適切なスペック選択（プラン選定）
- 一般に、**システムの需要が高まるほどデータベースサーバの処理が増加し、ストレージへの読み書きの頻度も増加**する。
- 高負荷時にデータベースサーバの**パフォーマンス不足がシステム全体のボトルネック**にならないよう、適切なスペックを選択する。
  - 選択すべきスペックの要素 = **CPUコア / メモリ / ディスクのI/O性能**。
- データベースサーバのシステムリソースが不足すると、**トランザクション処理がタイムアウト・失敗**する原因となり、結果的に**データベースの不整合**が生じる可能性がある。
- クラウド上で運用する際は、コストパフォーマンス向上のために**プランを最適化**するとともに、**不具合発生時の影響を考慮して十分なリソースを確保**することを検討する。

### 運用形態の選択肢（導入コストと運用コストの両面で比較）
さくらのクラウド上でデータベースを運用するにあたり、**アプライアンスを選ぶか、利用者側でサーバを構築するか**を、**導入コストと運用コストの両方を比較検討**して決定する。

| 選択肢 | 概要 | コスト面の特徴 |
|--------|------|----------------|
| データベースアプライアンス | マネージドなデータベース機能 | OS・ミドルウェアのセットアップ不要でコスト削減 |
| 利用者側でサーバを構築 | サーバ上にDBを自前構築 | **サーバとディスクの料金**が発生。DBに加え**サーバOSも含めたセットアップと運用**が必要 |
| 物理基盤サービス連携 | さくらインターネットの物理基盤サービスで構築したDBサーバと、さくらのクラウド上のサーバを連携 | 物理基盤の高パフォーマンスとクラウドを併用 |
| 専有ホスト・専有ストレージ上でアプライアンス運用 | 高く安定したI/O性能を求める場合の選択肢 | **料金は高額**。運用コストとのバランスを考慮して検討する |

> ※ 利用者側でサーバを構築する場合は「サーバとディスクの料金」が発生し、OSも含めた運用責任を負う点が、アプライアンスとの本質的な違い。

## 2. データベースアプライアンスの利用（コスト考慮事項）

### コスト面のメリットと前提
- 利用者側で**OSやミドルウェアのセットアップ作業が不要**となり、コストを削減できる。
- **使用するデータベースエンジンや選択するゾーンに関わらず、利用料金に差は無い。**
- アプライアンスは**スイッチ、もしくはルータ＋スイッチへ接続する必要**があるため、その分のコストも考慮する。

### リードレプリカ・バックアップの料金
- **リードレプリカ**を利用する場合、**リードレプリカ一台ごとに、マスターとして指定したアプライアンスのプランと同等の料金**が発生する。
- アプライアンスの**バックアップ機能を利用しても追加料金は発生しない**。
  - ただし、**バックアップデータ保管領域としてNFSアプライアンスを利用する場合は、別途その料金が発生**する。
- データベースを利用しない時間帯には、**アプライアンスを停止して不要なコストを発生させない**ことを検討する。

### スケールアップ（プラン変更）時の注意
- アプライアンスをスケールアップする際には**プラン変更**を行う。
- プラン変更すると**アプライアンスが停止し、変更後のプランで新規に作成**される。
  - **変更前のアプライアンスは自動で削除されない**ため、不要な場合は**手動で削除**する必要がある。
- 停止と作成の処理に**相応の時間を要する**ため、停止時間を十分に確保できないシステムでは、**はじめから余裕を持たせたスペックとディスクサイズのプラン**で運用する。

## 3. サーバ上でのデータベース利用（利用者自身で構築）

### メリット：チューニングの自由度
- 利用者自身でデータベースサーバを構築・運用する場合、**パフォーマンスチューニングを柔軟に行える**。
- 一方、**アプライアンスを使用する場合は、クエリ最適化やパラメータ設定の調整において、利用者が自由に変更できる設定項目が限られる**。

### ネットワーク構成とコスト
- 利用者自身が構築するサーバの場合、**サーバのNICを追加し異なるスイッチに接続することで、複数のネットワークに所属させる**ことができる。
- 例：**サービス用ネットワークとは別に、管理用のネットワークを用意する**場合など。
- この際、**構成するネットワークの数に応じて、スイッチやルータ＋スイッチの利用料金が発生**することを考慮する。

### アプライアンス vs サーバ上でのデータベース運用（比較表）

| 観点 | データベースアプライアンス | サーバ上でのデータベース（自前構築） |
|------|----------------------------|--------------------------------------|
| OS・ミドルウェアのセットアップ | 不要（コスト削減） | **必要**（DBに加えサーバOSも） |
| 料金体系 | エンジン・ゾーンに関わらず差は無い | **サーバとディスクの料金**が発生 |
| チューニング自由度 | 変更できる設定項目が限られる | **柔軟に行える**（クエリ最適化・パラメータ設定） |
| リードレプリカ | 1台ごとにマスターと同等の料金 | （自前構成次第） |
| バックアップ | 機能利用は追加料金なし（NFS保管は別途料金） | （自前構成次第） |
| スケールアップ | プラン変更＝停止→新規作成、旧機は手動削除 | （サーバのプラン変更等） |
| ネットワーク接続 | スイッチ／ルータ＋スイッチへ接続が必要 | NIC追加で複数NW所属可（NW数に応じ料金） |

## 4. ハイブリッド構成におけるデータベースの利用

クラウドの柔軟性と物理サーバの高パフォーマンスの**両方のメリットを享受**するため、さくらのクラウドを物理基盤サービスと組み合わせる。

### 専用サーバPHYとの組み合わせ
- さくらのクラウドと**専用サーバPHY**を組み合わせる。
- 例：クラウドでWeb/Appサーバを構成し、**ブリッジ経由で接続した専用サーバPHY上にデータベースを構成**する。

### ハウジングとの組み合わせ
- さくらのクラウドと**ハウジング**を併用しても同様のメリットを得られる。
- 例：クラウドでWeb/Appサーバを構成し、**ハイブリッド接続経由で接続したハウジングラック内の物理サーバ上にデータベースを構成**する。

### 接続経路まとめ

| 物理基盤 | クラウドとの接続経路 | DB配置先 |
|----------|----------------------|----------|
| 専用サーバPHY | **ブリッジ経由** | 専用サーバPHY上 |
| ハウジング | **ハイブリッド接続経由** | ハウジングラック内の物理サーバ上 |

### 【Tips】専用サーバPHY と ハウジング の比較
ハイブリッド構成では、**専用サーバPHYを使用するか、ハウジングラックに利用者所有の物理サーバを持ち込むか**を検討する。

| 観点 | 専用サーバPHY | ハウジング（物理サーバ持ち込み） |
|------|---------------|----------------------------------|
| スペック選択 | **提供プランが決まっており、選択できるスペックは限定** | **利用者がサーバを選定可能**（要件に応じたスペックを利用可） |
| 物理スペース・電源・機材設置 | **さくらインターネット側の責任範囲**（利用者の作業範囲外） | スペース・電源供給に**費用が発生**、機材の設置も**利用者の作業範囲**となり相応のコストが発生 |

## 5. 試験対策・要点チェック

- [ ] プラン選定で見るべきスペック要素 = **CPUコア / メモリ / ディスクのI/O性能**。
- [ ] リソース不足は**トランザクションのタイムアウト・失敗→データベースの不整合**につながる。
- [ ] 運用形態は**導入コストと運用コストの両方**を比較して決める。自前サーバ構築は**サーバ＋ディスク料金**とOS運用が発生。
- [ ] アプライアンスは**OS・ミドルウェアのセットアップ不要**。**エンジン・ゾーンに関わらず利用料金は同じ**。
- [ ] アプライアンスは**スイッチ／ルータ＋スイッチへの接続が必要**（その分のコスト）。
- [ ] **リードレプリカ1台ごとにマスターと同等の料金**が発生。
- [ ] **バックアップ機能は追加料金なし**。ただし**NFSアプライアンスを保管領域に使うと別途料金**。
- [ ] アプライアンスの**プラン変更＝停止→変更後プランで新規作成**。**旧アプライアンスは自動削除されず手動削除**が必要。停止時間を取れないなら**最初から余裕あるプラン**で。
- [ ] 自前サーバはチューニングが柔軟／アプライアンスは**変更できる設定項目が限られる**。
- [ ] 自前サーバは**NIC追加で複数ネットワークに所属可**。NW数に応じてスイッチ／ルータ＋スイッチ料金が発生。
- [ ] ハイブリッド: **専用サーバPHY＝ブリッジ経由**、**ハウジング＝ハイブリッド接続経由**でDBを配置。
- [ ] 専用サーバPHYは**スペック限定だが設置・電源はさくら側責任**。ハウジングは**スペック自由だが設置・電源は利用者負担（費用発生）**。
- [ ] 高く安定したI/O性能には**専有ホスト・専有ストレージ上でのアプライアンス運用**もあるが**料金は高額**。
