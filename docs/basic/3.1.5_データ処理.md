## 1. アーカイブ

### アーカイブとは（ディスクイメージ）
- アーカイブは **ディスクイメージ**（ディスク全体を丸ごとコピーしたデータ）を扱うリソース。
- 用途は **ディスクのバックアップと復旧**、**ディスクの複製**。
- 直接サーバに接続して入出力を行わず、**データの保管**に用いる。

> 【Tips】ディスクイメージとは、ディスク全体を丸ごとコピーしたデータ。OS・アプリケーション・ユーザーデータなどディスク上の全情報を含む。ファイルとして保存されるため「イメージファイル」とも呼ばれ、フォーマット形式には **raw形式** や **qcow形式** などがある。

### アーカイブの種類（重要）

| 種類 | 説明 |
|------|------|
| パブリックアーカイブ | さくらインターネットから提供。**各種OSが初期インストールされた状態** |
| マイアーカイブ | **利用者がディスクをもとに作成する** |

### 提供プラン・料金（数値）
- アーカイブに **プランは存在しない**。
- 作成できるサイズに制限がある: **最小20GB ～ 最大1TB**。
- **アーカイブを取得可能なディスクのプランには制限がない**。
- サイズに応じた **時間額・日額・月額** が設定されている。

### マイアーカイブの利用
- マイアーカイブを使って **ディスクを作成できる**（ディスク作成時にソースとして指定）。
- ディスク修正機能が対応するOSであれば、**ネットワーク情報やパスワードを変更してディスクへ書き込み可能**。ただし、さくらインターネットでは **動作を保証していない**。

> 【Tips】アーカイブはディスクのプランとは無関係。**標準プランのディスクから作成したマイアーカイブで SSDプランのディスクを作成でき、その逆も可能**。

## 2. ディスクとアーカイブの比較（最重要表）

| 項目 | ディスク | アーカイブ |
|------|----------|------------|
| 用途 | サーバに接続するブロックストレージ | 直接サーバに接続して入出力を行わない／データの保管 |
| サーバへの接続 | 可能 | 不可 |
| 新規作成時にソースとして指定可能なもの | ・同一ゾーン内のディスク<br>・パブリックアーカイブ<br>・同一ゾーン内のマイアーカイブ | ・同一ゾーン内のディスク<br>・パブリックアーカイブ<br>・同一ゾーン内のマイアーカイブ<br>・**他ゾーンにあるマイアーカイブ**<br>・**同一会員IDが持つさくらのVPSのディスク** |
| 利用料金 | アーカイブよりも高価 | ディスクよりも安価 |
| FTPによるデータのアップロード/ダウンロード | 不可 | 可能 |
| 他ゾーン／さくらのVPSディスクからのコピー | 不可 | 可能 |

> ⚠️ 試験頻出: アーカイブは **他ゾーンのマイアーカイブ** や **同一会員IDのさくらVPSディスク** をソースにできる（ディスクは不可）。アーカイブは **ディスクより安価**・**サーバ接続不可**・**FTP可**。

## 3. アーカイブの利用（コントロールパネル操作）

### マイアーカイブの作成 — アーカイブソースの種類

| アーカイブソース | 説明 |
|------------------|------|
| ブランク | 空のアーカイブを作成。**アーカイブサイズの選択が必要**。手元のイメージを **FTPアップロード** する。コマンドが表示され、アップロード終了後に「FTPを完了」をクリック |
| ディスク | ディスクのイメージを作成。**作成開始時点でのイメージ** となる。**ディスクのサイズがアーカイブサイズとして設定**される。ディスクのプランによらず作成可能 |
| 共有アーカイブ | **会員IDやプロジェクトの制限なく**、他の利用者のアーカイブをコピーできる。**共有キー**（ランダムな文字列）が必要 |

> 【Tips】ブランクとして作成したアーカイブは「FTPを完了」することで利用可能になる。ブランク以外でも、**OSのバンドル情報が付与されていないイメージ（例: Linux系OS）** のアーカイブは「FTPを開始」でFTP接続を有効にし、イメージファイルのDL/ULが可能。**Windows Server のアーカイブはバンドル情報が付与されているため、FTP接続を有効にできない**。

> 【Tips】共有を停止するには対象のアーカイブで「FTPを完了」する（アーカイブ共有はクラウド内部でFTP機能を利用）。共有終了後に「FTPを完了」を忘れないこと。**バンドル情報が付与されたイメージのアーカイブも共有可能**。

### 共有アーカイブの流れ
1. 共有元: 共有キー（ランダムな文字列）が発行される。
2. 共有元: 共有キーの情報を他の利用者に提供。
3. 共有先: 共有キーを使ってアーカイブを作成できる。

### アーカイブの有効状態（重要表）
- 有効状態が **「利用可能」** になると利用を開始できる。
- **削除したアーカイブは復旧できない**。

| 有効状態 | 説明 |
|----------|------|
| 利用可能 | アーカイブをソースとしてディスクを作成できる状態 |
| コピー中 | ディスクやアーカイブをソースとしてアーカイブを作成している状態 |
| 転送中 | 他ゾーンのマイアーカイブやVPSディスクをコピーしてアーカイブを作成している状態 |
| アップロード | FTP接続やアーカイブ共有が有効な状態 |

## 4. 自動バックアップ機能

### 概要
- **定期的にアーカイブを作成する機能**。指定するディスクのアーカイブを自動的に作成する。
- 実行間隔は **週単位** で **曜日を指定**（曜日は **複数選択可能**）。**日付や時間は指定できない**。
- 指定された **世代数** のアーカイブが保持され、**古いものから自動的に削除**される。

### 仕様（数値・重要表）

| 項目 | 仕様 |
|------|------|
| 最小バックアップ期間 | **1日** |
| 最大世代管理数 | **10世代** |
| ソースディスクに指定可能なディスクの最大サイズ | **1TB** |

### 料金
- 自動バックアップが **1回動作するごと** に、ディスクサイズに応じた利用料金が発生する。
- 作成するアーカイブの料金は **別途発生**。
- 月額料金の概算:
  - 自動バックアップ利用料金 = **自動バックアップ実行単価 × 週単位での実行回数 × 1ヶ月の週数**
  - アーカイブ利用料金 = **アーカイブ日割単価 × 世代数 × (7日 × 1ヶ月の週数)**
  - 月額概算 = 上記2つの合計

### バックアップ実行
- コントロールパネルの **イベントログ** に実行ログが記録される。
- 作成されるアーカイブには **`autobackup-{自動バックアップのリソースID}`** タグが付与される。
- **アーカイブからこのタグを削除すると、世代管理の対象から除外され自動削除されなくなる**。

> 【Tips】自動バックアップは、指定した曜日の **24時間中にランダムに実行**される。実行開始のタイミングは指定できない。

## 5. ディスクマイグレーション

raw イメージ（利用者拠点／データセンター）や さくらのVPS のディスクを、さくらのクラウドへ移行する処理。

```
[利用者拠点] raw イメージ ─┐
                           ├─→ [さくらのクラウド] ─→ ディスク
[データセンター] raw イメージ ┘            ↑
                              [さくらのVPS] ディスク
```

### さくらのクラウドのディスク移行
- 既存のディスクをソースとして、新規にディスクを作成する。
- **マイアーカイブをソースとすることも可能**。

### 利用者の手元にあるディスクイメージの移行
- マイアーカイブに **rawイメージをアップロードできる**。
- 手元のディスクイメージを **rawイメージに変換** し、**ブランクのマイアーカイブにFTPでアップロード** する。
- 手順例はクラウドマニュアルに記載。ただし **さくらインターネットでは動作保証をしていない**。

### VPSディスクの移行
- 既存のVPSディスクをソースとして、新規にマイアーカイブを作成できる。
- ただし、以下のVPSプランは **非対応**:
  - **さくらのVPS for Windows Server**
  - **ストレージ容量が1TBを超過するプラン**
  - **追加ストレージ(NFS)**

> 【Tips】VPSディスクをソースとするマイアーカイブの作成は、ディスクサイズやサービス基盤の状況により **作成完了まで数時間かかる場合がある**。

### ライブマイグレーション（参考）
> 【Tips】機器の老朽化などでさくらインターネットがストレージ機器を入れ替える際、休止予定ストレージ内のディスクは別のストレージ機器に随時移行される。**利用者の操作を必要とせず自動的に行われ、動作中のサーバに影響を与えない**。これを **「ライブマイグレーション」** と呼ぶ。移行後も **ディスクのプランとサイズは変わらず**、リソースIDや課金状態もそのまま引き継がれる。なお、通常運用中にプランやサイズを変更する場合は、移行ではなく **ディスクをコピー** する必要がある。

### マイグレーションサービス（参考）
> 【Tips】さくらインターネットはクラウド移行を支援する「マイグレーションサービス」を提供。**無償の移行ツール**で VMware環境の仮想マシンをそのまま移行でき、**有償の移行支援サービス**では他社クラウドやオンプレミスからの移行を専門チームが支援する。

## 6. アーカイブ利用の検討（設計の考え方）

### 基本的な考え方
- アーカイブは **頻繁な変更を必要としないデータの保管** に利用する。
- 用途例: サーバ作成時のテンプレート、バックアップ用途。
- バックアップ用途で利用する場合の留意点:
  - **アーカイブからファイルを単体で復元することはできない**（ディスク単位での復元）。
  - アーカイブは **バックアップとしての完全性を保証するものではない**。
  - 頻繁にディスクI/Oが発生する **データベースなどのディスクを自動バックアップすることは非推奨**。

> 【Tips】一般にバックアップとアーカイブは目的が異なる。バックアップはデータ損失・破損時の **短期間での復元** が目的、アーカイブは **長期保存**（法令による保存期間、将来のデータ分析など）が目的。さくらのクラウドのアーカイブはバックアップ用途にも使えるが、**データを個別に取り出しての復元は不可**（ディスク単位）。

### サイズに関する注意（数値）
- **作成可能なアーカイブの最大サイズは 1TB**。
- ディスクには1TBより大きいサイズが存在するため、**ディスクサイズによってはアーカイブを取得できない**。
- 用途に応じて **パーティションごとにディスクを分ける** など、1TB以下の複数ディスクで運用できないか検討する。

### 作成タイミングに関する注意
- **アーカイブの作成処理が開始された時点のディスクイメージ** が保存される。
- ディスクの書き込み操作中に処理が開始されると、**不完全なデータを含むイメージ** が取得される場合がある。
- 随時書き込まれるlogデータは書き戻し時に差異が発生する可能性がある。完全なデータを取得するには **サーバを一旦停止** させるか、**サーバに未接続のディスクを対象** にすることを検討する。

### 所要時間に関する注意
- アーカイブ作成は **作業時間に余裕を持って計画** する。
- サーバメンテナンス前後のバックアップとして取得する場合、メンテナンス時間を十分に検討する。
- 作成時間は **ディスクサイズやクラウド基盤の状況によって変動** する。
- **早朝から午後の早めの時間帯** は自動バックアップ等と重なり、コピー処理が混み合うことがあるため、想定以上に時間がかかる可能性に留意。

### ゾーン間コピーに関する注意（重要）
- ディスクのソースとして **他ゾーンのディスクやアーカイブを指定できない**。
- アーカイブのソースとして **他ゾーンのディスクは指定できないが、他ゾーンのアーカイブは指定できる**。
- **アーカイブを使ってディスクを他ゾーンにコピーする手順**:
  1. ディスクのあるゾーンでアーカイブを作成する。
  2. コピー先ゾーンで、前述のアーカイブをソースとするマイアーカイブを作成する。
  3. コピー先ゾーンで、同一ゾーンのマイアーカイブをソースに指定してディスクを作成する。

### アーカイブ共有に関する注意
- 異なる会員IDやプロジェクト間で共有する場合は **アーカイブ共有機能** を利用する。
- 共有アーカイブ内に **アクセスキー・シークレットキー等の機密情報** がある場合、共有先に十分注意する。
- **アーカイブ転送中に「FTPを完了」すると、共有アーカイブをソースとする作成が正常に完了しない**。作成が完了し有効状態が「利用可能」になったことを確認の上で完了操作を行う。

### アーカイブからディスクを作成する際の注意
- ソースディスクの情報がそのまま引き継がれるため、**IPアドレスやホスト名などの一意な設定はディスク作成後に適切に変更** する。
- アーカイブから作成したディスクをサーバに接続すると **ディスクのUUIDが重複する可能性** がある。重複すると、本来のディスクから起動できない／異なるパーティションにマウントされる問題が生じることがある。
  - 対処: **OSのコマンドでコピー後のディスクのUUIDを変更** する。
  - または、ディスク作成時に **ディスク修正機能でパーティションのUUIDを変更** する選択肢もある。

## 7. 試験対策・要点チェック

- [ ] アーカイブの種類: **パブリックアーカイブ（OS初期インストール済み・さくら提供）** と **マイアーカイブ（利用者がディスクから作成）**。
- [ ] アーカイブに **プランは存在しない**。サイズは **最小20GB～最大1TB**。
- [ ] アーカイブはディスクのプランと無関係（標準⇔SSD 相互に作成可能）。
- [ ] アーカイブは **サーバ接続不可**・**ディスクより安価**・**FTP可**。ソースに **他ゾーンのマイアーカイブ／同一会員IDのVPSディスク** を指定できる。
- [ ] アーカイブソース3種: **ブランク**（サイズ選択・FTPアップロード）/ **ディスク**（ディスクサイズがアーカイブサイズに）/ **共有アーカイブ**（共有キーが必要）。
- [ ] **Windows Server のアーカイブはバンドル情報のためFTP接続不可**。
- [ ] 有効状態: 利用可能／コピー中／転送中／アップロード。**削除したアーカイブは復旧不可**。
- [ ] 自動バックアップ: **週単位で曜日指定（複数可）、日付・時間は不可**。実行は **指定曜日の24時間中ランダム**。
- [ ] 自動バックアップ仕様: **最小1日 / 最大10世代 / ソースディスク最大1TB**。
- [ ] 自動バックアップのアーカイブには **`autobackup-{リソースID}`** タグ。タグ削除で世代管理対象外（自動削除されない）。
- [ ] **DBなど頻繁にI/Oするディスクの自動バックアップは非推奨**。
- [ ] ディスクマイグレーション: 手元の **rawイメージをブランクのマイアーカイブにFTPアップロード**（動作保証なし）。
- [ ] VPSディスク移行の非対応: **for Windows Server / 1TB超過 / 追加ストレージ(NFS)**。
- [ ] **ライブマイグレーション** はさくらが自動実行、サーバ無影響、プラン・サイズ・リソースID・課金状態を引き継ぐ。
- [ ] アーカイブは **ファイル単体復元不可**（ディスク単位）、完全性は非保証。最大 **1TB**。
- [ ] 他ゾーンへのディスクコピーは **アーカイブ経由の3ステップ**（作成→コピー先でマイアーカイブ→同一ゾーンソースでディスク）。
- [ ] アーカイブから作成したディスクは **UUID重複に注意**（OSコマンド or ディスク修正機能で変更）。
