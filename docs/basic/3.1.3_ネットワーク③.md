# 3.1.3 ネットワーク③（ハイブリッド接続・サービス間接続・DNS・シンプル監視・構成検討）

> 出典: SCB3.1.3_Network3（さくらのクラウド検定ベーシック教材, CC BY-SA 4.0 / さくらインターネット）
> 学習目標: ゾーン/サービスをまたぐ接続（ブリッジ・ハイブリッド接続・閉域接続）、運用補助サービス（DNSアプライアンス・シンプル監視）、およびネットワーク構成設計の考え方を理解する
> キーワード: ハイブリッド接続 / 接続マップ表示 / サービス間接続（AWS・SINET・LGWAN・プライベートリンク・ダイレクトアクセス・外部回線接続・OCX）/ DNSアプライアンス / シンプル監視 / VPNルータ・ローカルルータ / 負荷分散（ロードバランサ・GSLB・エンハンスドロードバランサ）

> ⚠️ 本ノートは「3.1.3 ネットワーク」**全3部構成の第3部**にあたる。第1部・第2部（スイッチ、ルータ＋スイッチ、共有セグメント、各アプライアンスの基礎等）に続き、本第3部ではゾーン/サービス間接続から負荷分散構成設計までを扱う。

## 1. ハイブリッド接続

### 概要・用途
- ゾーン間接続サービス（ハウジングサービス等を含む）。さくらインターネットの**周辺サービスと接続**したり、**複数ロケーションを利用するDR対策**に使う。
- 接続できる相手（同一プロジェクト内）:
  - さくらのクラウド / 専用サーバPHY・高火力PHY / さくらのVPS / ハウジング
  - プライベートリンク / ダイレクトアクセス / SINET接続サービス

### 提供プラン・申し込み
- **プランは存在しない**。
- 利用開始には**申し込みが必要**。コントロールパネル上の**「ハイブリッド接続申し込みフォーム」**から申し込む。
- 申し込みはコントロールパネルのホーム画面で操作。**会員IDでのログインが必要**。
- ハイブリッド接続するサービスの追加や、**既存のブリッジ接続をハイブリッド接続に変更**することも可能。
- 接続先のサービス・ゾーンは**2つ以上選択する**。選択すると対象プロジェクトに存在するスイッチを選択する画面が表示される。
- ⚠️ ハイブリッド接続は**利用者がコントロールパネルからリソースを作成するタイプのサービスではない**。
  - ブリッジ接続: 利用者が自らスイッチ接続の操作を行う。
  - ハイブリッド接続: 利用者は申し込み時にスイッチを**指定**し、**接続作業はさくらインターネットが行う**。

### 料金（2項目）
| 料金項目 | 内容 |
|----------|------|
| 基本料金 | 初期費用と月額料金。**月額料金は通信量に関わらず固定額** |
| 物理回線接続費用 | **ハウジングサービスに接続する場合にのみ発生**。定められた**回線帯域に応じた料金** |

### 接続の制約（重要）
- 1つのハイブリッド接続は**1ゾーンにつき1つのスイッチ**を接続する。
- **同一ゾーンにある複数のスイッチを接続することはできない**。
- **同一プロジェクト内のスイッチにのみ**接続できる。
- 1つのスイッチを**複数のハイブリッド接続に接続することはできない**。
- 解約: **書面の提出が必要**。コントロールパネルや会員メニューから**オンライン解約はできない**。

### ブリッジ接続からの変更
- ブリッジ接続はハイブリッド接続に変更できる。
- 申し込み時に**ブリッジのリソースID**を指定する。
- **ダウンタイムなく**ハイブリッド接続に切り替わる。
- 変更前のブリッジは**自動的に削除される**。

### ハウジングとの接続
- ハイブリッド接続の回線を**ルータ機器で収容し、ネットワークを分割する必要がある**（図: さくらのクラウド 172.16.0.0/24 ⇔ ルータで分割 ⇔ ハウジング 192.168.0.0/24）。
- 契約にあたり、**ネットワーク構成図や想定トラフィック量**などの情報をさくらインターネットに提示する。
- 接続の冗長化は**3方式**から選択:
  - マルチシャーシLAG (Static)
  - マルチシャーシLAG (LACP)
  - Active-Standby
- ⚠️ ネットワーク分割が必須の理由: 共有回線のため帯域幅は**ベストエフォート**。利用者NW内でループにより大量の輻輳が発生するとハイブリッド接続全体の品質に影響するため、品質担保目的でネットワーク分割が**必須**。
- ⚠️ ループ検出パケットが定期的にさくらインターネットから送信される。**ループ検出時には収容機器が自動的にポートをダウン**させる。**ポート復旧には利用者からさくらインターネットへの問い合わせが必要**。

## 2. 接続マップ表示

- ゾーン内の**サーバ・アプライアンス・スイッチの接続状況**をグラフィカルなマップとして表示する機能。
- マップには**選択しているゾーン**のリソースが表示される。リソース名・リソースID・IPアドレスなどが表示される。
- ⚠️ **他ゾーンのリソースやグローバルリソースは表示されない**。

### マップの凡例
| 分類 | 表示 | 意味 |
|------|------|------|
| ネットワークリソース | 赤色 | 共有セグメント |
| ネットワークリソース | 緑色 | ルータ＋スイッチ |
| ネットワークリソース | 青色 | スイッチ |
| サーバ／アプライアンス | 四角い箱 | クラウドリソース |
| サーバ／アプライアンス | 黒い丸印 | NIC／インターフェース |
| 接続線 | 黒い線 | スイッチ接続 |

### 操作
- マウス操作で画面上のリソース表示位置を移動できる。
- サーバ操作やネットワーク接続の設定をグラフィカルに行える。
- **電源操作やコンソール接続**など、マップ上のボタンからリソースの操作が可能。
- マップを**画像ファイルとしてダウンロード**できる。
- NICアイコンメニューより、**黒い丸印に表示する情報を変更**できる。
- ⚠️ サーバのローカルネットワーク側NICの黒い丸印にIPアドレスを表示するには、サーバ詳細画面のNICタブで**表示用IPアドレスを設定する必要がある**。**OSに設定したIPアドレスがそのまま表示されるわけではない**。

## 3. サービス間接続（外部接続・閉域接続）

さくらのクラウドで利用者が構築した環境と、以下を**閉域網で接続**できる。
- 他社クラウドサービス（AWS、Microsoft Azure、Google Cloud 等）
- SINET
- LGWAN
- 利用者のオンプレミス環境

### 接続先とサービスの対応（最重要表）
| 接続先 | 対象サービス名 |
|--------|----------------|
| 他社のクラウドサービス | AWS接続オプション / プライベートリンク for アルテリア / プライベートリンク for BBIX、OCX by BBIX / プライベートリンク for NTTドコモビジネス |
| SINET | SINET接続サービス |
| LGWAN | LGWANコネクト |
| 利用者のオンプレミス環境 | プライベートリンク（for アルテリア / for BBIX、OCX by BBIX / for NTTドコモビジネス）/ ダイレクトアクセス |

### AWS接続オプション
- **AWS Direct Connect** を利用してAWSと閉域接続。
- **Equinix TY2** のDirect Connectロケーションとの**既設配線**を使うため、短いリードタイムで利用開始可能。
- オプション申し込みでさくらのクラウドにAWS接続用リソースが用意され、**Direct Connect Gateway** または **Virtual Private Gateway** に接続する。
- 利用者は別途**ローカルルータ**を用意し、AWS接続用リソースと**ピア接続**。このローカルルータを経由してAWSと通信する。
- 料金: **月額費用＋転送量課金（さくらのクラウド⇒AWS）**。別途AWSの利用料金も発生。

### SINET接続サービス
- 学術ネットワーク**SINET**との閉域接続。
- SINETとの**既設配線**を使うため短いリードタイムで開始可能。
- **別途ハイブリッド接続の契約が必要**。
- 各大学/研究所とSINET間の接続は**利用者の対応範囲**。

### LGWANコネクト
- 総合行政ネットワーク**LGWAN**との閉域接続。
- さくらのクラウドを基盤として、**LGWAN向けにアプリケーション（LGWAN-ASP）を提供する事業者向け**。
- ⚠️ LGWANとの接続は**石狩リージョンのみ可能**。

### プライベートリンク（利用者の閉域網との接続）
共通: いずれも**既設配線を使い短いリードタイム**で開始可能。**別途ハイブリッド接続の契約が必要**。

| サービス | 内容 |
|----------|------|
| プライベートリンク（基本） | Equinix TY4・KDDI大手町データセンターのさくら内ラックにある**L3ゲートウェイ**と利用者機器を**構内接続**。当該DCに利用者ラックがあり閉域網を収容していることが前提。構内配線は利用者の対応範囲 |
| プライベートリンク for アルテリア | アルテリア・ネットワークスの「**VECTANTセキュアクラウドアクセス**」を利用者が契約し、さくらのL3ゲートウェイに接続して閉域網を引き込む |
| プライベートリンク for BBIX / OCX by BBIX | BBIXの「**Open Connectivity eXchange (OCX)**」をさくらインターネット経由で利用者が契約し、さくらのL3ゲートウェイに接続して閉域網を引き込む |
| プライベートリンク for NTTドコモビジネス | さくらインターネットとNTTドコモビジネス社の **Flexible InterConnect** を閉域接続。**共有回線を帯域確保型で利用**できる |

### ダイレクトアクセス
- 利用者の閉域網に接続する**ONUをさくらインターネットが預かり、専用ラックへ設置代行**する。
- 利用者が**ラックを契約する必要がない**。
- **別途ハイブリッド接続の契約が必要**。ハイブリッド接続とネットワークを分割するため、**さくらインターネットからルータをレンタル可能**。

### 外部回線接続サービス（インターネットVPN）
- さくらのクラウドと**インターネットVPN**で接続するためのサービス。
- さくらのクラウドや専用サーバPHYを使った利用者環境と利用者の拠点をインターネットVPNで接続。
- さくらのデータセンター内に設置の**VPN接続用ルータ機器が利用者に貸与**される。利用者はリモートでルータを設定し、拠点ルータとのVPN接続を確立する。
- ⚠️ 外部回線接続サービスでさくらのクラウドと接続する場合、**石狩リージョンのリソースのみが対象**。

## 4. DNSアプライアンス

### 概要・用途
- **権威DNSサーバ**。所有するドメインの名前解決、DNSサーバの運用コスト削減に使う。
- 権威DNS = 管理するドメイン情報を保持し、外部DNSサーバからの問い合わせに応答するサーバ（対してキャッシュDNSは問い合わせ結果をキャッシュ保持）。

### 提供プラン・料金
- **プランは存在しない**。
- **1ゾーンあたりに日額・月額**が設定。管理するゾーン数に応じて料金が加算される。
- **時間額は設定されていない**。**クエリ数やトラフィック量に応じた従量課金はない**。

### 基本仕様（重要）
- **権威DNS**として利用する。**キャッシュDNSとしては利用できない**。
- **プライマリDNS**として利用する。任意のDNSサーバの**セカンダリDNSとしての利用はできない**。
- **ゾーン転送には非対応**。
- **標準で冗長化**されている。ゾーン内に加え、**地理的にも冗長化**されている。
- **プライベートホストゾーン**（プライベートネットワーク専用のDNSゾーン）を作成できる。外部から応答せず、内部リソースの名前解決を安全に行える。

### ドメインの準備と権限委譲
- DNSアプライアンスで管理するドメインを用意する必要がある（利用者所有ドメインの持ち込み、または**さくらのドメイン取得代行サービス**で新規取得）。
- アプライアンスで管理するドメインの**権限委譲が必要**。アプライアンス詳細画面に表示されるDNSサーバに対して権限委譲する。
  - 例: `sub.example.co.jp` を管理する場合、`example.co.jp` のネームサーバで `sub` に対する**NSレコード**として `xxx.sakura.ne.jp.`（アプライアンス詳細画面表示のDNSサーバ）を設定する。
- ⚠️ **日本語ドメイン名（IDN）に対応**。「xn--」から始まるゾーン名を登録すると **Punycode** により変換処理される。例: 「例.com」→「xn--fsq.com」。

### レコード
- ゾーンに複数レコードを登録可能。登録時に**TTL**を指定。
- 登録可能な一般的レコードタイプ: **A、AAAA、NS、CNAME、MX、TXT、PTR など**（詳細はマニュアル参照）。
- ⚠️ **SOAレコードの編集**や **SPFレコードの登録**は**できない**。
- ⚠️ **ALIASレコード**の登録が可能。特定ドメインに別ドメインを別名として関連付ける。CNAMEと似るが、CNAMEは**ゾーンの頂点（Zone Apex）に別名を登録できない**制限がある。Zone Apexへ別名を登録する場合はALIASを使う。
  - 例: `example.jp` → ALIASレコード、`www.example.jp` → CNAMEレコード。

## 5. シンプル監視

### 概要・用途
- **グローバルネットワークからのネットワーク監視と通知**を行う監視サービス。監視サーバの運用コスト削減。
- 監視観点: 稼働状況（ping応答）/ パフォーマンス・接続性（TCPポート）/ 正常性（アプリケーション応答）/ セキュリティ（状態）。
- 監視対象例: 共有セグメント、ルータ＋スイッチ、さくらインターネットが提供するサービス、外部のクラウドサーバ、外部のサーバ。

### 提供プラン・料金
- **プランは存在しない**。
- 料金は監視対象によって異なる:
  - 一部のサービスに限り、さくらインターネットが提供する**グローバルIPアドレスを対象とする監視は無料**（**さくらのクラウド・専用サーバPHY・さくらのVPS**）。
  - 上記以外は**有料**。1つの監視設定あたりに**日額・月額**が設定。
  - **監視設定数（監視対象数 × 監視方法）**に応じて料金が加算される。
  - **時間額は設定されていない**。

### 監視対象
- IPアドレスは **IPv4のグローバルIPアドレス**を設定する。
- ⚠️ **プライベートIPアドレスは設定できない**。**IPv6非対応**。
- **SSL証明書有効期限アラート機能**: HTTPSサービスを提供する任意のFQDNに対しSSL証明書の有効期限を監視し、設定した残り日数を下回ると通知。監視対象に「SSL証明書有効期限」を選択する。

### 監視方法（プロトコル・一部抜粋）
| プロトコル | 監視方法 |
|------------|----------|
| ping | 指定送信先にpingを送信しネットワーク疎通を確認 |
| tcp | 指定監視先のポートへのTCP接続性を確認 |
| http(s) | 指定監視先/ポートの指定パスにhttp(s)接続し、レスポンスコードが期待通りか検査 |
| ssh | 指定監視先/ポートにTCP接続し、SSHサーバからのレスポンスを確認 |
| snmp | 指定監視先の**161番ポートにUDP接続**し、指定コミュニティ名とOIDで問い合わせた応答が期待通りか検査 |

### 監視設定値（標準値と範囲・重要）
| 項目 | 標準値 | 仕様・範囲 |
|------|--------|------------|
| チェック間隔 | 1分 | 監視の実行間隔。**1～60分** |
| 再試行回数 | 3回 | ダウン判定後に通知するまでの監視回数。指定回数を**連続して失敗するとダウン検知**。**1～10回** |
| 再試行間隔 | 10秒 | 監視失敗時の再実行間隔。**10～3600秒** |
| 監視タイムアウト | 10秒 | 監視のタイムアウト。**ping以外を指定した場合に設定が必要**。**1～30秒** |

- ⚠️ **SSL証明書有効期限アラート**は、**チェック間隔10分・再試行間隔30秒・再試行回数5回**に固定され、**これらの値は変更できない**。

### ステータスと通知
- ステータス: **監視中 / 一時停止 / ダウン検知**。各監視設定の**有効/無効**を設定できる。
- ダウン検知（例: 監視方法=ping、再試行回数=3 の場合、1～3回目連続失敗で障害発生＝ダウン検知）と復旧時に通知できる。
- 通知先は**メールとWebhook**。いずれか一方または**両方**を指定可能。
- **再通知間隔**: **1時間～72時間**を1時間単位で指定可能。**デフォルトは2時間**。
- メール通知先:
  - **緊急連絡用メールアドレスの登録がある場合**は登録済みの**すべての宛先**に通知。
  - 登録がない場合は**会員IDに登録のメールアドレス**宛に通知。
- Webhook通知先: **Slack・Discord・Microsoft Teams の Incoming Webhooks** などを指定可能。各サービスでWebhook URLを作成しシンプル監視に設定する。
- ⚠️ 詳細画面の「ログ」タブで監視・通知ログを確認可能。監視失敗/回復時に **SERVICE ALERT**、ダウン検知/復旧通知時に **SERVICE NOTIFICATION** が出力される。

## 6. ネットワーク構成の検討

### リージョンとゾーンの検討
- 利用者/管理者がクラウド上リソースにアクセスする**通信経路を確保**する必要がある（インターネット経由、閉域網による拠点間接続、サービス間接続など）。オンプレや他社クラウドとの連携構成も可能。
- 各接続には**帯域幅・セキュリティ・コストパフォーマンス**のトレードオフがあり、利用目的に応じて最適な方式を検討する。**機密性の高いデータやリアルタイム性**が求められる場合は閉域網による信頼性の高い接続を検討する。
- まず**シングルリージョン・シングルゾーン**の単純構成から検討し、可用性・コストパフォーマンスを考慮してマルチリージョン・マルチゾーンを活用する。
- ⚠️ **異なるゾーンにまたがるリソースに対して行える操作は制限される**。ゾーン分散で可用性は高まるが通信のオーバーヘッドが増加する。管理コストの最小化も重要。
- 一部のリソースやプランは提供リージョン/ゾーンが限られる。サービスサイト・マニュアルで確認する。

### グローバルネットワークの構成検討
- サーバをグローバルネットワークに**接続せずローカルネットワークのみ**に接続することも可能。
- インターネット経由でサーバにアクセスする場合はグローバルネットワーク接続を基本とする。一方、クラウドサーバ間の相互通信や一部周辺サービスとの通信は**ローカルネットワーク経由**を検討。オブジェクトストレージなど**グローバルNW上に公開されているサービス**がある点に留意。
- グローバルネットワークへのサーバ接続の3選択肢:
  1. サーバを**共有セグメント**に接続（VPNルータはスタンダード）
  2. サーバを**ルータ＋スイッチ**に接続（VPNルータはプレミアム/ハイスペック）
  3. サーバをスイッチに接続し**クラウド内部のプライベートネットワーク**に所属させる（※VPNルータの代わりにセキュリティアプライアンスを配置する構成もある）
- ルータ＋スイッチの用途: グローバルNWを専用セグメントとして分離しセキュリティ向上 / インターネット回線の集約・増強 / 回線帯域変更でコスト最適化 / グローバルIPアドレスのプール確保。
- ⚠️ 共有セグメントで**プロミスキャスモード**を使うと他利用者宛パケットを受信する可能性があるため、ルータ＋スイッチによる専用セグメント構成を検討。サーバ作成後に共有セグメント→ルータ＋スイッチへ切り替えるのは**非推奨**（グローバルIP変更が必要なため）。

### ローカルネットワークの構成検討
- インターネットから直接接続できないローカルNWは**スイッチ**を利用。**1スイッチに1つのCIDR範囲**を割り当てる。
- ⚠️ **1サーバは最大10個のネットワークに接続可能**。
- スイッチにVPNルータを接続しクラウド内部のプライベートネットワークを運用する。用途: 内部サーバからインターネット通信 / インターネットから内部サーバへの特定通信に制限した通信 / インターネットVPN経由の通信。
- **サービスエンドポイントゲートウェイ（SEG）**: グローバルNW公開サービス（オブジェクトストレージ等）との通信をクラウド内部NW経由で行いセキュリティ向上。通信元サーバの**DNS参照先をSEGのプライベートIPアドレス**に指定する。

#### ローカルルータ・ブリッジ接続・ハイブリッド接続の使い分け（重要）
| 用途 | 利用するもの |
|------|--------------|
| **異なる会員ID・異なるプロジェクト**の環境を**L3接続** | ローカルルータ |
| **同じプロジェクト内で異なるゾーン**の環境を**L2接続** | ブリッジ接続 |
| **同じプロジェクト内でさくらの複数サービスのNW間**を**L2接続** | ハイブリッド接続 |

- **スタティックルート**: VPNルータ・ローカルルータに設定し規模の大きなNW構成を実現。直接接続されていないNWへ各ルータ経由で通信する場合に設定（例: プリフィックス 172.16.0.0/24・ネクストホップ 192.168.0.100）。配下サーバにも適切なルーティング設定。
- **VRID重複に注意**: 同一NW上にVRRP有効アプライアンス（VPNルータ・ロードバランサ）、ローカルルータ、VRRP動作の仮想サーバが複数存在する場合は**一意なVRIDを設定**。重複するとVRRP切替が正常に行われない。
  - ⚠️ VPNルータ・ローカルルータのVRIDは**作成後変更可能**。**ロードバランサのVRIDは作成後変更不可**。
- ⚠️ VRRP（Virtual Router Redundancy Protocol）はVPNルータのプレミアム/ハイスペック、ロードバランサ冗長構成プラン、ローカルルータで使用。VRIDでグループを識別、マスターがVIPでトラフィック処理、障害時にバックアップから新マスターを自動選出しVIPを引き継ぐ。

### VPNルータの検討
- ネットワーク構成・性能目安・機能・冗長化有無を考慮してプラン選択。
- **スタンダードは共有セグメント**、**プレミアム/ハイスペックはルータ＋スイッチ**に接続する。
- 性能目安はマニュアル参照（目安超のパケット到達で遅延の可能性）。プランごとに**VPN接続可能なクライアント数・拠点数の上限が異なる**。
- **スタティックNATとIPエイリアス**を使う場合、また**冗長構成**で運用する場合は**プレミアム/ハイスペック**を選択。
- ⚠️ クラウド内部プライベートネットワークで使用可能な**サブネットマスク範囲は /16～/29**。

### ローカルルータの検討
- 用途: 複数の会員ID/プロジェクトの環境を相互通信（プロジェクト分離時など）/ 複数会員ID・プロジェクトのデータを1つに集約（運用監視・ログ集約など）。
- ⚠️ **L2フラットネットワークのスケーラビリティ問題**（ブロードキャストドメイン拡大による帯域消費・性能低下）解消にも利用。サーバ100台規模では同一スイッチ接続ではなく**ローカルルータでセグメント分離**する。
- ⚠️ **AWS接続オプションやLGWANコネクトの利用時はローカルルータの利用が必須**。
- ピア接続は**スター型**と**フルメッシュ型**から選択。3台以上のローカルルータで相互通信するには**フルメッシュ型**で構成し全ルータ間で経路情報を交換する。

### ブリッジ接続とハイブリッド接続の検討
- **ブリッジ接続**の用途: システムをゾーン間で冗長化 / クラウドとさくらの周辺サービスを併用 / 拡張性の高いクラウドと処理性能の高い専用サーバを接続（例: 東京第2の専用サーバPHY ⇔ 石狩第2のクラウドサーバ）。
- **ハイブリッド接続**の用途: ブリッジ接続の用途に加え、**ハウジングサービスとの接続やサービス間接続**で利用。回線はルータ機器で収容しネットワーク分割が必要。冗長化方式を検討。
- ⚠️ ブリッジ接続・ハイブリッド接続ともに、**同一ゾーン内で接続可能なスイッチは1つのみ**（同一ゾーン内の複数スイッチには接続不可）。**異なるゾーン間や異なるサービス間を接続**するために使う。同一ゾーン内の接続にはスイッチやVPNルータ等を使う。

#### ハイブリッド接続とローカルルータの応用構成
- ⚠️ ハイブリッド接続はローカルルータに接続可能。新規申し込み時に接続先としてローカルルータを選択。**ハイブリッド接続1契約あたり接続可能なローカルルータは1台**。
- ⚠️ **ローカルルータはスイッチとハイブリッド接続のどちらか片方にのみ接続可能**で、両方には接続できない。
- ⚠️ **スイッチはブリッジ接続・ハイブリッド接続・ローカルルータのいずれか1つにのみ接続可能**。ハイブリッド接続とローカルルータの両方には接続できない。
- 応用例: ①複数に分離した環境とハウジングを接続（各プロジェクトのローカルルータを集約しハイブリッド接続とつなぐ）。②AWS接続オプションとハウジングを併用。

### 負荷分散構成の検討

#### 3サービスの比較（最重要表）
| 項目 | ロードバランサ | GSLB | エンハンスドロードバランサ |
|------|----------------|------|----------------------------|
| 構成 | **DSR方式** | **DNSラウンドロビン相当** | **プロキシ方式** |
| 設置場所 | 利用者環境のスイッチ配下 | グローバルネットワーク | グローバルネットワーク |
| 分散する要素 | L4（IPアドレス・ポート） | DNS名前解決時のAレコード応答 | HTTP/HTTPSリバースプロキシ先、TCP着信 |
| LB自身の冗長化 | 冗長構成プランにより2台の冗長構成 | 標準で複数台の冗長構成 | 標準で複数台の冗長構成 |
| 実サーバとして設定可能なサーバ | ロードバランサを接続したスイッチと同一スイッチ配下のサーバ | 制限なし（さくらインターネット外部のサーバも設定可） | さくらインターネットのネットワーク内に設置のサーバ |
| 主な用途 | 単拠点で運用するサーバのスケールアウト | DR・BCP目的のリージョンスケールでの負荷分散 | HTTP/HTTPS環境に特化した負荷分散環境の構築 |

- DNSアプライアンスを使った**DNSラウンドロビン**による分散も可能（同じホスト名のレコードを複数登録しそれぞれのIPと関連付ける）。要件次第でマーケットプレイスの高機能ロードバランサも検討。

#### ヘルスチェック・実サーバの注意
- ヘルスチェックの接続元IP範囲から実サーバIPへ正常応答するようNW構成・パケットフィルタを設定（GSLBの接続元範囲はマニュアル、エンハンスドはリソースにより異なる＝プロキシ元ネットワーク参照）。
- ⚠️ **GSLBとエンハンスドロードバランサは実サーバにローカルIPアドレスを登録できない**。実サーバがプライベートNW内なら**VPNルータのNAT機能**でグローバルNWからアクセス可能にする。

#### ソーリーサーバ
- 高負荷/障害で実サーバが機能しない場合にメンテナンス画面を表示。**実サーバとは別にサーバを用意**。実サーバと同様の条件で指定する。
- ⚠️ エンハンスドロードバランサのソーリーサーバ応答条件: ①ルールでマッチしたサーバグループの実サーバが全てダウン / ②いずれのルールにもマッチせずサーバグループ未指定の実サーバが1つもない場合。
- 配置先の制約:
  - ロードバランサのソーリーサーバ: ロードバランサと**同じネットワーク（同じスイッチ）**に所属させる。
  - エンハンスドロードバランサのソーリーサーバ: **さくらインターネットのネットワーク内**に設置されている必要がある。
  - GSLBのソーリーサーバ: **制限なし**（さくらインターネット外部のサーバも設定可）。

#### 各リソース選択時の考慮事項
- **ロードバランサ**: 受け付ける**仮想IPアドレスとポート**を検討（実IPとは別に必要）。DSR構成のため実サーバの**ループバックインターフェースに仮想IPを設定**し、ARPリクエストに応答しないようカーネルパラメータを追加（手順はOSにより異なる、マニュアルに設定例）。TCPコネクション単位の細かなバランシングが必要な場合に選択。
- **GSLB**: 利用者で**バランシング対象FQDN**と**それを名前解決する権威DNS**を用意。**重み付け応答**を使うとDNSレスポンスがラウンドロビンでなく**単一レコードのみの応答**になる。冗長化目的の場合はフェイルオーバ高速性の観点から**重み付け応答を使用しないことが推奨**。
- **エンハンスドロードバランサ**: **配置先リージョン**と**VIPフェイルオーバーの有効/無効**は**作成後に変更不可**（事前検討）。VIPフェイルオーバー有効運用時はGSLB同様にバランシング対象FQDNと権威DNSが必要。実サーバ間通信は **httpかtcp**（⚠️ **httpsで通信できない**）。ログイン機能を持つWebアプリは**セッション維持機能**で実サーバを固定でき、L7関連機能が役立つため選択推奨。

## 7. 試験対策・要点チェック

- [ ] ハイブリッド接続は**プランなし・申し込み制**、接続作業は**さくらが実施**（ブリッジは利用者が操作）。
- [ ] ハイブリッド接続: **1ゾーン1スイッチ・同一プロジェクト内のみ**、解約は**書面提出**（オンライン不可）。
- [ ] ブリッジ→ハイブリッドは**ダウンタイムなし**で変更でき、旧ブリッジは**自動削除**。
- [ ] ハイブリッド接続はルータでNW分割が必須（ベストエフォート/ループ対策）。冗長化は**マルチシャーシLAG(Static/LACP)・Active-Standby**の3方式。
- [ ] 接続マップは**選択ゾーンのみ**表示（他ゾーン・グローバルは非表示）。色: **赤=共有セグメント/緑=ルータ＋スイッチ/青=スイッチ**。
- [ ] 閉域接続: AWS=**Equinix TY2/Direct Connect**、SINET・LGWAN・プライベートリンク・ダイレクトアクセスは**別途ハイブリッド接続契約が必要**。
- [ ] **LGWANコネクトは石狩リージョンのみ**、**外部回線接続サービス（インターネットVPN）も石狩リージョンのみ**対象。
- [ ] OCXは**BBIX**提供、プライベートリンクは for アルテリア / for BBIX・OCX / for NTTドコモビジネス。
- [ ] DNSアプライアンス: **権威・プライマリ専用**、キャッシュ/セカンダリ不可、**ゾーン転送非対応**、標準＋地理冗長。料金は**ゾーン単位の日額/月額**（時間額なし・従量なし）。
- [ ] DNSアプライアンス: **SOA編集・SPF登録は不可**、**ALIAS対応**（Zone ApexはALIAS、CNAMEは不可）、IDNは**Punycode**。
- [ ] シンプル監視: **IPv4グローバルIPのみ**（プライベート/IPv6不可）。チェック間隔**1～60分(標準1分)**、再試行回数**1～10回(3回)**、再試行間隔**10～3600秒(10秒)**、タイムアウト**1～30秒(10秒)**。
- [ ] SSL証明書有効期限アラートは**10分/30秒/5回固定**（変更不可）。再通知間隔は**1～72時間(デフォルト2時間)**。
- [ ] 使い分け: **L3で別会員/別プロジェクト=ローカルルータ**、**L2で別ゾーン=ブリッジ**、**L2で別サービス=ハイブリッド**。
- [ ] **1サーバ最大10NW**、プライベートNWのサブネットマスクは **/16～/29**。
- [ ] **AWS接続オプション・LGWANコネクトはローカルルータ必須**。ハイブリッド接続1契約に接続可能なローカルルータは**1台**。
- [ ] 負荷分散: ロードバランサ=**DSR/L4/同一スイッチ配下**、GSLB=**DNSラウンドロビン相当/外部サーバ可**、エンハンスド=**プロキシ/L7/実サーバ通信はhttp・tcpのみ**。
- [ ] GSLB・エンハンスドは**ローカルIPを実サーバ登録不可**（VPNルータNATで対応）。ロードバランサVRID・エンハンスドの配置先/VIPフェイルオーバーは**作成後変更不可**。
