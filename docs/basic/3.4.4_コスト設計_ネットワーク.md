## 1. ネットワークとコストパフォーマンス

### 基本的な考え方
- システム稼働時は、**将来的に必要となるネットワーク性能（帯域やコネクション数など）** とそれに基づくコストを考慮し、**システム導入時に適切なネットワークリソースやサービスを選択**する。
- さくらのクラウドでは、**一部のサービスを除きデータ転送量による従量課金が発生しない**。
  - そのため、**トラフィックが増加しても想定外のコストが発生せず**、計画的に利用できる。

> ⚠️ 試験頻出: さくらのクラウドは原則「データ転送量による従量課金なし」（※一部サービスを除く。AWS接続オプション等は転送量課金あり ― 第4節参照）。

### 運用開始後の変更しにくさ
- 通常、利用中のネットワークリソースを**他のリソース（またはサービス）に変更することは、ネットワーク構成の変更を伴うため、運用開始後の柔軟な変更が難しい**。
- そのため**導入時に適切なリソース（サービス）を選択**し、ワークロードの増加などに応じて**柔軟にプランを拡張・縮小**することで必要な性能を確保する運用を検討する。

### スモールスタートとプラン変更
- **ルータ＋スイッチ**や**エンハンスドロードバランサ**を利用するにあたり、**スモールスタート**を意識し、トラフィックに応じて適切なプランへ変更し、発生するコストをフィットさせていく。
- **ルータ＋スイッチ、エンハンスドロードバランサともに、プラン変更における停止は発生しない**。
- **ルータ＋スイッチのオートスケール機能**を使い、必要なトラフィックに対してコストを支出する構成とする。

## 2. グローバルネットワークの利用

### 接続方法とプラン選定
- サーバをグローバルネットワークに接続する際、**コスト重視なら標準の共有セグメント**を検討。**帯域を増強する必要がある場合はルータ＋スイッチ**を検討する。
- **共有セグメントは 100Mbps の共有帯域で、無料で利用できる**。
- 共有セグメントやルータ＋スイッチの各プランで設定されている**転送量目安**に注意する。

| 接続方法 | 帯域 | 料金 | 用途 |
|----------|------|------|------|
| 共有セグメント | 100Mbps（共有） | 無料 | コスト重視 |
| ルータ＋スイッチ | プランに応じて増強 | プラン課金 | 帯域増強が必要な場合 |

### ルータ＋スイッチの料金体系（重要）
- **1時間以内に複数回のプラン変更を行うと、コストが増加する可能性がある**ことに注意。
- 料金体系上、**1時間未満の利用時間は1時間として切り上げ**される。
- ルータ＋スイッチの利用料金は**日割料金の設定がなく**、月内にプラン変更した場合は**各プランの利用時間に応じた時間割料金の合算**となる。

### 帯域のオートスケール（重要）
- ルータ＋スイッチの帯域をオートスケールする際は、**想定トラフィックを考慮してスケーリングが発動するトリガーの値を検討**する。
- コスト増を避けるため、**オートスケール発動後、最低でも1時間はその状態を維持する**ことを検討する。

> 【Tips】オートスケール発動タイミングの調整
> **`cooldown` パラメータ**に適切な値を設定する。`cooldown` は同一ジョブの連続実行を抑制する**クールダウン期間で秒単位**で指定。
> 例: `cooldown=3600` に設定すると、**スケーリング処理が発動後 3600秒間（1時間）は、以降のスケーリングジョブがスキップ**される。

### スケジュール機能によるコスト削減
- トラフィックの増減が**事前に予測できる場合**は、**オートスケールのスケジュール機能**でコスト削減を検討する。
- 例: 日中帯はトラフィックが多く夜間帯は少ない場合、スケジュール機能で**日中帯と夜間帯の帯域を自動的に適切なプランへ変更**する選択肢がある。
- オートスケール機能利用時は、運用開始後も**パラメータ設定のチューニングなど相応の運用コストが発生**する点を考慮する。

## 3. 負荷分散の利用

### プラン選定の考え方
- ロードバランサ、またはエンハンスドロードバランサを利用する際は、発生するコストを考慮し、**性能要件に応じた適切なプランを選択**する。
- **ロードバランサとエンハンスドロードバランサには性能に応じたプランが提供されている**が、**GSLB には性能に応じたプランは提供されていない**。
- エンハンスドロードバランサのプラン選択では、**各プランの上限値を越える秒間あたりの新規接続が発生した場合、処理中の接続が完了するまで接続待機状態となる**ことも考慮する。

### エニーキャスト（エンハンスドロードバランサ）
- パフォーマンス向上のため、**エニーキャストを選択することを検討**する。

> 【Tips】エンハンスドロードバランサのエニーキャスト
> エニーキャストを選択した場合、接続するクライアントへの応答は**ネットワーク的に近いリージョンのエンハンスドロードバランサが自動的に選択**される。
> これにより、**設置先リージョンを固定した場合よりもクライアントへのレスポンスタイムが短縮**されることが期待できる。

### 多段構成（重要）
- 高トラフィックが想定される大規模構成では、負荷分散用リソースの仕様を確認し、求める性能を実現できない場合は**ロードバランサを使った多段構成**を検討する。
- 1台では提供スペックや**実サーバとして登録可能な最大台数が不十分**な場合、複数台利用して多段構成とし、1台あたりに収容する実サーバ台数を調整して最適化する。

**GSLBとロードバランサによる多段構成の例**
- **GSLB の実サーバとしてロードバランサを指定**する。
- **1台のロードバランサに登録できる実サーバは 40台まで**。
- それより多い台数で負荷分散する場合は多段構成を検討する。

```
        ┌────────┐
        │  GSLB  │
        └───┬────┘
        ┌───┴───┐
     ┌──┴──┐ ┌──┴──┐
     │ LB  │ │ LB  │   ← GSLBの実サーバとしてLBを登録
     └──┬──┘ └──┬──┘
   [Web][Web] [Web][Web]  ← 1台のLBに実サーバ最大40台
```

### エンハンスドロードバランサのプラン変更・オートスケール（重要）
- プランを変更する際は、**月内に複数回の変更を行うとコストが増加する可能性がある**ことに注意。
- **プランを変更すると月内の利用時間の積算がリセットされる**。
- **オートスケール機能で自動的にエンハンスドロードバランサのプランを変更可能**。
  - ただし、指定できる**オートスケールの発動トリガーは「サーバのCPU時間」か「ルータ＋スイッチのトラフィック」のみ**。
  - **エンハンスドロードバランサのコネクション数を指定することはできない**点に注意。

> 【Tips】エンハンスドロードバランサのプラン変更
> 各プランの上限値を越える秒間あたりの新規接続が発生しても、**クライアント側へ即時にエラーとして接続を拒否することはない**。クライアントからの再送が行われるまで接続に時間がかかる状態となる。
> **アクティビティグラフよりセッション数を確認**でき、契約中のプランを超過するセッションが発生する場合は、より高い上限値を持つプランへの変更を検討する。

## 4. 外部接続の利用

### 閉域網接続とインターネットVPN接続
- 利用者拠点間、もしくは他社クラウド間を安全に通信したい場合、**求めるセキュリティレベルと発生するコストを比較**して、**閉域網接続**と**インターネットVPN接続**の両方の構成を検討する。
- 閉域網で接続する場合、現在のネットワーク構成を考慮して最適な外部接続サービスを選択する。
  - **閉域網接続には複数の選択肢**があり、サービスごとに前提条件が異なる。現在の閉域網サービスやネットワーク環境に基づいて**導入コストと運用コストを比較**し、最もコストパフォーマンスに優れたサービスを選択する。
- **インターネットVPNで接続する場合は VPNルータの利用を検討**する。
  - **閉域網接続を利用するよりも安価に構成できる**。

### AWS接続オプションの利用（重要：転送量課金あり）
- 月額の基本料に加えて、**さくらのクラウドから AWS への通信に対する転送量課金が発生**する。
- また、**AWS側への支払いとして、AWS からさくらのクラウドへの通信に対する転送量に課金が発生**する（双方向で課金）。
- 構成上、**ローカルルータが必要**であるため、その分のコストも考慮する。

> ⚠️ 試験頻出: AWS接続オプションは**双方向で転送量課金が発生**（さくら→AWSはさくら側課金、AWS→さくらはAWS側課金）。「従量課金なし」原則の例外。

### プライベートリンクの利用
- プライベートリンク自体の利用コスト以外に、**他社サービスやデータセンターの利用に伴うコスト**が発生する点に注意。

| サービス | 発生するコスト / 特長 |
|----------|----------------------|
| プライベートリンク（標準） | さくらインターネットが指定したデータセンターの**ラック利用料金**などが発生 |
| プライベートリンク for アルテリア | 指定された**アルテリア・ネットワークスのサービス利用料金**が発生 |
| プライベートリンク for BBIX / OCX by BBIX | **広帯域の閉域網を安価に利用**できる |
| プライベートリンク for NTTドコモビジネス | **共有回線を帯域確保型で利用**できる |

- プライベートリンクは構成上、**ハイブリッド接続とスイッチを使うことが必要**なため、その分のコストも考慮する。
- ハイブリッド接続で接続されるさくらのクラウドの各サービスには**個別の通信帯域上限**があるため、各ネットワーク区間で必要な帯域を考慮して利用する。

## 5. オプションサービスの利用

- さくらのクラウドでは複数の安価なオプションサービスが提供されており、利用することでコスト削減が期待できる。

| サービス | コスト削減効果 |
|----------|----------------|
| DNSアプライアンス | クラウド上で権威DNSを運用する場合に検討。利用者側で**権威DNSのサーバOSやミドルウェアの運用が不要** |
| シンプル監視 | さくらのクラウドで提供される**グローバルIPアドレスに対して無料で監視**ができる。監視サーバを自前運用している場合、切り替えで**運用コスト削減**が期待できる |

## 6. 試験対策・要点チェック

- [ ] さくらのクラウドは原則 **データ転送量による従量課金なし**（一部サービスを除く）。トラフィック増でも想定外コストが出にくい。
- [ ] ネットワークリソースは**導入時の選定が重要**（運用開始後の変更は構成変更を伴い難しい）。プラン拡張・縮小で性能確保。
- [ ] **共有セグメント = 100Mbps 共有・無料**。帯域増強が必要ならルータ＋スイッチ。
- [ ] ルータ＋スイッチ／エンハンスドロードバランサとも**プラン変更で停止は発生しない**。
- [ ] ルータ＋スイッチは**日割なし、時間割の合算**。**1時間未満は1時間に切り上げ**。1時間内の複数回プラン変更はコスト増。
- [ ] オートスケール発動後は**最低1時間維持**。**`cooldown=3600`** で1時間スキップ。予測可能なら**スケジュール機能**でコスト削減。
- [ ] **GSLBには性能別プランがない**（LB/エンハンスドLBにはある）。
- [ ] エンハンスドLBはエニーキャストで**近いリージョンが自動選択**されレスポンス短縮。上限超過時は即エラーにせず接続待機（再送待ち）。
- [ ] **1台のロードバランサに実サーバは最大40台**。超える場合はGSLB＋LBの**多段構成**。
- [ ] エンハンスドLBのオートスケールトリガーは**サーバのCPU時間 or ルータ＋スイッチのトラフィックのみ**。**コネクション数は指定不可**。プラン変更で利用時間積算がリセット。
- [ ] 外部接続: 閉域網 vs インターネットVPN（**VPNルータは閉域網より安価**）をコストとセキュリティで比較。
- [ ] **AWS接続オプションは双方向で転送量課金**＋ローカルルータが必要。
- [ ] プライベートリンクはラック利用料金等の付帯コストあり。BBIX/OCXは広帯域を安価に、NTTドコモビジネスは帯域確保型。
- [ ] オプション: **DNSアプライアンス**（権威DNS運用不要）、**シンプル監視**（グローバルIP無料監視）でコスト削減。
