# 3.1.2 ストレージ

> 出典: SCB3.1.2_Storage（さくらのクラウド検定ベーシック教材, CC BY-SA 4.0 / さくらインターネット）
> 学習目標: さくらのクラウドで提供される各種ストレージ（ディスクリソース、ストレージサービス）の特徴を把握し、システムの要件に応じたシステム構成設計の考え方を理解する
> キーワード: ディスクプラン（標準プラン・SSDプラン・ディスクIOPS・クローン） / 専有ストレージ / ISOイメージ / NFSアプライアンス / オブジェクトストレージ

## 0. 全体像（教材の構成）

本章は「3.1 さくらのクラウドで実現するシステム構成設計」配下のストレージ単元。各ストレージリソースの「特徴と選択可能なプラン」を理解したうえで、「システム構成設計に対する考え方」を学ぶ二部構成。

| 区分 | 対象リソース／テーマ |
|------|----------------------|
| リソースの特徴とプラン | ディスクプラン / 専有ストレージ / ISOイメージ / NFSアプライアンス / オブジェクトストレージ |
| システム構成設計の考え方 | ストレージ形式の選択 / ディスクプランの検討 / NFSアプライアンスの検討 / オブジェクトストレージの検討 |

ストレージ形式の大分類と該当サービス:

| ストレージ形式 | 一般的な用途 | さくらのクラウドでの該当 |
|----------------|--------------|--------------------------|
| ブロックストレージ | DBなど高速・低遅延な読み書き、サーバOSのストレージ | ディスク（標準/SSD）、専有ストレージ |
| ファイルストレージ | 文書・画像・動画をネットワーク経由でファイル共有 | NFSアプライアンス（自前構築も選択肢） |
| オブジェクトストレージ | 大量の静的コンテンツ保存、アーカイブ・バックアップ、大規模Web | オブジェクトストレージ |

## 1. ディスクプラン（ブロックストレージデバイス）

- サーバに接続可能なブロックストレージデバイス。**大容量・高性能**。
- プランは **標準プラン** と **SSDプラン** の2つ。

### プランとサイズ（重要表）

| プラン | 使用媒体 | サイズ範囲 | 備考 |
|--------|----------|------------|------|
| 標準プラン | ハードディスク（HDD） | 最小 **40GB** ～ 最大 **12TB** | — |
| SSDプラン | SSD（Solid State Drive） | 最小 **20GB** ～ 最大 **16TB** | **2TB～** は東京第2ゾーンおよび石狩第3ゾーンのみ |

- 各プランで複数のディスクサイズから選択できる。
- 料金: プランとサイズに応じた **時間額・日額・月額** が設定。
  - 同じサイズなら **標準プランより SSDプランが高価**。
  - **東京リージョンと石狩リージョンで料金が異なるサイズがある**（例: SSDプラン20GB）。

### ディスクの作成

- ディスクは **サーバと同時に作成** できるほか、**ディスク単体での個別作成・削除** も可能。
- ディスクはサーバに **接続・取り外し** ができる。
- **サーバ1台あたり最大3台** のディスクを接続可能。
- 空のディスクだけでなく、既存ディスクやアーカイブからコピーして作成できる。

#### ディスクソース（作成元）

| ディスクソース | 説明 |
|----------------|------|
| ブランク | 空のディスク（何もデータが入っていない状態）を作成 |
| ディスク | **同一ゾーン内**の既存ディスクをもとに新規ディスクを作成 |
| アーカイブ | パブリックアーカイブをもとに新規ディスクを作成 |
| マイアーカイブ | 利用者が作成したアーカイブをもとに新規ディスクを作成 |

### ディスクインターフェース（IDE / VirtIO）

- ディスクインターフェースは **IDE** か **VirtIO** のいずれかを選択。
  - **VirtIO**: オーバーヘッドが少なく高性能。最近の多くのOSが対応。
  - **IDE**: 互換性が高い。古いOSやVirtIO未対応の場合に選択。
- tips:
  - インターフェースは **作成後に変更可能**。ただし接続先サーバの **停止が必要**。
  - サーバには **IDEのディスクが先に認識** される。IDEとVirtIOが混在すると想定した順序で認識されない恐れがあるので注意。

### ストレージ分散

- 作成するディスクを既存サーバに接続する場合、対象サーバに既に接続済みのディスクとは **別のストレージに作成** することで **耐障害性を向上**。

### ディスクの削除

- サーバに **未接続** のディスクは削除できる。
- サーバに接続済みのディスク:
  - サーバ削除と同時にディスクも削除できる。
  - ディスク単体で削除する場合は **サーバからの取り外しが必要**。
- **削除したディスクは復旧できない**。

### ディスクの修正（ディスク修正機能）

- パブリックアーカイブからディスクにコピーする際に、**OSの設定を自動的に変更** する機能。サーバ作成時の「ディスクの修正」はこの機能を利用している。
- ディスク詳細画面の「ディスクの修正」からも使用可能。

#### ディスク修正機能で設定できる項目（Linuxの場合）

| 項目 | 説明 |
|------|------|
| IPアドレス、ネットマスク | ルータ＋スイッチ／スイッチ接続時のみ修正可能 |
| デフォルトゲートウェイ | ルータ＋スイッチ／スイッチ接続時のみ修正可能 |
| DHCP | DHCPでIPアドレスを設定する |
| ホスト名 | サーバのhostnameとして登録する名前 |
| パスワード | 管理者アカウントのパスワード（多くのOSはroot、Ubuntuはubuntuユーザ） |
| 公開鍵 | 管理者アカウントのホームディレクトリの公開鍵設定。パスワードでのSSHログイン無効化も可 |
| スタートアップスクリプト | 指定スクリプトで起動するよう設定 |
| パーティションのUUID | ルートパーティションのファイルシステムのUUIDを変更 |

※Windowsの場合は項目が異なる（詳細はクラウドマニュアル参照）。

- 修正の条件:
  - サーバに **未接続** のディスクは修正可能。
  - 接続済みディスクを修正するには **サーバの停止が必要**。
  - tips: **パブリックアーカイブ以外**から作成されたディスク（ISOイメージで独自にOSをインストールしたディスク等）は **修正機能に非対応**。

### ディスクの拡張

- **ディスクサイズは変更できない**（※専有ストレージ上のディスクを除く）。
- サイズ拡張の手順（付け替え方式）:
  1. 既存ディスクをソースとして、**サイズの大きなディスクを新規作成**。
  2. パーティションサイズを拡張。
  3. サーバから既存ディスクを取り外し、作成したディスクを接続。

#### パーティション拡張機能

- ディスクに空き容量がある場合、パーティションサイズをディスクサイズに合わせて拡張する機能。
- 実行条件:
  - サーバに **未接続** のディスクで実行可能。
  - 接続済みディスクで実行するには **サーバの停止が必要**。
- 制限:
  - **8TB、12TB、16TB** のディスクには **非対応**。
  - 対応ファイルシステムは **ext2 / ext3 / ext4** のいずれか。
- tips: 非対応のサイズ・FSの場合は、利用者がOS上で拡張する（Linuxは `growpart`、WindowsはOS標準の管理ツール）。

## 2. 専有ストレージ（ブロックストレージ SSDサービス）

- 物理ストレージを **専有** できる高性能プラン（SSD）。
- **最大IOPS 50,000、1GB/s スループット** に対応。
- **専有ホスト（専有ストレージ用）の別契約が必要**。
  - 対比: ディスク＝共有型ストレージ、専有ストレージ＝専有型ストレージ。

### 料金

- **月額固定料金のみ** での提供。
- **ディスクの作成有無に関わらず課金開始**。
- ストレージ内で作成したディスクやスナップショットには **別課金なし**。
- **専有ストレージにプランは存在しない**。

### 基本仕様（重要表）

| 項目 | 内容 |
|------|------|
| 最大ストレージ容量 | **32TB** |
| 最大ディスクサイズ | **16TB**（1ディスクあたり） |
| 最大IOPS | **50,000** |
| 最大スループット | **1GB/s** |
| 提供ゾーン | **東京第2ゾーン** |

### スナップショット機能

- ディスクの状態を **任意のタイミングで保存** できるバックアップ機能。
- スナップショットは **合計27TBまで** 保存可能。
- 任意のタイミングで取得でき **世代管理に対応**。
- **ディスクごとに最大16個** のスナップショット取得が可能。

### オンライン容量拡張機能

- **サーバを停止することなく** ディスク容量を拡張できる。
- 拡張後、パーティションやファイルシステムの拡張を別途実施する必要がある。
- **容量縮小は非対応**。
- 対象ディスクに **スナップショットが存在する場合は利用できない**。

### 利用上の注意

- 利用前に **事前申し込み** が必要。申し込みには **さくらインターネットの審査** が必要。
- 専有ストレージで作成したディスクは、**組み合わせ申し込みした専有ホスト上のサーバにのみ接続可能**。他のサーバには接続できない。
- tips: 物理筐体を占有するため **I/Oの揺らぎが少なく** 安定したスループットが求められるシステムに適する。提供は **東京第2ゾーンのみ**。

## 3. ISOイメージ機能

- ISOイメージを保存し、サーバの **CDドライブへ挿入** して利用する機能。
- 種類は **パブリックISOイメージ** と **プライベートISOイメージ** の2つ。

### パブリック／プライベートの比較（重要表）

| 項目 | パブリックISOイメージ | プライベートISOイメージ |
|------|----------------------|------------------------|
| 内容 | OS開発元が配布するインストールイメージを格納したISO | 利用者がISOイメージ用ディスク領域にアップロードしたイメージ |
| 利用範囲 | — | **同一ゾーン内のサーバでのみ**使用可能 |
| 料金 | **無料** | ISO保存用のディスク領域に料金が発生 |
| 提供OS例 | パブリックアーカイブ提供OSに加え、Fedora・FreeBSD等のディストリビューション、Microsoft SQL Server Expressエディション等も利用可 | 利用者がアップロードしたもの |

- プライベートISOイメージの利用フロー: ①ISOイメージ用のディスク領域を作成 → ②ISOイメージを **FTPでアップロード** → ③サーバに挿入して使用。

### プライベートISOイメージのディスク領域

- ディスク領域のサイズは **5GB / 10GB / 20GB** から選択。サイズが大きいほど高価（時間額・日額・月額）。
- アップロード可能なISOは **一つの領域につき一つのイメージのみ**。複数必要なら個数分の領域を作成する。
- **サイズは変更できない**（変更したい場合は再作成が必要）。
- 同じ領域に別のISOをアップロードすると **後からのイメージで上書き** される。

### アップロードと有効状態

| 有効状態 | 説明 |
|----------|------|
| アップロード | FTPによるアップロードが可能な状態（アップロード済みISOのダウンロードも可能） |
| 利用可能 | FTPが完了しサーバに挿入できる状態 |

- tips: ISOイメージは **FTPS** でアップロード／ダウンロードする。**TLS1.3で接続するとアップロードに失敗する場合がある** → TLS1.2までを使用する設定にしてから接続する。

## 4. NFSアプライアンス（NFSファイルサーバ）

- **大容量** かつ **複数クライアントからアクセス可能** なNFSファイルサーバ。
- プランは **標準プラン** と **SSDプラン** の2つ。

### プランとサイズ（重要表）

| プラン | サイズ範囲 | 備考 |
|--------|------------|------|
| 標準プラン | 最小 **100GB** ～ 最大 **12TB** | — |
| SSDプラン | 最小 **20GB** ～ 最大 **4TB** | **2TB～** は東京第2ゾーンおよび石狩第3ゾーンのみ |

- 料金: プランとサイズに応じた時間額・日額・月額。同サイズなら **標準より SSDが高価**。

### 基本仕様

- 対応プロトコル: **NFSv3, NFSv4**。
- マウントポイント: **/export**。
- **グローバルIPアドレス環境への接続はできない**。
- **ユーザ認証機構がない**。
- **IPv6 非対応**。

### ネットワークとクローン

- ネットワーク: **スイッチに接続** が必要（事前にスイッチを作成しておく）。**IPv4アドレスを付与**、デフォルトゲートウェイの設定も可能。
- クローン機能: NFSアプライアンスの複製が可能。**同等サイズか、より大きいサイズに複製** できる（上位プランへのスケールアップ手段）。

### 作成・利用上の注意

- 作成後は **接続先スイッチの変更・切断、IPアドレス等のネットワーク設定の変更ができない** → 作成前にネットワーク構成を検討しておく。
- ネットワークインターフェースは **一つのみ**。複数スイッチには接続できない。
- 作成後は **自動的に起動** する。削除する際は **NFSアプライアンスを停止** する。
- スケールアップ（上位プランへのクローン）の際は **アプライアンスの停止が必要**。
- tips: **SNMPエージェント機能** を提供。付与IPへSNMP接続で各種状況を監視できる（コミュニティ名・OIDはクラウドマニュアル参照）。

## 5. オブジェクトストレージ（ストレージサービス）

- **スケーラブル**、**Amazon S3互換API**、**定額従量制** のストレージサービス。

### 構成要素

| 構成要素 | 説明 |
|----------|------|
| サイト | リソースが作成される物理的位置。**石狩第1サイト**と**東京第1サイト**から選択可能 |
| バケット | 各サイトにおいてオブジェクトを格納する領域 |
| フォルダ | 各バケットでオブジェクトを管理する **疑似的なフォルダ** |
| オブジェクト | バケットやフォルダ内に格納するファイル（データ） |

- 階層: サイト ＞ バケット ＞ フォルダ ＞ オブジェクト。フォルダ配下にさらにフォルダを作成可能。

### 料金

- **基本料金**（一定の利用量まで月額固定料金）＋ **基本料金超過分**（従量課金）。
  - アーカイブプランはバケット容量に応じた **固定料金**。
- **バケットごとに料金が発生**。バケット作成完了時点からそのバケットの基本料金課金が開始。

#### 基本料金に含まれる利用量の範囲（超過分は従量課金）

| 項目 | 利用量 |
|------|--------|
| ストレージ容量 | **100GiB** まで |
| 転送量 | **10GiB** まで |
| リクエスト数 | **100,000リクエスト** まで |
| オブジェクト数 | **100,000オブジェクト** まで |

- 転送量は **さくらインターネット外部への通信が課金対象**。
- 課金対象外:
  - さくらインターネット **内部へのデータ転送**（クラウド、VPS、専用サーバPHYなど）。
  - さくらインターネット **外部からのPUT/POSTを利用した通信**。

#### アーカイブプラン

- **アクセス頻度の低いデータを長期保存** する用途に適する。
- **東京第1サイトのみ** で利用可能。
- tips: 標準のオブジェクトストレージは初期状態で **1バケットあたり最大10TiB** に制限され、料金は使用量に応じる。アーカイブプランは **1バケットあたりの最大容量を 1～10TiB の範囲から選択** し、使用量・転送量に関係なく **固定料金**（標準より割安）。

### サイトとキーの利用

- 利用にあたり、初回アクセス時に **「サイトの利用開始」** が必要。
- API操作で使う **シークレットアクセスキー** は、サイト利用開始の **このタイミングでのみ確認可能**（後から新規キーの再発行は可能）。

### バケット／フォルダ／オブジェクト

- バケット名は、**他の利用者も含めたオブジェクトストレージ全体で一意** な文字列である必要がある。
  - **バケット名の変更機能はない**（誤作成時は削除して再作成）。
  - バケット削除には内部のオブジェクト・フォルダが全削除されている必要がある（サイト削除も同様に内部が空である必要）。
- アーカイブプラン選択時はバケットの容量を指定する必要がある。
- オブジェクトはバケット直下とフォルダ配下にアップロード可能。
- アップロードしたオブジェクトはURLで **HTTPSアクセス可能**: `https://S3エンドポイント/バケット名/フォルダ名/ファイル名`。

### 操作方法（管理画面とAPI）

- 操作手段は **管理画面** と **API** の2つ。APIは利用形態・操作範囲に応じて2種類。

| API | 認証 | 操作範囲 |
|-----|------|----------|
| さくらのオブジェクトストレージAPI | さくらのクラウドの **APIキー** | バケットの新規作成・削除を含む、管理画面と同様の操作 |
| Amazon S3互換API | サイト作成時／パーミッション設定時に発行される **アクセスキー** | 作成済みバケットとオブジェクトの操作 |

- tips: 管理画面から実行可能なバケット操作は限定的。**バケットバージョニング**（複数バージョン保持）の設定は **S3 APIでのみ** 行える。

### パーミッションとACL（重要）

#### パーミッション（API操作におけるバケット単位の操作権限）

| パーミッション | 説明 |
|----------------|------|
| NONE | 読み込みも書き込みも許可しない（**デフォルト値**） |
| READ | 読み込みのみ許可 |
| WRITE | 書き込みのみ許可 |
| READ/WRITE | 読み込みおよび書き込みを許可 |

- バケット・オブジェクトのAPI操作で使うシークレットアクセスキーは、パーミッション設定の **このタイミングでのみ確認可能**（再発行は可能）。
- tips: サイト作成時のアクセスキーでも操作できるが、セキュリティの観点から **パーミッション設定で発行されるキーの使用が推奨**。各バケットには操作に必要な **最小限のパーミッション** を設定する。

#### バケットACL（バケット単位のアクセス制限）

| アクセス制限 | 説明 |
|--------------|------|
| private | 認証が必要なAPI経由でのみオブジェクトリストを取得できる（**デフォルト値**） |
| public-read | 認証不要のURL経由でオブジェクトリストを取得できる |

#### オブジェクトACL（オブジェクト単位のアクセス制限）

| アクセス制限 | 説明 |
|--------------|------|
| private | API経由でのアクセスのみ許可（**デフォルト値**） |
| public-read | アクセスキー不要でURLを指定してアクセス可能 |

- パーミッション（鍵＝操作権限）とACL（公開可否）の組み合わせでアクセス可否が決まる。第三者に公開不要なオブジェクトには **オブジェクトACL: private** を設定する。

### リージョン間レプリケーション（CRR: Cross Region Replication）

- リージョンを跨いでバケット間でオブジェクトを複製する機能。
- **石狩第1サイト → 東京第1サイト への片方向のみ** 可能。
- 管理画面、またはさくらのオブジェクトストレージAPIで有効化できる。
- **非同期方式** のため、複製先サイトには **即時には反映されない**。

## 6. システム構成設計の考え方

### ストレージ形式の選択
- ブロックストレージ／ファイルストレージ／オブジェクトストレージのいずれの形式かを検討（→ 「0. 全体像」の表参照）。
- ファイルストレージはNFSアプライアンスのほか、**ディスク付きサーバ上に利用者自身でファイルサーバを構築** するのも選択肢。

### ディスクプランの検討
- システム要件に応じて適切なプラン（標準・SSD）とサイズを選択。**IOPS性能の制限値・データ転送帯域の制限値** を考慮（性能情報はクラウドマニュアル）。
- 空き容量不足時は、対象ディスクをソースに別ディスクを新規作成して **スケールアップ**（要サーバ停止）。余裕を持った容量で作成するのも一案。
- **Windows Server のパブリックアーカイブ** を選ぶ場合、ディスクサイズは **100GB以上 2TB以下** である必要がある。
- パーティション設計に応じて接続ディスク本数を検討。一般的に **OSとデータは別ディスク** に分ける。
- ディスクインターフェースは特別な要件がなければ高パフォーマンスな **VirtIO** を選択（古いLinux・未対応OSはIDE）。

### NFSアプライアンスの検討
- 用途に応じプラン（標準・SSD）とサイズを選択。**データ転送帯域の目安** を参考にする（クラウドマニュアル）。
- 空き容量不足時は **上位プランへのクローン** でスケールアップ（要アプライアンス停止）。
- スイッチ接続が必須でインターフェースは一つのみ。**ネットワーク設定は作成後変更不可** → 作成前にネットワーク構成を検討する。

### オブジェクトストレージの検討
- ストレージ容量・転送量等に応じた **従量課金** で、サーバ・ディスクとは料金体系が異なる。**アーカイブプラン** も選択可。
- **API限定機能** があるため、運用フェーズのバケット・オブジェクト操作は基本的にAPIで行う。
- サーバにネットワーク経由でマウントする使い方もあるが、**マウントツールは利用者自身で選定**（さくらインターネットのサポート範囲外）。
- 適切なパーミッション設定と発行アクセスキーで操作する。**通常運用ではサイト利用開始時のアクセスキーは使用しない**。バケット・オブジェクトには適切なACLを設定（公開不要はprivate）。
- サーバ⇔オブジェクトストレージ間の通信は **さくらのグローバルネットワークを経由**（ローカルネットワークには接続できない）。通信はバックボーン内で行われ **インターネットは経由しない**。**スイッチのサービスポイントゲートウェイ** を使うと通信がクラウド内部ネットワーク内で完結する。
- 要件を満たせない場合は他社オブジェクトストレージとの **マルチクラウド構成** も検討。

## 7. 試験対策・要点チェック

- [ ] ディスク標準プラン = **40GB～12TB**、SSDプラン = **20GB～16TB**（2TB超は東京第2／石狩第3ゾーンのみ）。同サイズなら **SSDが高価**。
- [ ] サーバ1台に接続できるディスクは **最大3台**。ディスクソースは ブランク／ディスク（同一ゾーン）／アーカイブ／マイアーカイブ。
- [ ] ディスクインターフェースは **VirtIO（高性能）/ IDE（互換性）**。IDEが先に認識される。変更時はサーバ停止。
- [ ] **ディスクサイズは変更不可**（専有ストレージ上のディスクを除く）。拡張は大きいディスクを新規作成して付け替え。
- [ ] パーティション拡張機能は **8TB/12TB/16TBは非対応**、対応FSは **ext2/ext3/ext4**。
- [ ] ディスク修正機能は **パブリックアーカイブ由来のディスクのみ**対応。削除したディスクは復旧不可。
- [ ] 専有ストレージ: **最大32TB / 1ディスク最大16TB / 最大IOPS 50,000 / 1GB/s / 東京第2ゾーンのみ**。月額固定のみ・**プランなし**・事前申込＋審査必須。
- [ ] 専有ストレージのスナップショット = **合計27TBまで / ディスクごと最大16個**。オンライン容量拡張は **縮小不可・スナップショットありで不可**。
- [ ] プライベートISO: 領域サイズ **5/10/20GB**、1領域1イメージ、同一ゾーン限定、**FTP(S)** で転送。**TLS1.3は失敗の恐れ → TLS1.2**。パブリックISOは **無料**。
- [ ] NFSアプライアンス: 標準 **100GB～12TB** / SSD **20GB～4TB**。**NFSv3/v4**、マウントポイント **/export**、グローバルIP不可・認証なし・IPv6非対応。スイッチ接続必須、設定は作成後変更不可、スケールは **クローン**。
- [ ] オブジェクトストレージ: **S3互換API**、サイト = 石狩第1／東京第1、料金は **バケット単位**。基本料金範囲 = 容量100GiB／転送10GiB／リクエスト10万／オブジェクト10万。
- [ ] アーカイブプランは **東京第1サイトのみ・固定料金**、1バケット1～10TiB。標準は1バケット最大10TiB。
- [ ] シークレットアクセスキーは **発行時のみ確認可**（再発行可）。バケット名は **全体で一意・変更不可**。
- [ ] パーミッション既定 = **NONE**、バケット/オブジェクトACL既定 = **private**。S3 APIでのみ可能な機能（**バケットバージョニング**等）あり。
- [ ] CRR（リージョン間レプリケーション）= **石狩第1 → 東京第1 の片方向のみ・非同期**。
- [ ] オブジェクトストレージ通信は **グローバルNW経由（ローカル接続不可）/ インターネット非経由**。**サービスポイントゲートウェイ** で内部完結。
