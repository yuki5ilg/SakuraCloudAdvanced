## 1. ストレージとコストパフォーマンス（基本の考え方）

- ストレージを利用するにあたり、利用者が求めるコストパフォーマンスに応じた**適切なサービス・リソース・プラン・機能を選択**する。
- ディスクの利用開始時は**スモールスタート**を意識し、需要に応じて**スケールアップ**させることで、実運用で必要となるディスクサイズと、それに基づくコストをフィットさせていく。
- ⚠️ 注意（スケールアップの制約）: ディスクをスケールアップするには、対象ディスクが接続された**サーバの停止**と、**ディスク作成処理に相応の時間**を要する。サーバの停止時間を十分に確保できないシステムでは、**はじめから余裕を持たせたサイズ**のディスクを作成して運用する。
- 外部ストレージとして、さくらのクラウドの**NFSアプライアンス**や、コストパフォーマンスに優れた**オブジェクトストレージ**を使用し、利用を効率化して運用コストを削減することを検討する。
- 要件によっては、さくらのクラウドのストレージではなく**さくらのVPS**を利用する、もしくはクラウドと併用するほうがコストメリットが出る場合もある。**発生するトータルコスト**を考慮した上で選択する。

## 2. ディスクプランの選定（HDD・SSD）

### ゾーン・リージョンによる差異

- ⚠️ ディスク料金と提供中のディスクサイズは**ゾーンによって異なる場合がある**ため、最新の情報を確認した上でゾーンを選択する。
- **標準プラン**は、ゾーンによって提供されるディスクサイズが異なる。

| ゾーン | 標準プランで選択できるディスクサイズ |
|--------|--------------------------------------|
| 石狩第１、石狩第２、東京第１ | 最小 **40GB** ～ 最大 **12TB** |
| 東京第２、石狩第３ | 最小 **2TB** ～ 最大 **12TB** |

- **SSDプラン**は、**リージョンによって一部のディスクプランの料金が異なる**。20GBのディスクプランでは、**石狩リージョンが東京リージョンよりも安価**に提供されている。
- 最小サイズの違い: **標準プランの最小は40GB**、**SSDプランの最小は20GB**。必要なサイズも考慮して適切なプランを選択する。

### 標準プランとSSDプランの比較（重要表）

| 項目 | 標準プラン（HDD） | SSDプラン |
|------|-------------------|-----------|
| 重視する観点 | **容量を重視**する場合 | **性能を重視**する場合 |
| 性能の目安 | 一般的なHDDの **2倍以上**の性能 | 一般的なHDDの **20倍以上**の性能 |
| 最小ディスクサイズ | **40GB** | **20GB** |
| 料金 | SSDプランより**安価** | 標準プランより高価 |

- ⚠️ 試験頻出: **性能重視＝SSDプラン / 容量重視＝標準プラン** を基本とする。
- 各プランの**IOPS**と**データ転送帯の制限値**は**クラウドマニュアル**で確認できる。**ディスクサイズが大きいほどI/O性能は余裕を持たせた制限値**となっており、制限値を参考に要件を満たすディスクを選択する。

### プランの使い分け運用

SSDプランより標準プランのほうが安価であることを踏まえ、以下のような使い分けでコストパフォーマンスを最適化できる可能性がある。

- **時系列での使い分け（プラン変更）**: 既存のディスクを元に、**別のプランのディスクを作成可能**。例として、構築時はコスト重視で標準プランを選択し、運用しながら性能を確認、性能が足りない場合は運用中のディスクを元にSSDプランのディスクを作成して**付け替える**。
- **用途別の使い分け（混在構成）**: **異なるプランのディスクを同一サーバに接続可能**。例として、同一サーバの**1番目のディスク**にI/Oが頻繁に発生する**OS/アプリケーション用としてSSDプラン**を、**2番目のディスク**にI/Oがあまり発生しない**データ用として標準プラン**を選択する。

## 3. 外部ストレージの利用

### NFSアプライアンス

- さくらのクラウドの**ローカルネットワーク内**で、**複数のサーバからアクセス可能なファイルサーバ**が必要な場合に利用を検討する。
- 利用者が直接NFSサーバを構築するよりも、**OSやミドルウェアの管理が不要**になり、**運用コストを削減**できる。
- ⚠️ 注意: NFSアプライアンスで利用されるディスクは、**通常のディスクよりも性能が低い**。**IOPSの制限値が通常のディスクより小さい**。IOPSの目安は**クラウドマニュアル**で確認できる。

### オブジェクトストレージ

- **大容量のデータを保管**したい場合に利用を検討する。
- **基本料金に含まれる範囲内（ストレージ容量 100GiB まで等）**での利用であれば、**安価に定額**で利用を開始できる。
- ⚠️ 基本料金に含まれる範囲を超えて利用する場合は、**ストレージ容量や転送量等に伴う従量課金**となり、**通常のディスクとは異なる料金体系**である点に注意。

#### リージョン間レプリケーション（CRR）の料金

- CRR利用時は、**ソースバケットに加えてディスティネーションバケットの料金が発生**する。
- **CRR機能自体は無料**で利用でき、**CRRによるデータ転送量には課金が発生しない**。
- ⚠️ CRR利用には、**ソースバケット・ディスティネーションバケットの両方でバケットバージョニングを有効化**する必要がある。バージョニングで保存される各オブジェクトは**課金対象のストレージ使用量に含まれる**ため、想定外の課金に注意する。

## 4. さくらのクラウド周辺サービスの利用（さくらのVPS併用）

- コストを抑えるため、より安価な**さくらのVPS**の利用を検討する。VPSを**ストレージサーバの役割**で利用し、クラウドのサーバと併用することで、各サービスのコストメリットを活かしたネットワーク構成を採れる。
- ⚠️ クラウドサーバからVPSに**ローカルネットワーク経由で接続**する場合は、**ブリッジとスイッチを使用**する必要がある。トータルコスト算出時には発生する料金として含める。
- VPS併用時は、コンピューティングリソースのコスト設計で取り上げた**VPS併用時の注意事項**を考慮する。

### VPS併用時の注意（プラン・ストレージ変更）

- ⚠️ VPSでは**柔軟なプラン変更ができない**。**ストレージ変更オプション**でストレージ容量を増やすことは可能だが、**変更後の容量は限定**されている。容量について多くの選択肢を求める場合は**クラウドのディスク**を利用する。
- ⚠️ **さくらのVPS for Windows Server では、ストレージ変更オプションは利用できない**点に注意する。

## 5. 変更の少ないデータの保管

### アーカイブによる保管

- 変更の少ないデータは**アーカイブで保管**することを検討する。
- **ディスクに比べてアーカイブの料金は安価**である。
- **アーカイブ化した後のディスクを削除**することでコストを削減できる。データを取り出す場合は、対象の**アーカイブからディスクを作成**する。
- さらにコスト削減するには、**アーカイブをローカル端末等にダウンロードして保管し、クラウド上から削除**する。データを取り出す場合は、**ブランクで作成したアーカイブにアーカイブのイメージファイルをアップロード**する。
- ⚠️ **アーカイブを取得できるディスクの最大サイズは 1TB**。これを超えるディスクが対象の場合は、別の方法を検討するか、**1TB以下の複数のディスクにデータを分ける**。

### 定期的なアーカイブの作成（自動バックアップ）

- 定期的にアーカイブを自動で作成したい場合は、**自動バックアップ機能**の利用を検討する。
- ⚠️ 自動バックアップ機能の料金は、**作成されるアーカイブの料金に加えて、バックアップ処理の実行にも料金が都度発生**する点に注意。
- ⚠️ **自動バックアップでアーカイブを取得できるディスクの最大サイズも 1TB**。これを超えるディスクが対象の場合は、通常のアーカイブ取得時と同様の検討が必要。

> 💡 Tips: アーカイブとライセンス料金について
> **アーカイブにはライセンス料金が発生しない**。Windowsがインストールされたディスクのアーカイブを取得しても新たなライセンス料金は発生しない。ただし、**アーカイブからディスクを作成した場合はライセンス料金が発生**する。

### アクセス頻度の低いデータ（オブジェクトストレージ アーカイブプラン）

- **アクセス頻度の低いデータ**は、オブジェクトストレージの**アーカイブプラン**での保管を検討する。
- アーカイブプランは、標準のオブジェクトストレージより**データ容量単位の料金が割安**。
- **長期利用を前提に割引パスポートを適用**すると、大幅なコスト削減が見込める。
- ⚠️ アーカイブプランは、標準のオブジェクトストレージよりも**アクセス性能が低く**、**1バケットあたりの最大アクセス数が10分の1に制限**されている点に注意。

## 6. 試験対策・要点チェック

- [ ] 基本方針: ストレージはスモールスタート＋需要に応じたスケールアップ。ただし**スケールアップはサーバ停止＋時間を要する**ため、停止猶予のないシステムは**最初から余裕あるサイズ**。
- [ ] 標準プランのサイズはゾーンで異なる: **石狩第1/第2・東京第1＝40GB〜12TB**、**東京第2・石狩第3＝2TB〜12TB**。
- [ ] 最小サイズ: **標準＝40GB / SSD＝20GB**。SSD 20GBは**石狩リージョンが東京より安価**。
- [ ] 性能の目安: **標準プラン＝HDDの2倍以上 / SSDプラン＝HDDの20倍以上**。IOPS・転送帯の制限値は**クラウドマニュアル**、ディスクが大きいほど制限値に余裕。
- [ ] プラン使い分け: 既存ディスクから**別プランを作成して付け替え**可、**異なるプランを同一サーバに混在**可（OS/アプリ＝SSD、データ＝標準）。
- [ ] **NFSアプライアンス**＝ローカルNW内の共有ファイルサーバ、OS/ミドル管理不要。ただし**通常ディスクより性能・IOPSが低い**。
- [ ] **オブジェクトストレージ**＝大容量向け、**100GiBまで等は定額**、超過は**従量課金（通常ディスクと異なる料金体系）**。
- [ ] **CRR**: 機能自体・転送量は**無料**だが**ディスティネーションバケット料金が発生**。**両バケットでバージョニング有効化必須**、バージョン分も**課金対象**。
- [ ] VPS併用: ローカル接続には**ブリッジ＋スイッチ**が必要。VPSは**プラン変更が柔軟でない**、変更後容量は限定、**VPS for Windows Serverはストレージ変更オプション不可**。
- [ ] **アーカイブ料金はディスクより安価**。ダウンロード保管→クラウド削除でさらに削減。**アーカイブ取得可能なディスク最大は1TB**（自動バックアップも同じく1TB）。
- [ ] **自動バックアップ**は**アーカイブ料金＋バックアップ処理の実行料金**が都度発生。
- [ ] アーカイブには**ライセンス料金が発生しない**（**ディスク作成時には発生**）。
- [ ] オブジェクトストレージ**アーカイブプラン**＝容量単位料金が割安・割引パスポートで大幅削減。ただし**アクセス性能が低く、1バケットあたり最大アクセス数が標準の1/10**。
