## 1. さくらのクラウドの第三者機関による認証

サービス提供基盤に対するセキュリティへの取り組み状況を把握し、利用者の求める要件を満たしているかを確認する。

### 1.1 取得・登録状況（重要表）

| 対象 | 認証・報告書 |
|------|--------------|
| さくらインターネット（会社） | **プライバシーマーク**、**ISMS** を取得 |
| さくらのクラウド | **ISMSクラウドセキュリティ** を取得。また **ISMAP** に登録 |
| 石狩データセンター | **SOC2 Type2 報告書** および **SOC3 報告書** を監査法人より受領 |
| 石狩データセンター | **PCI DSS Ver.4.0** の物理セキュリティに関する一部要件に準拠（後述） |

> 注意: 主体ごとに認証が異なる点が頻出。
> 「会社＝プライバシーマーク・ISMS」「クラウド＝ISMSクラウドセキュリティ・ISMAP」「石狩DC＝SOC2 Type2/SOC3・PCI DSS」。

### 1.2 PCI DSS（石狩データセンター）

- カード会員データを扱う企業のファシリティサービスにおいて、クレジットカード情報を安全に取り扱うために策定されたセキュリティ基準。
- **PCI DSS Ver.4.0** の全12要件のうち、物理的なセキュリティに関する **「要件9」** と **「要件12」** に準拠。
  - **要件9**:「カード会員データへの物理アクセスを制限」
  - **要件12**:「全ての担当者の情報セキュリティに対応するポリシーを維持」

### 1.3 ISMAP・ガバメントクラウド

- **ISMAP** とは、**政府情報システムのためのセキュリティ評価制度**。
- さくらのクラウドは、**ISMAPのクラウドサービスリスト**に登録されている。
- さくらのクラウドは、**2023年度**にデジタル庁が募集した「ガバメントクラウド整備のためのクラウドサービス」（**ガバメントクラウド**）に認定された。
  - ただし、**2025年度末までに技術要件をすべて満たすことを前提とした条件付きの認定**である。

## 2. 暗号化通信の利用（データ転送時）

### 2.1 考慮事項
- データ転送時に、悪意のある第三者による**通信の盗聴**リスクを考慮し、暗号化通信を利用する。
- さらに、**データの改ざんやなりすまし**のリスクに対処するため、**公的な認証局によって発行されたSSL証明書**の利用を検討する。
- ウェブサイトとの通信では、HTTP通信をSSL/TLSで暗号化した **HTTPS** が使用される。
- ファイル転送では、SSL/TLSを使用した **FTPS** や、SSHを使用した **SFTP / SCP** が一般的。求めるセキュリティレベルや利用環境に応じて選択する。

### 2.2 Tips: さくらのクラウドで標準的に利用されるSSL/TLS通信
- クラウドコントロールパネルやAPIの通信は、**標準でSSL/TLSによる暗号化**が実現されている。
- **オブジェクトストレージ**も **HTTPS** による暗号化通信に対応。
- **アーカイブやISOイメージのアップロード機能**では、標準で **FTPS通信** を使用可能。

### 2.3 SSL証明書の選択（認証レベル比較）

認証局が発行するSSL証明書には3種類があり、求める認証レベルに応じて選択する。

| 種類 | 略称 | 認証範囲 |
|------|------|----------|
| ドメイン認証 | **DV** | ドメインの管理権 |
| 組織認証 | **OV** | 組織の実在性 |
| 拡張認証 | **EV** | 厳格な組織審査 |

- 米国の非営利団体 **Internet Security Research Group（ISRG）** が運営する認証局 **Let's Encrypt** では、**ドメイン認証（DV）のSSL証明書のみ**発行できる。
- Let's Encrypt の証明書は、提供元のポリシーに同意することで**無料**で簡単に発行・登録できる。時間当たりの作成数などの制限はあるが、**自動更新の仕組み**を入れると管理の手間を削減できる。

### 2.4 SSL証明書の管理（配置先）
- HTTPS通信時のSSL証明書の配置先には、直接Webサーバ内に置く以外に、**エンハンスドロードバランサ**や**さくらのウェブアクセラレータ**に登録する選択肢がある。
- これらの登録機能では、**利用者が用意した証明書の持ち込み**だけでなく、**Let's Encrypt証明書の登録と自動更新の設定**も可能。
- 特に **Webサーバの複数台構成**では、各Webサーバ内に証明書を格納せず、**コントロールパネル上で一元管理**できる。

## 3. 接続元ネットワークの制限（データ転送時）

### 3.1 考慮事項
- 通信の盗聴・改ざんリスクを軽減するため、サーバと接続可能なネットワークを制限する。
- クラウドリソースからサーバへの**接続元ネットワーク**を確認し、経路上の**ファイアウォール／パケットフィルタ**、または**サーバOSのセキュリティ機能**で不要な通信をフィルタリングする。

### 3.2 GSLB・エンハンスドロードバランサ
- GSLB／エンハンスドロードバランサを使う場合は、**それらのリソースからのみ実サーバへのアクセスを許可**することを検討する。
- 対象リソースから実サーバへ**ヘルスチェック**が行われるため、**ヘルスチェックの接続元ネットワークからのアクセスを許可**する設定が必要。
- **エンハンスドロードバランサ** では、**オリジンガード機能** によりHTTPヘッダ（**X-Origin-Guard**）に含まれるトークンをもとに実サーバへのアクセスを制限できる。

**接続元ネットワーク（プロキシ元）情報の確認先（重要表）**

| リソース | 接続元ネットワーク情報の確認先 |
|----------|--------------------------------|
| GSLB | クラウドマニュアル |
| エンハンスドロードバランサ | 対象リソースの詳細情報「**プロキシ元ネットワーク**」 |
| シンプル監視（監視元） | クラウドマニュアル |
| ウェブアクセラレータ | クラウドマニュアル |

- **Tips（クライアントIPによる接続制限）**: エンハンスドロードバランサ使用時、実サーバへのプロキシ時にクライアント側IPアドレスが **X-Real-IP** ヘッダおよび **X-Forwarded-For** ヘッダに付加される。これらをもとにサーバ側でアクセス制御が可能。
- **Tips（Syslog）**: エンハンスドロードバランサのSyslogを有効化した場合、**ログ転送元も「プロキシ元ネットワーク」のアドレス**となる。Syslogサーバ側のフィルタリング設定に注意。

### 3.3 シンプル監視
- シンプル監視で監視する場合、**監視元ネットワークから監視対象までの経路上で、指定した監視方法にもとづく通信を許可**する必要がある。
- 監視元ネットワークのアドレス情報は**クラウドマニュアル**で確認できる。

### 3.4 さくらのウェブアクセラレータ
- ウェブアクセラレータ使用時は、**ウェブアクセラレータからのアクセスのみをオリジンのWebサーバに許可**することを検討する。
- パケットフィルタリングに加え、ウェブアクセラレータの**オリジンガード機能**を利用する選択肢もある。
- オリジンが**オブジェクトストレージ**の場合は、**パーミッションとACL**を適切に設定し、必要なアクセスキー以外からのアクセスを許可しない。
- **ACL機能**でウェブアクセラレータ自体へのアクセスを制限可能。特定の **IPアドレス / CIDR範囲 / 全アクセス** のいずれかを許可または拒否できる。
- ACL設定に必要な接続元IPアドレス情報は、オリジンサーバのアクセスログに **X-Real-IP** 等のリクエストヘッダを出力することで確認できる。

### 3.5 データベースアプライアンス
- データベースアプライアンスでは、**標準提供される送信元ネットワークの制限機能**を利用し、特定のネットワークからのみデータベースへのアクセスを許可することを検討する。

## 4. ディスクの暗号化（データ保管時）

### 4.1 考慮事項
- サービス提供基盤の**ストレージ内でデータを暗号化して保管**することを検討する。不正アクセスやシステム不具合でデータ漏洩が発生した際の**閲覧・悪用を防ぐ**。
- クラウド上で機密性の高いデータを扱う場合や、データ暗号化が要件として求められる場合など、**データの機密性レベルを考慮して選択**する。

### 4.2 ディスク暗号化機能
- **クラウド基盤内の仮想デバイスドライバ**により、サーバ上のディスクの読み書きを暗号化・復号化するオプション機能。
- ホストサーバ内のIOバッファ、仮想ネットワーク、ストレージ装置とのネットワーク経路、ストレージ装置内に保存されるデータなど、**暗号化部分の不正な窃取・流出に対する安全性**を高められる。
- **性能影響なし**: 暗号化・復号化処理にかかる計算コストや時間的遅延は、**公表されているディスクのIOPSや転送帯域に影響を与えない**。

### 4.3 利用時の注意事項（重要）

| 項目 | 内容 |
|------|------|
| 有効化のタイミング | **ディスクの新規作成時のみ**有効化できる |
| 後からの変更 | 作成済みディスクへの**暗号化の有効化**、利用途中での**無効化**はできない |
| 対応リソース | データベースアプライアンス／NFSアプライアンスの**ディスク領域も暗号化可能** |
| アーカイブ | **アーカイブの暗号化には非対応**。暗号化ディスクの**アーカイブ取得は不可** |
| 自動バックアップ | 暗号化ディスクへの**自動バックアップの有効化は不可** |

### 4.4 OS上のツールによる暗号化（Tips）
- OS上のツールでデータを暗号化する選択肢もある。クラウドマニュアルでは、Linux系ディストリビューションで利用可能な **「LUKS」** によるディスク全体の暗号化が紹介されている。

### 4.5 オブジェクト暗号化機能（Tips）
- ディスクだけでなく、**オブジェクトストレージ内のオブジェクト**も暗号化できる。
- **バケット単位**で有効化し、**有効化後にアップロードされたオブジェクト**は保存時に自動的に暗号化される。
- 注意: **有効化前から保管されている既存オブジェクトは自動では暗号化されない**ため、暗号化状態の異なるオブジェクトが混在する点に注意。

## 5. マルウェア対策

### 5.1 考慮事項と責任範囲
- サーバ／ネットワークへの悪意あるソフトウェアの侵入を防ぐため、**サーバ上で動作するマルウェア対策ソフト**や、**ネットワーク境界で稼働するセキュリティアプライアンス**の導入を検討する。
- **サーバOSやアプリケーションのセキュリティ対策は利用者側の責任範囲**。OS・アプリを最新状態に保つよう、**セキュリティアップデートの運用**を検討する。
- 責任分界: 利用者業務データ・アプリケーション・OS等の上位層は**利用者の責任範囲**、基盤・物理層は**さくらインターネットの責任範囲**（責任共有モデル）。

### 5.2 具体的な対策手段
- **マーケットプレイス**で提供される**サーバセキュリティサービス**を使ったマルウェア対策を検討する。
- **サーバOSの標準機能**を使った対策や、**オープンソースのアンチウィルスソフト**を導入する選択肢もある。
- **Tips（セキュリティアプライアンス）**: マーケットプレイスのセキュリティアプライアンスでは、**脅威検出**や**不正侵入検知防御（IDS/IPS）**の機能を利用できる。
- データベースを扱う際は**データベースアプライアンス**の利用を検討する。セキュリティリスクへの対応は**さくらインターネットの責任範囲**となる。
- さくらインターネットは、**自動化された継続的な脆弱性管理・評価のサービス**を提供している。必要に応じて利用を検討する。

## 6. 試験対策・要点チェック

- [ ] 認証の主体別整理: **会社＝プライバシーマーク・ISMS** / **クラウド＝ISMSクラウドセキュリティ・ISMAP** / **石狩DC＝SOC2 Type2・SOC3・PCI DSS**。
- [ ] **ISMAP** ＝政府情報システムのためのセキュリティ評価制度。クラウドはクラウドサービスリストに登録済み。
- [ ] ガバメントクラウドは **2023年度認定**、ただし **2025年度末までに技術要件充足を前提とした条件付き**。
- [ ] PCI DSS は **Ver.4.0**、物理セキュリティの **要件9（物理アクセス制限）** と **要件12（情報セキュリティポリシー維持）** に準拠。
- [ ] 暗号化通信: Web＝**HTTPS**、ファイル転送＝**FTPS / SFTP / SCP**。CP・API・オブジェクトストレージは標準SSL/TLS、アーカイブ/ISOアップロードは**FTPS**。
- [ ] SSL証明書は **DV / OV / EV** の3種。**Let's Encrypt（運営：ISRG）は DV のみ**、無料・自動更新可。
- [ ] 証明書の一元管理先＝**エンハンスドロードバランサ / ウェブアクセラレータ**（Let's Encrypt自動更新対応）。
- [ ] 接続元制限: ELBのオリジンガードは **X-Origin-Guard**、クライアントIPは **X-Real-IP / X-Forwarded-For**。ELBの接続元確認は「**プロキシ元ネットワーク**」。
- [ ] ディスク暗号化は**新規作成時のみ有効化**、後からの有効化・途中無効化は**不可**。**IOPS/転送帯域に影響なし**。
- [ ] 暗号化ディスクは**アーカイブ取得不可・自動バックアップ不可**。**アーカイブ暗号化は非対応**。DBアプライアンス/NFSアプライアンスのディスクは暗号化可。
- [ ] オブジェクト暗号化は**バケット単位**、**有効化後の新規オブジェクトのみ**自動暗号化（既存は対象外）。
- [ ] OSレベルのディスク暗号化は **LUKS**（Linux）。
- [ ] マルウェア対策: **OS・アプリは利用者責任**。マーケットプレイスのセキュリティアプライアンスで **IDS/IPS**。DBアプライアンスのセキュリティはさくら責任。
