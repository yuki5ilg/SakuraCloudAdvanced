## 1. マルチレイヤーセキュリティ

検討にあたっての考慮事項。

- 単一のセキュリティ対策ではなく、**複数のネットワークレイヤーに対して防御手段を重ねる**ことで、アプリケーションのセキュリティを高めることを検討する。
- さくらのクラウド利用にあたり、**ネットワークセキュリティと境界型防御**の観点から:
  - 通信パケットのフィルタリングにより**不要な通信を遮断**
  - Webアプリケーションの脆弱性を狙った攻撃の**検知・遮断**
  - **DDoS攻撃からの保護**
- その他、**マルウェア対策**等も含めて総合的なセキュリティを考慮し、**情報セキュリティ管理体制の構築や運用**についても検討する。

## 2. 通信パケットのフィルタリング

### 検討にあたっての考慮事項
- さくらのクラウドでは通信パケットのフィルタリングとして、**パケットフィルタ機能**または **VPNルータのファイアウォール機能**の利用を検討する。
- クラウドのネットワーク構成や、フィルタリングを適用する**ネットワーク上の位置**を考慮して、どちらを使うか選択する。
- **一つのNICに適用可能なパケットフィルタルール数には最大値がある**ため、想定されるルール数を検討し適用可能か確認する。

### パケットフィルタ機能 vs VPNルータのファイアウォール機能（最重要・比較表）

| 項目 | パケットフィルタ機能 | VPNルータのファイアウォール機能 |
|------|----------------------|--------------------------------|
| 機能（インスペクション） | **ステートレスインスペクション**（戻りパケットの自動許可なし） | **ステートフルインスペクション**（戻りパケットの自動許可あり） |
| ネットワーク上の位置 | **サーバのNICに適用** | **仮想アプライアンス**としてネットワーク境界に設置 |
| ログ | ルールにマッチした通信を**ログ出力する機能がない** | ルールにマッチした通信を**ログ出力する機能がある** |
| 費用 | **無料**で利用可能 | **VPNルータの利用料金が発生** |

> ⚠️ 試験頻出: パケットフィルタ＝**ステートレス・NIC適用・無料・ログ無**、VPNルータFW＝**ステートフル・境界設置・有料・ログ有**。

### その他のフィルタリング手段
- 上記2機能の仕様で対応できない設定を実現するには、**サーバOSのファイアウォール機能**を利用する選択肢がある。
  - その場合、動作させる上で**サーバOSのリソースが使われる**ことを考慮する。
- **マーケットプレイスで提供されるセキュリティアプライアンス**を使ってフィルタリングする選択肢もある。
  - ただし、利用者にて**各セキュリティメーカーの仕様に従った設定と運用が必要**となる。

### パケットフィルタ機能 利用のポイント
- サーバ内のファイアウォール等の設定によらず、**コントロールパネル上で簡単にパケット制限**ができる。
- 特定の通信のみ許可して**他通信を全て拒否**したい場合は、**最後の順番のルールとして `deny` アクションのルールを指定**する必要がある。
- よく使われるルールの設定例が**クラウドマニュアル**に記載されている。
- **ステートレス動作**であることに注意。最後に全拒否ルールを設定する場合、**サーバ発の通信の戻りパケットを適切に許可する設定**が必要。

> 【Tips】共有セグメント配下のサーバにパケットフィルタを適用する場合
> 共有セグメントに接続されたサーバのNICや、利用者が独自構築したDHCPサーバでIPアドレスを付与しているサーバのNICにパケットフィルタを適用する場合、DHCPで利用される以下のポート/プロトコルをルールで許可する必要がある。
> - クライアント側 → DHCPサーバ宛: **67/UDP** を許可
> - DHCPサーバ側 → クライアント宛: **68/UDP** を許可

### VPNルータのファイアウォール機能 利用のポイント
- クラウドサーバーに対する**ゲートウェイセキュリティを強化**できる。
- 特定の通信のみ許可して他通信を全て拒否したい場合は、**最後の順番のルールとして `deny` アクションのルールを指定**する必要がある。
- ルール設定例は**クラウドマニュアル**に記載されている。
- ⚠️ ルール設定時に**ログ記録を「有効」に選択しないと、マッチした通信がログ表示機能に出力されない**ことに注意（**デフォルトは無効**）。

## 3. WAFの利用

### 検討にあたっての考慮事項
- **WAF（Web Application Firewall）**を導入し、Webアプリケーションの**脆弱性を狙った攻撃の検知と通信の遮断**を検討する。
- クラウドのネットワーク構成や環境に合わせて、**適切なWAFのタイプを選択**する。

### WAFのタイプ
一般的に以下のタイプがある。

| タイプ | 概要 |
|--------|------|
| **ホスト型WAF** | サーバ上で**エージェントを稼働**させるタイプ |
| **クラウド型WAF** | セキュリティベンダーが運営する**クラウド上のWAFサービスを経由して通信**させるタイプ |
| セキュリティアプライアンスのWAF機能 | **ネットワーク境界に配置**したセキュリティアプライアンスのWAF機能を使う選択肢 |

（図: ホスト型はサーバ内にエージェント、クラウド型はクライアントとサーバの間にクラウドWAFを経由させる構成）

### さくらのクラウドで提供されるWAF
- セキュリティベンダーとの協業により、**ホスト型WAF製品を無料で利用**できる。
- **マーケットプレイス**では、高機能な**ホスト型/クラウド型WAFサービス**が提供されている。
- マーケットプレイスのセキュリティアプライアンスのWAF機能を利用すると、**ネットワーク境界でWAFを利用**できる。

> 【Tips】ホスト型WAFで複数エージェントを運用する際は、**管理画面で一元管理**し運用効率の向上を検討する。セキュリティベンダーの**有償ライセンス購入**または**マーケットプレイスの対象プラン選択**で一元管理を実現できる。**WAFの設定代行に対応するライセンス**もあり、運用負荷軽減に利用を検討する。

## 4. DDoS対策の検討

### 検討にあたっての考慮事項
- 必要に応じて、クラウド上で稼働させるアプリケーションに対する**DDoS対策**を検討する。
- さくらのクラウドでは、**サービス提供基盤全体に対してバックボーンレベルでDDoS対策**が講じられている。攻撃を検知した場合は**さくらインターネットで状況を確認し、個別に対応**が行われる。
- 一般的なDDoS対策としては、**接続元ネットワークの制限**や、**WAF・DDoS対策専用ツール等の利用**がある。

### さくらのクラウドで提供されるDDoS対策（重要）
- **エンハンスドロードバランサ**を利用する構成では、**VIPフェイルオーバ機能**を利用できる。
  - DDoS攻撃等によりIPアドレスへの到達が失われ疎通が取れなくなった場合、**自動的に別のVIPアドレスに変更**される。
  - **VIPアドレスの無応答検知からフェイルオーバ動作までの目安時間は約5分**。
- **マーケットプレイス**で提供されるセキュリティアプライアンスには、**DoS攻撃対策機能**を備えたものがある。

> ⚠️ 試験頻出: エンハンスドロードバランサの**VIPフェイルオーバ**で別VIPへ自動切替、**目安5分程度**。バックボーンレベルのDDoS対策は**さくら側で個別対応**。

## 5. ネットワーク構成の検討

### 基本方針
- **サーバの役割と機密性のレベルに応じて、接続するネットワークを検討**する。

### グローバルネットワークとローカルネットワークの構成（重要）

| ネットワーク | 接続するサーバ | アクセス | 機密情報 |
|--------------|----------------|----------|----------|
| **グローバルネットワーク** | 外部公開サーバ（例: Webサーバ） | 外部から**直接アクセス可能** | **保管しない** |
| **ローカルネットワーク** | 機密情報を扱うサーバ（例: DBサーバ） | 外部から**直接アクセス不可** | **保管する** |

- グローバルネットワークに接続するサーバは、**外部から直接アクセスできることを考慮してセキュリティ対策**を実施する。
- グローバルネットワークに接続するサーバでは**機密情報を保管しない**。
- ローカルネットワークにのみ接続するサーバは、**外部から直接アクセスできない構成**とする。
- **機密情報を保管するサーバは、ローカルネットワークにのみ接続**する。

#### インターネット公開サーバの構成例（図: PAGE 24）
- **【グローバルネットワーク】**: Webサーバを接続。ユーザはグローバルネットワーク経由でWebサーバにアクセスする。**ユーザがDBサーバにアクセスすることはできない**。
- **【ローカルネットワーク】**: DBサーバを接続。
- **WebサーバはNICを2つ保有**し、グローバルとローカルの両方に接続する。Webサーバはローカルネットワークを経由してDBサーバにアクセスする。

> ⚠️ 試験頻出: **Webサーバ＝NIC2つ（グローバル＋ローカル）**、**DBサーバ＝ローカルのみ**、機密情報を持つサーバはローカル限定。

### クラウド内部のプライベートネットワークの構成（重要）

検討にあたっての考慮事項。

- インターネットにサーバを公開する場合は、**ネットワーク境界にVPNルータを配置**し、サーバを**クラウド内部のプライベートネットワークに所属**させる構成でセキュリティ向上を検討する。
- 外部からプライベートネットワーク内へのアクセスは、**VPNルータのポートフォワーディング機能やスタティックNAT機能**を使って、プライベートネットワークに所属するサーバに転送する。
- **VPNルータのファイアウォール機能**を使って必要な通信のみ許可するよう制限する。
- VPNルータ配下のプライベートネットワークに所属するサーバは、**デフォルトゲートウェイのIPアドレスとしてVPNルータのプライベートネットワーク側NICを指定**する。

#### 構成例（図: PAGE 26）
- インターネット ─ 共有セグメント ─ **VPNルータ（スタンダード）** ─ スイッチ ─ プライベートネットワーク（仮想サーバ、NFSアプライアンス等）。
- サーバを**クラウド内部のプライベートネットワークに所属**させる構成を取る。

> 【Tips】VPNルータをインターネットと切り離す構成
> VPNルータは**複数のクラウド内部のプライベートネットワーク間で通信**させることが可能。プライベートネットワーク内のサーバをVPNルータ経由でインターネットと通信させる必要が無い場合は、**VPNルータをインターネットと切り離した状態で運用**することも可能（コントロールパネルの「インターネット接続」を無効に設定）。

## 6. 試験対策・要点チェック

- [ ] マルチレイヤーセキュリティ＝**複数レイヤーに防御を重ねる**。境界型防御で不要通信遮断・攻撃検知遮断・DDoS保護を検討。
- [ ] パケットフィルタ＝**ステートレス / NICに適用 / 無料 / ログ出力機能なし**。
- [ ] VPNルータFW＝**ステートフル / 境界に仮想アプライアンス設置 / 有料 / ログ出力機能あり**。
- [ ] 全拒否したい場合は**最後のルールに `deny`** を指定（両機能共通）。
- [ ] パケットフィルタはステートレスなので**戻りパケットの許可設定**が必要。共有セグメント+DHCPでは **67/UDP（クライアント→サーバ）・68/UDP（サーバ→クライアント）** を許可。
- [ ] VPNルータFWのログは**デフォルト無効**、設定時に「有効」選択が必要。
- [ ] WAFタイプ＝**ホスト型（エージェント）/ クラウド型（サービス経由）/ 境界アプライアンス**。さくらは**ホスト型WAF製品を無料提供**。
- [ ] DDoS対策: さくらは**バックボーンレベルで対策・個別対応**。**エンハンスドロードバランサのVIPフェイルオーバ**で別VIPへ自動切替、**目安約5分**。
- [ ] ネットワーク構成: **機密情報サーバはローカルのみ**、Webサーバは**NIC2つ**でグローバル＋ローカル接続。
- [ ] プライベートネットワーク公開: **VPNルータを境界配置**、**ポートフォワーディング/スタティックNAT**で転送、配下サーバの**デフォルトGWはVPNルータのプライベート側NIC**。
- [ ] VPNルータは**プライベートネットワーク間通信**が可能で、**インターネットと切り離した運用**もできる。
